# Governance

Kedra currently follows a maintainer-led model. The repository's existing owner
maintains the foundation; there is no elected council or established maintainer team.

- Small fixes use pull requests; substantial changes start with an issue or proposal.
- Architecture decisions are recorded as ADRs with alternatives and consequences.
- Maintainers decide scope, API direction and releases, and explain disputed decisions.
- Passing CI does not imply acceptance. Safety, clarity and maintenance cost matter.
- Reviewers should disclose conflicts of interest and avoid reviewing their own work
  as if it were independent approval.
- Maintainer access is granted deliberately after sustained, trusted contributions.

Appeals can be raised in a repository issue unless they involve private security
or conduct information. Use the private channels described in the relevant policies.
Governance can evolve through a reviewed public proposal.
