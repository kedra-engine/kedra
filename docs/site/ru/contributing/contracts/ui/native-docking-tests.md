# Контракты native docking tests

Тесты docking проверяют топологию, жесты, сохранение содержимого и время жизни нативных окон.
Подготовка запуска описана в [нативных сценариях](../../../manual/testing/native-scenarios.md).
У docking, окон и панелей нет активных эталонных снимков, допусков различий пикселей или набора
сравнений снимков. Манифест хранит только
[происхождение](design-provenance.md#independent-references-and-provenance).

## Native behavior route {#native-behavior-route}

На доверенном, свободном, разблокированном рабочем столе, с новым каталогом результатов:

```sh
cargo xtask test -- features --only docking,docking-states,dock-fixture --output target/test/docking
```

Rust строит и проверяет поставки, запускает изолированные процессы. Сценарий редактора отказывается
от личных настроек, использует штатный ввод и перезапуск со своим состоянием для проверки
восстановления топологии и нативных окон. Нерегулярные сбои взаимодействия и захвата кадров
не устранены. Нельзя скрыто повторять прерванный жест, возвращать фокус или перезапускать
приложение ради успешного результата.

Потеря фокуса отменяет жест без публикации; возврат фокуса с зажатой кнопкой не возобновляет его.
Нужно новое нажатие. Тестовая сцена проверяет, продолжается ли жест, пока ожидает направляющие,
маркеры вставки и предварительные области. При отмене она сразу сообщает об этом, не ожидая
отклика от уже завершённого жеста.

Изолированная сцена дважды работает в обычном редакторе без жизненного цикла проекта, панелей
или настроек. Она проверяет компас и прямой выбор краёв, вставку и порядок, запрещённый сброс,
Escape, измеренную геометрию предварительного и опубликованного размещения, изменение размера,
разворачивание и восстановление, отделение и возврат, запросы закрытия, сохранение черновиков
и локальные для окна Tab/Shift+Tab. Обратная связь Flat и привязка всплывающих окон проверяются
наблюдениями, не изображениями. Разделение должно укладываться в штатный предел выхода за границы
окна 0.5px, включая дробное выделение области и нативное округление.

`app.capture` служит барьером синхронизации GPU: временные приватные кадры проверяются и удаляются.
Отчёты сохраняют квитанции кадров, геометрию, состояние и результаты ввода, но не галереи PNG,
хеши или сравнения. Квитанция подтверждает завершение чтения, а не качество изображения;
снимки сравнивает только [корпус компонентов](ui-corpus.md).

## Полномочия host и scenario {#host-and-scenario-authority}

Общий `dock-fixture` владеет нативной матрицей направлений, порядка, отказов и отмены.
`docking` проверяет сохранение настоящих панелей редактора, их нативных окон и настроек;
`docking-states` — реальные меню рабочего пространства и панелей, включая компактное плавающее окно.
Матрица компаса в нём не повторяется. Предпросмотр ждёт тот же предикат готовности кандидата,
что и штатный drop, а не отдельный алгоритм стабильности снимков.

Обычный отладочный `kedra` выбирает `editor://fixtures/docking.scene.ron` через `--scene`.
Штатные ввод, выбор цели, проекция, всплывающие окна и нативные окна используют топологию A/B/C/D
из исходника через существующую проверку Snapshot. Обычный запуск и запуск с явной сценой
устанавливают `EditorPlugin` и одинаковые нативные возможности. Явный жизненный цикл исключает
запуск проекта и отклоняет операции с ним. Отдельной цели example или второй реализации
перетаскивания нет.

| Зарегистрированная программа Luau | Полномочия подготовки |
| --- | --- |
| `dock.reset` | Завершить ввод, изменить размер, восстановить данные сцены, удалить вспомогательные окна |
| `dock.drafts` | Переключить поля для нативной проверки сохранения состояния |
| `dock.overflow` | Добавить длинный заголовок для действий при переполнении |

Эти программы задают порядок диагностических действий, а не предоставляют общий удалённый API
изменения топологии. Нативные операции проверяют действующего владельца сцены и рабочей области.
F12 завершает запуск с явно выбранной сценой. Reset подготавливает тест, а не восстанавливает
пользовательские настройки продукта. `dock.state`, `dock.fixture` и явно включаемый `dock.trace`
доступны только для чтения. Ограниченная трассировка хранит переходы жестов, владение курсором
и окном, модификаторы, но никогда не введённый текст. Действия используют реальный ввод Bevy,
не прямое назначение компоновки.

## Владельцы контрактов и независимый потребитель {#product-owners-and-independent-consumer}

Rust-контракты топологии, владения, устаревших кандидатов и снимков принадлежат `kedra_docking`,
сохраняемой проекции — `kedra_ui`, отказа сохранения настроек и управления окнами — тестам
рабочей области редактора.

```sh
cargo test -p kedra_docking --locked
cargo test -p kedra_ui --test contracts --locked docking::
cargo xtask check
```

Зависящая только от runtime
[test game (English)](https://github.com/kedra-engine/kedra/blob/main/tests/fixtures/test_project/README.md)
использует ту же модель и проекцию через `ui.docking` из исходника и
`editor://fixtures/projection.scene.ron` с явно указанной проверенной поставкой визуальных ресурсов.
Её команды модели не заменяют проверки жестов. См.
[независимые приложения runtime](../../../manual/testing/native-scenarios.md).

## Ограничения приёмки {#acceptance-limits}

Программный запрос закрытия проверяет обычную политику обработки запроса, не щелчок по системному
заголовку. Физический захват и отпускание указателя, системные кнопки и перетаскивание, IME,
диалоги выбора, мониторы с разным DPI и Windows/Linux/Wayland требуют отдельных проверок ввода
и кадров на каждой платформе. Чтение кадров Bevy не включает системные элементы управления.
Компиляция и нативная проверка этой ревизии ещё не подтверждены.
