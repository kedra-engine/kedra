# Контракты UI corpus

Корпус UI сравнивает нативные кнопки и текстовые поля с независимыми экспортами дизайна.
Запуск описан в
[Визуальной проверке](../../../manual/testing/visual-verification.md).
[ADR 0028 (English)](https://github.com/kedra-engine/kedra/blob/main/docs/decisions/0028-shared-native-test.md)
определяет общие инструменты. Компиляция и нативная проверка этой ревизии ещё не подтверждены.

## Активный scope и запуск {#active-scope-and-launch-contract}

Активны пять исходников штатных префабов, два семейства, 22 случая: кнопки Quiet/Secondary/Primary
и плоские кнопки с иконками в Default/Hover/Pressed/Focus/Disabled, поля в Default/Focus.
Остальной интерфейс реализован в пределах своих контрактов, но корпус его не включает
и не утверждает. Эталонных снимков целых окон запуска, docking, панелей или сцен нет.
Источник списка —
[`docs/ui/corpus/catalog.json` (English)](https://github.com/kedra-engine/kedra/blob/main/docs/ui/corpus/catalog.json).
Каждый исходник должен существовать и относиться ровно к одному семейству; у каждого семейства
должны быть случаи проверки.

```sh
cargo xtask test -- components
cargo xtask test -- components --only button-primary,field-default
cargo xtask test -- components --source PATH_TO_NEW_SOURCES --policy PATH_TO_REVIEWED_POLICY
```

Нужен доверенный, свободный и разблокированный рабочий стол. Rust строит штатную поставку
и обычный отладочный редактор, захватывает кадры Bevy через существующий транспорт ввода
и захвата, вызывает `kedra_test`. Подмена браузером, собственный декодер и второй механизм
сравнения не используются. Результаты по умолчанию создаются в новом каталоге под
`target/test/ui-runs/`; `--output NEW_DIRECTORY` не должен существовать. Диагностика и ход проверки
каждого случая завершаются итогом и путём `public/index.html`. Отчёт автономный и пассивный.
При ошибках сохраняются отчёт и готовые кадры, а не подставляются старые результаты.
`--only` проверяет часть корпуса, не весь корпус. Пропущенные, неуспешные и незапущенные случаи,
ошибки профиля, неполные наблюдения, нестабильность и сбои восстановления должны оставаться
в итоговом результате.

## Authored native fixture {#authored-native-fixture}

Отладочные привязки `crates/kedra_editor/src/catalog.rs` монтируют
`editor://fixtures/catalog.scene.ron` через общий `--scene`. Слоты используют штатные
скомпилированные префабы, CSS рабочей области и только перечисленные исходники. Холст 640×360
при DPR 1 имеет фиксированное начало (32,32): текстовые кнопки 110×22, кнопки с иконками 22×22,
поля 172×22; подписи “Save changes”, “Main Camera”. У иконок нет предка с отступами панели
инструментов. Компоновка и ввод исходника остаются действующими во всех слоях.

`editor.catalog` задаёт текст, период мигания каретки, округление, нативный хинтинг и плотность.
Rust проверяет ограниченную калибровку и применяет её к неизменным экземплярам префабов, сохраняя
нативные измерения, захват и проверки адресов исходников. `catalog.show` принимает логический
путь, например `{"source":"editor://prefabs/primary-button.prefab.ron","disabled":false}`.
Хост определяет исходный документ загруженного ресурса без таблицы выбора по UUID. Сценарий
сверяет путь и документ с независимыми метаданными; сохранённые ID и отпечаток не меняются.

Зарегистрированный хостом `catalog.prepare` выполняет нативные изменение размера, наведение,
удержание нажатия и фокус через отладочный CLI. Монтирование — явное предварительное условие.
Rust независимо проверяет исходник, состояние, геометрию слота, кадры и процесс. Холст сохраняется
между состояниями; каждый образец монтируется заново. Ровно две независимые сессии проходят
всю выбранную последовательность, без перезапуска для каждого случая. Каждый случай отпускает
указатель, заново монтирует образец, сбрасывает фокус и отрисовку. Наведение, нажатие и клавиатура
используют программно поданный ввод; отключённость — предварительное условие тестовой сцены.
End снимает полное выделение поля после Tab без подмены отрисовки выделения; нативные каретка
и выделение сохраняются.

Сессия захватывает full → shape без глифов → восстановленный full. Требуются три подряд
одинаковых кадра на слой и совпадение сессий; восстановление точно воспроизводит исходные пиксели
и типографику. Полный кадр не может быть одноцветным. Только обоснованный диагностический слой
без глифов может быть одноцветным при сохранённых тексте и компоновке, а также независимо
проверенных неоднородных полном и восстановленном кадрах.

## Строгая typography и fixed regions {#strict-typography-and-fixed-regions}

[`text-families.json` (English)](https://github.com/kedra-engine/kedra/blob/main/docs/ui/corpus/text-families.json)
связывает ID текстовых свойств Figma с `NodeAddress` из исходников, не строками или ближайшей
геометрией. Quiet/Secondary/Primary используют общий Button Label; у TextField Value свой узел.
Случаи только с иконкой требуют пустого списка текста. Доступный только в отладочной сборке
`kedra_ui/text-capture` измеряет `Text`/`EditableText`: содержимое, путь и хеш загруженного шрифта,
начертание, размер, итоговый RGBA, интервалы, высоту и число строк, выделенную область и обрезку.
Позиции глифов должны совпадать с независимым формированием текста без отсутствующих глифов
и с полным покрытием; взаимно однозначное соответствие символов Unicode и глифов не предполагается.

Единственная активная политика шрифтов:
[`docs/ui/corpus/text-policy.json` (English)](https://github.com/kedra-engine/kedra/blob/main/docs/ui/corpus/text-policy.json).
Она принимает растеризацию только при точном совпадении рендерера, окружения, DPR, файла
зависимостей, отпечатка исходников и файлов шрифтов. Содержимое, шрифт, начертание, размер,
RGBA, интервалы и строки должны совпадать точно. Выделенные прямоугольники подписей, не границы
закрашенных пикселей, допускают только округление 0.5px при DPR-1. Различия полного кадра
остаются видимыми информационными результатами и не выдаются за совпадение пикселей.

Для слоя shape действуют допуск YIQ 0.05 и локальный предел различий 2% в независимо закреплённых
областях, включая внешний отступ фокуса 3px. Байты полного кадра 640×360 не меняются:
выравнивание, обрезка, масштабирование, размытие и маски исключений запрещены. Фактические границы
элемента не сдвигают начало координат эталона и не меняют знаменатель. Полный отпечаток метаданных,
изображений и семейств, а также файл зависимостей проверяются до запуска, даже с `--only`.
Обновление требует согласования; захват не записывает вычисленные хеши в политику.

### Принятые SVG differences {#accepted-svg-differences}

## Evidence и source package {#evidence-and-source-package}

[`text/text-manifest.json` (English)](https://github.com/kedra-engine/kedra/blob/main/docs/ui/corpus/text/text-manifest.json)
хранит полные PNG, полученные из них PNG без глифов и метаданные 22 состояний: точные ID фреймов,
свойств и узлов, происхождение канонических компонентов и вариантов, метрики шрифтов
и прямоугольники
компоновки. Скрытый текст исключён; отсутствующие, лишние, неоднозначные и неподдерживаемые роли
отклоняются. 44 активных изображения остаются в `docs/ui/corpus/text`. 28 обёрток, связанных
с каноническими компонентами, на
[QA / Native exports](https://www.figma.com/design/2EZlK40cfx2Mub7GmDyI70/UI-KIT?node-id=352-1515)
используют полные холсты, не меняя мастер-компоненты.

| Материалы запуска | Назначение |
| --- | --- |
| `source/` | Побайтово неизменные независимые PNG и метаданные дизайна |
| `CASE/run-1/`, `CASE/run-2/` | Нативные кадры full/shape/restored и измерения |
| `CASE/full/`, `CASE/shape/` | Входы сравнения, исходные разности, подробные отчёты |
| `public/index.html`, `public/report.json` | Результаты для человека и машинной обработки |
| `policy.json`, `families.json` | Точные копии политики и привязок |
| `private/` | Локальные учётные данные, журналы, созданная поставка; не публиковать |

Отчёты сохраняют все случаи, исходные пары слоёв, ожидаемые и фактические размер и цвет,
локальные проценты и ссылки в нативном разрешении. Масштаб просмотра не меняет входные данные.
Частичные отказы указывают слой, сессию и путь диагностики без приватного состояния; очистка
удаляет учётные данные даже при ошибке. Канонический тестовый проект нужен для ручных сценариев
и проверок функций, не для этого независимого хоста. У проверок функций нет эталонных снимков.

## Ручной source export без AI {#manual-source-export-without-an-ai-service}

```sh
cargo xtask test -- export --text-plugin
cargo xtask test -- export --text-bundle path/to/kedra-text-sources.json
cargo xtask test -- components --source PATH_TO_NEW_RUN/exports
```

Импортируйте указанный `plugin/manifest.json` как локальный плагин разработки Figma в точный
UI-KIT. Запустите плагин интерактивно и скачайте пакет JSON вручную.
`tools/test/figma_text_export.js`
использует обычные Plugin APIs без Node/npm, сети или публикации; флаг приватного API открывает
только идентичность текущего файла. Шрифты загружаются до операций с текстом. Полные оригиналы
сохраняются; один временный клон меняет только непрозрачность текста для слоя shape. Компоновка,
иконки и мастер-компоненты сохраняются; клоны удаляются и при ошибке. При ошибке на позднем этапе
можно получить диагностический пакет с явной отметкой неполноты. Он не считается полным импортом
или успешной проверкой. Импорт резервирует новый каталог, проверяет хеши, происхождение,
метаданные, целостность и размеры PNG средствами Rust; он не перезаписывает и не утверждает
исходники. Автономный захват и CI не обращаются к Figma. Новому состоянию нужны фрейм и запись
каталога, не ручные варианты без текста, код отрисовки или метрики шрифта.
Созданная оболочка для настольного приложения требует независимой интерактивной проверки хоста;
сохранённые входные данные её не заменяют.

## Verification и CI {#verification-and-ci-boundary}

У средств управления проверками, хостов и отчётов нет отдельного набора самотестирования;
проверяются реальные сценарии, ввод, кадры и механизм сравнения. Rust-контракты продукта
обязательны. Запускаемый вручную процесс **Native UI corpus** в `.github/workflows/ui.yml`
использует ту же команду и явную политику на Ubuntu 24.04 с Xvfb/Openbox/Mesa software Vulkan,
фиксирует пакеты и драйверы, сохраняет только публичные результаты и данные окружения.
Устаревшие маршруты capture/audit/replay и самотесты сценариев QA не подразумеваются.

Политика macOS/Metal не утверждает Linux. Непроверенная платформа отклоняется до захвата;
для заявления об успешной проверке на CI или обязательной проверке PR нужны утверждённая
политика Linux и реальный запуск процесса CI. Запасного режима «только захват» и автоматического
одобрения нет. Компиляция не проверяет нативное взаимодействие. Статичные кадры с уменьшенным
движением не сертифицируют движение, системный ввод, IME, диалоги выбора, буфер обмена или
мониторы с разным DPI. Отдельного примера catalog или специального профиля Cargo нет.
Обычный отладочный `EditorPlugin` обслуживает оба цикла жизни; явная сцена исключает запуск
проекта и операции с ним. Обычная зависимость редактора включает захват текста, но привязки
и службы доступны только в отладочной сборке. Калибровка и именованные программы Luau не заменяют
часы приложения и независимую проверку сборки, ввода и кадров.
