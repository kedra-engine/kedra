# Контракты chrome окон

Приложения собирают собственные заголовки окон через общие адаптеры привязки и нативного ввода.
[ADR 0019 (English)](https://github.com/kedra-engine/kedra/blob/main/docs/decisions/0019-composable-window-chrome.md)
задаёт эту архитектуру. Ограничения нативной проверки перечислены ниже.

## Binding и заимствованные slots {#binding-and-borrowed-slots}

`kedra_ui::window_chrome` связывает корень из исходника с явно указанным живым окном.
Он предоставляет
именованные слоты, заимствование содержимого, области ввода по данным рендерера и подбор заголовка
Unicode по ширине, но не создаёт окна или оформление редактора. Приложения могут использовать
деревья из исходников или обычные нативные деревья Bevy.

```rust
use kedra_ui::window_chrome::{Header, HeaderRegion, RegionRole};
use std::collections::BTreeMap;

let mut header = Header::bind(world, window, authored_root,
    BTreeMap::from([("tools".into(), tools_slot)]))?;
world.entity_mut(drag_background).insert(HeaderRegion {
    header: authored_root,
    role: RegionRole::Drag,
});
header.attach(world, "tools", existing_content, live_parking_parent)?;
// Before retiring the authored header:
header.unbind(world)?;
```

Корни, слоты, содержимое и места временного размещения должны вести к одному живому окну через
цепочку предков камеры. Повторные привязки и слоты, циклы, чужое содержимое и устаревшие назначения
отклоняются без неявной передачи владения. Attach заимствует содержимое; detach/unbind перемещает
его во временное место до удаления заголовка. `unbind(&mut self, ...)` сначала проверяет все
такие места: ошибка сохраняет присоединённое содержимое и дескриптор восстановления. Прямой
despawn обходит этот цикл жизни. Новые поколения привязок ECS защищают последующие привязки
того же корня от устаревшего дескриптора. Камеры слотов проверяются заново перед attach.

`Header::set_title` и адаптер `set_title` зарегистрированного корня сохраняют полный текст.
Они используют то же сокращение многоточием по кластерам текста, сформированным Bevy, что
и подписи docking. Отсутствие измерения не стирает Unicode и не подменяется предположениями
о ширине байтов или глифов.

## Input regions и native adapter {#input-regions-and-native-adapter}

По умолчанию ввод относится к клиентской области. Только явный `Drag` разрешает нативный жест;
пересекающиеся `Client`/`NativeControls` имеют приоритет. Кнопки, поля и меню остаются клиентскими
областями, даже когда отключены. Модальное окно блокирует нативные жесты своего окна. Геометрия
следует текущим компоновке, области просмотра, обрезке, DPR и `UiScale`; неверные или неизмеренные
области никогда не начинают нативное перетаскивание.

`kedra_desktop::chrome` устанавливается через `DesktopPlugin`; `bind(world, window)` включает
нативный адаптер после привязки UI. `ChromeControl` связывает обычный `Activate` с явными
`ChromeAction` и окном. Close отправляет `WindowCloseRequested`; владелец жизненного цикла решает,
завершать приложение или скрывать окно. Согласование закрытия с документами ещё предстоит
реализовать. `NativeChromeState` сообщает подтверждение оконной системы и состояния фокуса,
разворачивания и полноэкранного режима. Жесты обрабатывают события своего окна, включая
программно поданный ввод, а не полагаются на предполагаемое обновление кеша аппаратного курсора.

[ADR 0020 (English)](https://github.com/kedra-engine/kedra/blob/main/docs/decisions/0020-macos-client-titlebar-input.md)
принимает точное исправление Winit для macOS: AppKit не начинает автоматическое движение окна
при клиентском перетаскивании вкладки в прозрачном заголовке. Перемещение за пустой заголовок
по-прежнему использует общий адаптер; движение за фон включается явно.

## Композиции окон {#window-compositions}

Высота нативных строк — 32 логических пикселя. Заголовки запуска и общих окон центрированы;
Loading/failure имеют фиксированный размер и только Close; Projects допускает изменение размера.
Boot готовится без окна и заставки. Области проекта, управления выполнением и команд встроены
в строку. Неподдерживаемые Play/Save/Build и глобальный поиск отключены; идентификаторы панелей
и сброса — `workspace/panels`, `workspace/reset`.

Плавающее окно с одной корневой группой интегрирует сохраняемую полосу вкладок и общее меню;
разделённое окно оставляет отдельный заголовок и обычные полосы вкладок. Maximize не меняет
это правило топологии. Разделение и объединение меняют композицию без пересоздания вкладок,
содержимого или фокуса. `Projection::set_header_destinations` готовит слоты; успешная синхронизация
публикует композицию и меняет родителей. Измерение использует то же оформление. Миграция
или сброс настроек не нужны.

macOS резервирует 82px под реальные системные кнопки, не иллюстрации. Другие платформы используют
собственные элементы управления 44×32px. Области изменения размера: края 6px, углы 12px.
Интегрированные плавающие окна сохраняют 96px фона для нативного перетаскивания вне целей docking.
Полноэкранный режим убирает элементы заголовка, резервные области и жесты, оставляя панель
инструментов и вкладки клиентским UI. Утверждённая рамка без светлого контура или скоса сохраняет
прозрачный внутренний отступ компоновки 1px, не меняя геометрию изменения размера. Системные тени
и края не заменяются обходным решением с окном без рамки.

## Проверки и ограничения {#verification-and-limits}

```sh
cargo test -p kedra_ui --test contracts --locked
cargo test -p kedra_desktop --locked
cargo run -p kedra_desktop --example macos_header_policy --locked # macOS only
cargo xtask test -- features --only window-chrome --output target/test/window-chrome
cargo xtask check --non-interactive
```

Для запуска нужны доверенные входные данные сборки, свободный рабочий стол и новый каталог
результатов; см. [Подготовку запуска](../../../manual/testing/native-scenarios.md).
Сценарий использует отдельные состояние, учётные данные и приватные кадры. Он сбрасывает только
свою компоновку к четырём инструментам, проверяет DPR 1/2, команды, отключённые действия и
сохранение вкладок при интеграции заголовка, разделении и повторной интеграции. Барьеры GPU
и программно поданный ввод не проверяют физические системные кнопки, перетаскивание или работу
с разными мониторами. Захват Bevy не включает системные кнопки. Двойной щелчок и полноэкранный
режим требуют отдельной проверки; небезопасная прослойка и выдуманная платформенная политика
двойного щелчка не предоставляются. Эталонных снимков и сравнений пикселей заголовков нет;
снимки покрывают только элементы UI-kit. Нативная проверка остаётся неподтверждённой, включая
системные тени, кнопки и полное визуальное соответствие.
