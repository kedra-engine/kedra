# Сессии исходных документов

Сессии исходников реализуют часть
[ADR 0012](https://github.com/kedra-engine/kedra/blob/main/docs/decisions/0012-document-sessions-and-selection.md),
с изменениями Transform/UiCaption в памяти и историей, но без общего редактирования,
завершения ввода и публикации новых документов. Save группы исходников описан ниже. Инструкции Open,
работы с вкладками и внешними изменениями находятся в
[Editor workspace](../../../manual/editor/index.md).

## Полномочия и идентичность

`kedra_editor::documents` владеет одним принятым `kedra_authoring::persistence::Workspace`
на открытый проект. Вкладки используют общие принятые исходники, а не отдельные рабочие области.
Координатор владеет активным документом и необязательным выбранным `NodeAddress` каждого
открытого документа. Адрес сохраняет полную область вложенных экземпляров. Нативные сущности
и `ViewId` размещения панелей — идентичности представления и размещения, не исходного документа
или узла.
Подписи никогда не становятся локаторами.

Поддерживаемая область — проверенный корень ресурсов проекта и пространство имён `game`.
Поставка работающего редактора и дескрипторы AssetServer не определяют подключение исходников
с правом записи. Другие пространства имён и исходники самого редактора требуют явной настройки
области исходников. Нативный код
ссылается на ресурсы редактора полными логическими путями, например
`editor://prefabs/source-document.prefab.ron`, через загруженный каталог с проверкой членства
и опубликованной ревизии. Сохранённые UUID, соседние файлы метаданных, адреса с областью
экземпляров и данные происхождения сохраняют идентичность.
Интерфейс показывает пути относительно проекта, не абсолютные файловые пути; форматирование
не меняет нативный локатор.

## Разрешённые скриптовые транзакции {#authorized-script-transactions}

Явный запуск:
`kedra <project> --editor-script Editor/path.luau --edit-source game://Main.scene.ron`;
`--edit-source` повторяется для каждого разрешённого документа.
Скрипт определяет `function run(ctx)`;
обычные относительные модули читаются из неизменяемого снимка Editor/. Само открытие проекта код
не запускает. Снимок ограничен 256 файлами / 8 MiB, 64 KiB на файл, 1024 элементами / глубиной 16;
ссылки и специальные файлы запрещены. Это не sandbox против конкурентной враждебной подмены файлов.
Нативный host получает `edit_scripts::status` и `cancel`; отладочное наблюдение показывает статус
без права eval. Контекст общей истории привязан к `HistoryId`: логическая selection/focus
и отображения элементов коллекций без копий значений. Закрытые панели не блокируют Undo.
Для синхронной компиляции исходников editor-инструменты получают одну секунду на resume
при обычном общем сроке 45 секунд. Длинные пакеты уступают кадр между запросами через
`wait.updates(1)`; лимиты runtime behaviors не меняются.

Доверенные Rust bindings явно вызывают `kedra_editor::edit_scripts::install` с точными
допущенными путями, например `game://Prefabs/First.prefab.ron`. Разрешения задаёт нативный
код, не аргументы скрипта. Редакторный `kedra_authoring_luau` устанавливает
`ctx.edit.begin(label)`, но не поиск/автозапуск проектного кода или Save. Существующий
отладочный API наблюдения остаётся read-only и не получает это разрешение.
Первый успешный begin закрепляет разрешение за одной source-сессией; после её завершения
нужна новая нативная авторизация, даже если пути новой сессии совпадают.

Методы: `nodes(path)`, `set_property(node, component, path, value)`, `rename(node, name)`,
`remove_node(node)`, `reparent(node, parent)`, `remove_component(node, component)`,
`commit()` и `cancel()`. Узлы — непрозрачные userdata своей транзакции с отображаемым `name`.
Значения проходят нативную reflected-десериализацию и PropertySession; JSON служит транспортом,
не схемой исходника. Каждый запрос должен создавать корректный типизированный кандидат;
временно невалидные связанные поля этим binding не поддерживаются. Вложенные правки остаются
overrides принимающего документа. Доступ отклоняется при жестах/черновиках, незавершённом Save,
смене области или ревизий. Commit проверяет полный каталог и публикует одну именованную
запись общей истории, возвращая строку ID либо nil без изменений.

Пределы: 128 изменений, 4096 узлов на перечисление, 64 KiB JSON на свойство, 1024 байта
на путь поля/имя и 256 байт на ключ компонента. Доступны только допущенные документы.
Непринятый кандидат не публикуется после исключения, отмены или завершения run. Явный
commit сохраняется даже при последующей ошибке скрипта; ошибка runtime не отменяет commit.
Отдельной истории скрипта или Inspector нет. Файлы меняет только отдельный Save;
отдельный Save сохраняет полную связанную группу существующих исходников.

## Ограниченный приём исходников

Сканер редактора использует закреплённый `walkdir` 2.5.0 без перехода по ссылкам. Runtime получает
явные каталоги, а не файловый сканер. Ограничения:

| Граница инвентаря | Предел |
| --- | --- |
| Обнаруженные записи / глубина | 8192 / 64 |
| Документы scene/prefab | 128 |
| Каждый документ / соседний sidecar | 64 KiB / 64 KiB |
| Каждый другой ресурс | 8 MiB |
| Суммарные байты содержимого исходников | 64 MiB |

Суммарный учёт складывает содержимое документов и других ресурсов; у соседнего файла метаданных
отдельный пофайловый предел. Ссылки, специальные файлы, неадресуемые нативные пути, повторные
или нулевые идентификаторы метаданных, неверные документы и несовпадение идентичности документа
и его метаданных отклоняют приём. Отдельный `.meta` без исходника не является ресурсом.
Без соседнего файла метаданных источник остаётся неотслеживаемым; Open не создаёт UUID или
метаданные. Идентичность документа берётся из проверенного исходного документа.

Адаптер создаёт `SourceSnapshot` без индекса и один раз вызывает `Workspace::open_compiled`
для приёма. Существующие разбор, композиция, политики рефлексии и компиляция проверяют весь
кандидат и сохраняют неизменяемые результаты компиляции для просмотра. Один неподдерживаемый
или неверный документ может отклонить всю область; браузер остаётся доступен. Runtime `.prefabs.ron`
не переименовывается и не выдаётся за `catalog.prefabs.ron`. Индекс не записывается;
служебный учёт базового состояния без индекса не должен выглядеть несохранённой пользовательской
правкой.

Адаптер `LoadFromPath` только для рефлексии проверяет ссылки `game://` из исходников по реальным
идентичностям инвентаря и выдаёт UUID-дескрипторы. Неизвестные, чужие и неотслеживаемые ресурсы
дают явную ошибку. Адаптер не загружает ресурсы и не запускает выбранные метаданными обработчики
или загрузчики. Этот адаптер не подтверждает разрешение вложенных ресурсов и зависимостей,
декодирование изображений и шрифтов или готовность рендерера. Исходные пути и подписи сохраняются.
Эти дескрипторы не разрешают рендеринг или Save.

## Асинхронный Open и замена

Выбор/фокус браузера не активирует документ. Явный Open передаёт координатору проекта точный
относительный локатор. Повторный Open для того же локатора присоединяется к уже ожидающему
запросу. Более поздний Open для другого локатора заменяет цель активации. Обнаружение исходников
может завершиться для общего приёма, но опубликовать вкладку можно только для последнего
запрошенного локатора. Счётчики запросов проверяются на переполнение. Закрытие проекта
удаляет координатор и ожидающую работу; устаревшие результаты не наполняют другой проект.

Перед первым показом другого ресурса инвентаря вне основного потока повторно проверяются хеш
исходника, обычные каталоги-предки и текущая идентичность соседнего файла метаданных. Изменение
или исчезновение входных данных вызывает ошибку и
не заменяет активный документ. Уже открытый документ использует сохранённое принятое состояние,
не перечитывая его с диска. Новым членам инвентаря нужен повторный Open проекта; Refresh
не расширяет область исходников, не согласует исходники и не перезагружает документы. Проверки
файловой системы не изолируют от одновременной злонамеренной замены файлов.

## Представления, выбор и завершение жизни

У открытого документа одно отдельное сохраняемое представление в docking; начальный выбор — корень.
Повторный Open возвращает это представление и выбор. Активация вкладки обновляет координатор;
фокус инструмента — нет. Выбор должен принадлежать активному принятому графу. Отладочный
`editor.workspace` показывает ревизии, dirty и доступность истории вместе с docking,
а не удалённый API записи.

Первый документ скрывает пустой Document Preview. Поддерживаемые документы используют
[Scene View](scene-view.md); подходящая поставка и готовый кадр независимы от валидности
исходников. PNG и статический GLB открываются как представления отдельных ресурсов, не вымышленные
документы;
их активация очищает активную исходную цель. [Hierarchy](hierarchy.md) и
[Inspector](inspector.md) используют общий выбор с областью экземпляров без обязательного кадра.

Hide/Close сохраняет принятые исходники и дескрипторы; они доступны через Windows или Open.
Закрытие плавающего окна сохраняет скрытые представления и рабочие документы.
Черновики Transform удерживаются в Inspector; история исходников отказывает до их разрешения.
Закрытие главного окна блокируется до разрешения ввода/несохранённых исходников.
Диалог предлагает **Save and exit**, **Exit without saving** и **Cancel**. Save ждёт
публикации; черновики нужно сначала принять или отменить. Exit without saving восстанавливает
подтверждённый снимок без чтения/записи диска, очищает историю и завершает привязки.
Незавершённая публикация блокирует discard. Автоматического принятия по blur нет.
После перезапуска видимые вкладки автоматически запрашивают обычный приём исходников,
неактивные — при выборе. Настройки хранят пути, не доверенное содержимое. При ошибке
нет цикла повторных попыток; Open через Assets повторяет запрос с тем же дескриптором. Восстановление
несохранённой сессии, внешнее слияние и выполнение кода проекта не реализованы.
Прерванная разрешённая группа Save требует явного восстановления до Open.

## Владение Save

`documents::saving` закрепляет `prepare_existing_save` активного исходника и запускает
отдельный `kedra_authoring_fs` в IO pool. Инвентарь и каталог не меняются; новые/удалённые
файлы получают отказ до записи; связанные группы закрепляются полностью. Черновики Inspector
нужно завершить явно. Save не предоставляет Luau доступа к файловой системе.

Writer проверяет полный инвентарь/хеши, сохраняет разрешения и атомарно заменяет файл
через временные файлы с advisory-lease и журналом группы рядом с корнем исходников.
Хост также использует проверки идентичности ресурсов/sidecar из admission. Внешний конфликт
сохраняет рабочие значения и историю. Базу обновляет лишь точная квитанция; более новые рабочие
ревизии остаются dirty. Исходный снимок приёма поставки рендерера закреплён отдельно.

Известный отказ освобождает операцию. Неопределённый результат удерживает точные байты и
блокирует discard/закрытие; Retry Save согласует тот же запрос, включая уже записанные байты.
Save не собирает ресурсы и не очищает историю. Admission удерживает shared lease и
отказывает незавершённым группам. После перезапуска выполните `kedra recover-save <source-root>`;
сам Open не выполняет восстановление. См.
[ADR 0039](https://github.com/kedra-engine/kedra/blob/main/docs/decisions/0039-existing-source-save-groups.md).
См. [инструкцию Save](../../../manual/editor/inspector.md#сохранение-активного-документа) и
[ADR 0037](https://github.com/kedra-engine/kedra/blob/main/docs/decisions/0037-existing-document-save.md)
(English).

Open, коллизии, неверные, отсутствующие и несовпадающие данные, отказ ссылок, выбор с областью
