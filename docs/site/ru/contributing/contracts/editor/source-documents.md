# Сессии исходных документов только для чтения

Сессии исходников только для чтения реализуют часть
[ADR 0012](https://github.com/kedra-engine/kedra/blob/main/docs/decisions/0012-document-sessions-and-selection.md),
без предложенного полного цикла редактирования, завершения ввода и Save. Инструкции Open,
работы с вкладками и внешними изменениями находятся в
[Editor workspace](../../../manual/editor/index.md).

## Полномочия и идентичность

`kedra_editor::documents` владеет одним принятым `kedra_authoring::persistence::Workspace`
на открытый проект. Вкладки используют общие принятые исходники, а не отдельные рабочие области.
Координатор владеет активным документом и необязательным выбранным `NodeAddress` каждого
открытого документа. Адрес сохраняет полную область вложенных экземпляров. Нативные сущности
и `ViewId` размещения панелей — идентичности представления и размещения, не исходного документа
или узла.
Подписи никогда не становятся локаторами.

Поддерживаемая область — проверенный корень ресурсов проекта и пространство имён `game`.
Поставка работающего редактора и дескрипторы AssetServer не определяют подключение исходников
с правом записи. Другие пространства имён и исходники самого редактора требуют явной настройки
области исходников. Нативный код
ссылается на ресурсы редактора полными логическими путями, например
`editor://prefabs/source-document.prefab.ron`, через загруженный каталог с проверкой членства
и опубликованной ревизии. Сохранённые UUID, соседние файлы метаданных, адреса с областью
экземпляров и данные происхождения сохраняют идентичность.
Интерфейс показывает пути относительно проекта, не абсолютные файловые пути; форматирование
не меняет нативный локатор.

## Ограниченный приём исходников

Сканер редактора использует закреплённый `walkdir` 2.5.0 без перехода по ссылкам. Runtime получает
явные каталоги, а не файловый сканер. Ограничения:

| Граница инвентаря | Предел |
| --- | --- |
| Обнаруженные записи / глубина | 8192 / 64 |
| Документы scene/prefab | 128 |
| Каждый документ / соседний sidecar | 64 KiB / 64 KiB |
| Каждый другой ресурс | 8 MiB |
| Суммарные байты содержимого исходников | 64 MiB |

Суммарный учёт складывает содержимое документов и других ресурсов; у соседнего файла метаданных
отдельный пофайловый предел. Ссылки, специальные файлы, неадресуемые нативные пути, повторные
или нулевые идентификаторы метаданных, неверные документы и несовпадение идентичности документа
и его метаданных отклоняют приём. Отдельный `.meta` без исходника не является ресурсом.
Без соседнего файла метаданных источник остаётся неотслеживаемым; Open не создаёт UUID или
метаданные. Идентичность документа берётся из проверенного исходного документа.

Адаптер создаёт `SourceSnapshot` без индекса и один раз вызывает `Workspace::open_compiled`
для приёма. Существующие разбор, композиция, политики рефлексии и компиляция проверяют весь
кандидат и сохраняют неизменяемые результаты компиляции для просмотра. Один неподдерживаемый
или неверный документ может отклонить всю область; браузер остаётся доступен. Runtime `.prefabs.ron`
не переименовывается и не выдаётся за `catalog.prefabs.ron`. Индекс не записывается;
служебный учёт базового состояния без индекса не должен выглядеть несохранённой пользовательской
правкой.

Адаптер `LoadFromPath` только для рефлексии проверяет ссылки `game://` из исходников по реальным
идентичностям инвентаря и выдаёт UUID-дескрипторы. Неизвестные, чужие и неотслеживаемые ресурсы
дают явную ошибку. Адаптер не загружает ресурсы и не запускает выбранные метаданными обработчики
или загрузчики. Этот адаптер не подтверждает разрешение вложенных ресурсов и зависимостей,
декодирование изображений и шрифтов или готовность рендерера. Исходные пути и подписи сохраняются.
Эти дескрипторы не разрешают рендеринг или Save.

## Асинхронный Open и замена

Выбор/фокус браузера не активирует документ. Явный Open передаёт координатору проекта точный
относительный локатор. Повторный Open для того же локатора присоединяется к уже ожидающему
запросу. Более поздний Open для другого локатора заменяет цель активации. Обнаружение исходников
может завершиться для общего приёма, но опубликовать вкладку можно только для последнего
запрошенного локатора. Счётчики запросов проверяются на переполнение. Закрытие проекта
удаляет координатор и ожидающую работу; устаревшие результаты не наполняют другой проект.

Перед первым показом другого ресурса инвентаря вне основного потока повторно проверяются хеш
исходника, обычные каталоги-предки и текущая идентичность соседнего файла метаданных. Изменение
или исчезновение входных данных вызывает ошибку и
не заменяет активный документ. Уже открытый документ использует сохранённое принятое состояние,
не перечитывая его с диска. Новым членам инвентаря нужен повторный Open проекта; Refresh
не расширяет область исходников, не согласует исходники и не перезагружает документы. Проверки
файловой системы не изолируют от одновременной злонамеренной замены файлов.

## Представления, выбор и завершение жизни

У открытого документа одно отдельное сохраняемое представление в docking; начальный выбор — корень.
Повторный Open возвращает это представление и выбор. Активация вкладки обновляет координатор;
фокус инструмента — нет. Выбор должен принадлежать активному принятому графу. Отладочный
`editor.workspace` показывает сессии только для чтения вместе с docking, а не API записи.

Первый документ скрывает пустой Document Preview. Поддерживаемые документы используют
[Scene View](scene-view.md); подходящая поставка и готовый кадр независимы от валидности
исходников. PNG и статический GLB открываются как представления отдельных ресурсов, не вымышленные
документы;
их активация очищает активную исходную цель. [Hierarchy](hierarchy.md) и
[Inspector](inspector.md) используют общий выбор с областью экземпляров без обязательного кадра.

Hide/Close сохраняет принятые исходники и дескрипторы; они доступны через Panels или Open.
Закрытие плавающего окна со смешанным содержимым безопасно только при запрете записи.
До разрешения изменений нужны завершение ввода, доступ к изменённым документам и одобрение
закрытия по ADR 0012. Перезапуск восстанавливает только неактивные заглушки: настройки
не содержат доверенные документы и не принимают сохранённые пути автоматически. Open через
Assets проверяет текущую область исходников и повторно использует дескриптор. Восстановление
после сбоя, согласование изменений, Save, Discard и выполнение кода проекта не реализованы.

[`documents/source.rs`](https://github.com/kedra-engine/kedra/blob/main/crates/kedra_editor/src/documents/source.rs)
и
[`documents/inspection.rs`](https://github.com/kedra-engine/kedra/blob/main/crates/kedra_editor/src/documents/inspection.rs).
Локальные `tests.rs`, `source_tests.rs`, `inspection_tests.rs` проверяют повторный и последний
Open, коллизии, неверные, отсутствующие и несовпадающие данные, отказ ссылок, выбор с областью
экземпляров и неизменность
исходников при ошибке. [Asset Browser](asset-browser.md) описывает нативную проверку Open.
Нативная проверка этой ревизии ещё не подтверждена.
