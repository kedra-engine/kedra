# Контракт Asset Browser

Asset Browser предоставляет навигацию и открытие исходников только для чтения по
[ADR 0013](https://github.com/kedra-engine/kedra/blob/main/docs/decisions/0013-asset-browser-panel.md).
Клавиатурные команды, поиск, Open и Refresh описаны в
[руководстве](../../../manual/editor/asset-browser.md).

## Модель, эффекты и идентичность

`kedra_editor::asset_browser::model` и `tree` — обычное Rust-состояние, не ECS-база исходников.
`Panel`, `view`, `tiles`, `input`, `hints` связывают асинхронные операции, представления
из исходников
и нативный ввод. `workspace` размещает инструмент и направляет явный Open через
[координатор документов](source-documents.md); отдельного загрузчика документов у браузера нет.
Просмотр, фильтрация, Refresh и Open не создают метаданные, не строят поставки, не запускают
код проекта и не записывают исходники. Задачи и результаты привязаны к сохраняемому инструменту
и поколению запроса; устаревшие ответы каталога или дерева не заменяют текущие результаты.

Операции используют точные нативные `PathBuf`/`OsString`. Подписи с потерей данных не преобразуются
обратно в локаторы. Перед чтением повторно проверяются каталоги-предки. `.meta` не является
отдельной плиткой. По ссылкам переходить нельзя; записи-ссылки, специальные файлы и записи без
допустимого адреса нельзя активировать. Значок отслеживания проверяет только наличие рядом
обычного файла метаданных, который не является символической ссылкой, а не корректность метаданных.
Статус показывает относительный `assets/...`, не абсолютный путь. Конкурентная
замена файлов не предотвращается: эти проверки не создают изолированную среду.

## Бюджеты списков и кеша

Непосредственное перечисление `std::fs::read_dir` допускает не более 4096 записей и 1 MiB
закодированных имён. Превышение отклоняет список. Успешный результат сортирует каталоги
перед файлами, затем точные нативные имена, сохраняет до 512 записей и отмечает неполноту.
Это ограниченная выборка каталога, не полный список исходников рабочей области. Поиск не рекурсивен
и не читает содержимое; закреплённый `unicase` 2.9.0 сопоставляет Unicode без учёта регистра,
не меняя идентичность.

Дерево читает только раскрытые ветви. Раскрытие/видимые строки ограничены 512, кеш дочерних
путей — 4096, байты закодированных кешированных путей — 1 MiB. Сворачивание сохраняет кеш
до Refresh. При достижении предела диагностика предлагает Refresh; дерево может быть неполным.
История навигации ограничена 64 местоположениями. Нативный поиск принимает до 256 символов,
отклоняя управляющие
при вставке/вводе; это не протокол завершения исходного поля.

## Сохранение состояния и ошибки

Выбор браузера, клавиатурный фокус и активация документа различны. Сетка и список используют общие
данные и выбор; режим и фильтр типов действуют на браузер целиком. Успешные Back/Forward
восстанавливают поиск, допустимый выбор и прокрутку для местоположения. Исчезнувшие записи очищают
только недействительный выбор. Скрытый фильтром выбор остаётся в статусе; Open не подменяет
его первым результатом. Float/Redock и Hide/Reopen сохраняют корень, нативное поле поиска и модель.
Перезапуск восстанавливает дескрипторы размещения панелей, но не историю браузера.

Загрузка, пустая папка, отсутствие совпадений, недоступный или устаревший список, неполный список,
неотслеживаемые данные, неподдерживаемое открытие и отказ приёма — разные состояния.
Ошибка Refresh сохраняет старый список как устаревший и блокирует открытие до восстановления.
Ошибка Open сохраняет выбор и активный документ; исходник по умолчанию не создаётся.

## Retained-представление и визуальный источник

Монтируются только видимые строки с запасом за краями по нативной геометрии области просмотра
и прокрутки. При переносе временно скрытые окна или окна без выделенной области не вызывают
перестроение виртуализации. `assets/editor/prefabs/asset-browser.prefab.ron` собирает общие поля,
плоские кнопки с иконками, навигационную цепочку, строки папок, плитки и полосы прокрутки.
Flair CSS `styles/asset-browser.css` задаёт стиль через существующие токены. Bevy отвечает за
редактирование текста, кнопки, компоновку, прокрутку и перетаскивание ползунка. Адаптер удаляет
`Node` ползунка из исходника: нативный `ScrollbarThumb` задаёт геометрию после компоновки,
CSS — цвет.

Визуальный источник — UI-KIT `163:37852`, правила плоских панелей — `163:37771`; сохраняется
[каноническое происхождение](../ui/design-provenance.md#asset-browser-exports).
Общие заголовки окон и docking не перерисовываются. Плитки — 112 × 96 логических пикселей,
строки списка — 22px. Внешняя ширина боковой панели 200px включает разделитель 4px:
для содержимого остаётся 196px при наличии места. Панель инструментов переносится на строки,
затем прокручивается при превышении предельной высоты. Общие всплывающие подсказки появляются
у курсора после задержки, не заменяя содержимое баннером. Статус выбранного источника, типа
и отслеживания отделён от постоянно видимого счётчика.

Значки показывают тип ресурса, а не его миниатюру. New/Import отключены с пояснениями.
Отрисованные миниатюры, рекурсивный поиск, выбор ссылок, переименование, перемещение, удаление,
создание, импорт и Save исходников не реализованы. Scene View и просмотр отдельных ресурсов
требуют подходящих ресурсов; Inspector и Hierarchy доступны только для чтения. Общие текстовые
Undo/Redo, системный буфер обмена, IME, физический ввод, работа с разными мониторами и точное
соответствие пикселям Figma не проверены.

## Проверка

Реализация и локальные тесты модели и ошибок находятся в
[`asset_browser`](https://github.com/kedra-engine/kedra/blob/main/crates/kedra_editor/src/asset_browser/mod.rs).
Они проверяют списки, состояния, виртуализацию, дерево и сохранение состояния при ошибках.
Тесты приёма принадлежат `documents`; браузер не дублирует тесты компилятора.

```sh
cargo test -p kedra_editor --lib --locked
cargo test -p kedra_editor --test contracts --locked icons::
cargo xtask check --non-interactive
cargo xtask test -- features --only browser --output target/test/browser
```

Для нативного сценария нужен свободный рабочий стол. Сценарий строит поставку и открывает
изолированную копию тестового проекта. Он проверяет нативные элементы управления, приём исходников
и отказы, сохранение идентичности и кадры рендерера. Результаты хранятся в `target/`, не среди
эталонов дизайна. Нативная проверка этой ревизии ещё не подтверждена.
