# Контракт Inspector только для чтения

Inspector показывает значения исходников только для чтения по
[ADR 0015](https://github.com/kedra-engine/kedra/blob/main/docs/decisions/0015-inspector-panel.md),
[ADR 0011](https://github.com/kedra-engine/kedra/blob/main/docs/decisions/0011-universal-reflected-inspector.md)
и
[ADR 0009](https://github.com/kedra-engine/kedra/blob/main/docs/decisions/0009-property-editing-and-inspector.md).
Эта же архитектура рассчитана на поддержку редактирования. Просмотр, поиск, блокировка цели
и стандартное представление описаны в [руководстве](../../../manual/editor/inspector.md).
Редактирование, история, команды компонентов, диалоги выбора, Save и выполнение проекта
недоступны, в том числе во встроенных специализированных представлениях.
Begin/Propose/Accept/Cancel — предложенная семантика, а не доступный протокол записи.

## Владельцы и слои

| Владелец | Ответственность |
| --- | --- |
| `kedra_ui::fields` | Общие сохраняемые строки, подписи, области значений, диагностика, нативное взаимодействие только для чтения и адаптивная компоновка |
| `kedra_inspector` | Обнаружение через рефлексию, ограниченный просмотр, выбор представлений, стандартная и специализированная композиция, сохраняемые представления значений |
| `kedra_editor::inspector` | Следование за целью исходника, её блокировка, происхождение и жизненный цикл стыкуемой панели |
| `kedra_editor::documents` | Принятая рабочая область, активный документ и постоянный выбор с областью экземпляров |
| Существующий компилятор исходников | Итоговые типизированные значения и разрешение ссылок |

Runtime UI не должен зависеть от inspector, authoring или editor. `kedra_inspector` относится
к слою editor; его рабочие зависимости — только Bevy и `kedra_ui`, без authoring/desktop/editor.
Архитектурная проверка разрешает ему зависимости внутри рабочей области только на слои core/runtime.
Обычный редактор также использует те же элементы просмотра значений через рефлексию без привязки
к документу. Общие элементы интерфейса должны находиться в `kedra_ui::fields`, а не в частных
копиях панели. Модели — обычные значения; сущности остаются в адаптерах UI.

Общие примитивы префабов и CSS используют существующую поставку. Элементы управления Rust получают
явные скомпилированные шаблоны и контекст темы: они не ищут UUID редактора и не читают его ресурсы.
Хост задаёт идентичность выбора и контекст исходника при композиции.

## Binding, заимствования и исходники

Цель просмотра включает идентичность области исходников, ID документа и полный `NodeAddress`
с областью вложенных экземпляров. Значения определяются ключом компонента, версией схемы,
представляемым нативным типом и путём рефлексии Bevy. Подписи, переводы, порядок показа и сущности
рендерера не привязывают данные. Просмотр исходника не требует работающей области просмотра
или поставки ресурсов рендерера.

Адаптер перечисляет компоненты собранного узла из исходников, не сгенерированные `Name`, компоненты
иерархии или рендеринга. `Workspace::open_compiled` сохраняет неизменяемые результаты компиляции
при приёме; существующий `ReflectComponent` читает итоговые значения с учётом переопределений.
Метаданные происхождения хранятся отдельно, вычисленная компоновка UI не подменяет заданную
в исходнике. Если рабочая ревизия зависимости отличается от принятой, просмотр становится
недействительным вместо возврата устаревших скомпилированных значений.

Общий `ValueBinding` получает неизменяемое значение через рефлексию, непрозрачный токен хоста,
доступ с причиной и метаданные. Изменяемый World исходников или игры ему не передаётся.
Аргументы World в обработчиках относятся только к представлению. Хост владеет снимком всё время
заимствования; обработчики не должны удерживать `ValueBinding`, строки обнаруженных полей или
заимствованные поля после возврата mount/update либо замены снимка. Удаление цели или завершение
жизни области даёт Target unavailable, а не одноимённую замену. Lock фиксирует идентичность,
но не замораживает значения.

Ссылкам нужен символьный контекст от хоста, не временные номера сущностей. Адаптер исходников
явно сообщает об ограничениях представления `Entity` и `Option<Entity>`: непривязанный порт
после преобразования в нативное представление нельзя показывать как явно заданный в исходнике
`None`. Если существующий API не позволяет восстановить точное намерение, нужно показать
ограничение, а не вводить второй декодер.

## Discovery и детерминированная специализация

Обнаружение использует Bevy `TypeRegistry`, информацию представляемого типа `TypeInfo`,
`PartialReflect` и нативные пути. Строки — временные проекции, не новая сериализованная схема,
реестр типов или универсальная модель значений. Примитивы и строки сохраняют тип и точность;
структуры, кортежи, кортежные структуры, активные варианты перечислений и ограниченные коллекции
раскрывают структуру. При непрозрачном типе или отсутствии возможностей сохраняются тип и причина.
Не допускается нормализация всех чисел через `f64` или промежуточная сериализация значений
в строки. Точные числа форматируются так, чтобы обратное чтение сохраняло значение.

Обычная регистрация в Rust сначала выбирает явно заданный редактор поля по нативному типу
владельца и разобранному пути Bevy. Затем проверяются редактор точного типа, стандартное
структурное представление и представление неподдерживаемого значения. Повторная регистрация
с тем же ключом и приоритетом завершается ошибкой, не заменяя запись. Порядок регистрации,
короткие имена и пространства имён не определяют выбор редактора.

Специализированные редакторы отвечают за монтирование, обновление и удаление, собирают общие
элементы управления и рекурсируют с общим бюджетом. Обновление той же цели меняет сохраняемые
представления; смена представляемого типа или редактора удаляет только затронутое поддерево.
При ошибке монтирования нужно освободить ресурсы, выделенные обработчиками. Ошибка должна
оставаться видимой, а пользователь должен иметь возможность явно открыть стандартное представление.
Стандартный режим обходит специализации всего выбранного поддерева, включая потомков. Оба пути
используют ту же неизменяемую привязку, нативные значения, доступ и диагностику. Специализация
не разрешает запись и не скрывает неподдерживаемое содержимое молча. Встроенная регистрация
не вводит динамическую загрузку кода проекта или стабильный ABI расширений.

Тестовые представления точного типа и вложенного поля проверяют сами элементы управления,
не только ID выбора редактора. Панель передаёт действия раскрытия только для деревьев компонентов
верхнего уровня. Потребитель рекурсивного специализированного представления должен сам передавать
действия внутренних деревьев. Поставляемые плоские образцы не подтверждают общую работу
вложенных раскрытий.

## Сохранение, бюджеты и нативный текст

Раскрытие, поиск, стандартный режим и блокировка локальны для представления. Обновление той же
цели сохраняет элементы управления, раскрытие, нативное выделение и прокрутку. Поиск сохраняет
цель и контекст предков и компонентов; фильтрация и сворачивание не меняют выбор документа.
Фокус инструмента не активирует другой документ. Hide/Reopen, Float/Redock и разворачивание
используют сохраняемый инструмент, общий механизм размещения панелей и действий.

Общие пределы перестроения: глубина рефлексии 32, 128 элементов коллекции, 2048 обнаруженных строк,
4096 скалярных значений Unicode на предварительный просмотр. Раскрытие, поиск и рекурсия
специализированных представлений используют общий бюджет; фильтрация не запускает неограниченный
обход. Исчерпание бюджета видно пользователю. Усечённый просмотр не является полным значением
для копирования и не меняет источник. Коллекции показывают первый ограниченный сегмент без
постраничного просмотра. Ключам отображений и элементам множеств не приписывается позиционная
идентичность поля. Непрозрачные для Bevy типы, например `BTreeSet`, требуют своего представления.

Текст только для чтения использует нативное выделение и копирование там, где они поддерживаются.
Он не имитируется редактируемым полем с игнорируемой записью или отдельным текстовым редактором.
Поиск не является сеансом правки исходника. Перед заявлением поддержки копирования и вставки
нужно отдельно проверить системный буфер обмена. `kedra_ui/system-fonts` включает поиск системных
резервных шрифтов Bevy/Parley без поставки проприетарных шрифтов. Наличие CJK-шрифтов зависит
от хоста; предупреждения ICU о сегментации сложных письменностей остаются. Поддержка IME
и универсальное покрытие глифов не сертифицированы.

## Визуальный источник и acceptance

Канонический [UI-kit provenance](../ui/design-provenance.md#inspector-and-shared-controls):
Flat compact A `131:20213` (320px) и `131:20388` (480px). Блок идентичности — 40px,
заголовки — 24px, элементы управления — 22px с рамками. Связанные строки имеют зазоры 2px,
группы и секции — 4px. Стопка образца Window glyph занимает 394px с неизменными значениями
и единицами; это не универсальная высота схемы. Отступы области прокрутки — 8px по вертикали /
12px по горизонтали, без повторения во вложенных группах. Типографика — 12/16, иконки — 16px;
при ширине тела свойств ниже 296px подписи размещаются над значениями. Нативная компоновка,
семантические токены, точные экспорты и общие ресурсы из исходников остаются определяющими.
Transform/Mesh/Material — примеры, не фиксированные схемы; вращение сохраняет нативное
представление до определения политики углов Эйлера.

Не показывайте неподдерживаемые Add component, Reset, Apply/Revert или действия перехода к ресурсу.
До выпуска владелец должен проверить отсутствие выбора, недоступную или заблокированную цель,
пустые компоненты, отсутствующие возможности, ошибки специализированных представлений, лимиты,
отсутствие совпадений, узкий и плавающий вид. Базовый образец эти состояния не проверяет.
Недостающие композиции требуют согласования с владельцем дизайна. Физический ввод, системный
буфер обмена и IME, программы чтения с экрана, точное соответствие пикселей и одобрение
диагностических и узких состояний владельцем ещё не проверены.

## Проверка

API реализации находятся в
[`kedra_inspector`](https://github.com/kedra-engine/kedra/blob/main/crates/kedra_inspector/src/lib.rs),
[`documents/inspection.rs`](https://github.com/kedra-engine/kedra/blob/main/crates/kedra_editor/src/documents/inspection.rs)
и
[`inspector`](https://github.com/kedra-engine/kedra/blob/main/crates/kedra_editor/src/inspector/mod.rs).
Публичные контракты Inspector проверяют нативную точность и структуру, неподдерживаемые типы,
выбор редактора, ошибки специализаций, сохранение состояния, возврат к стандартному представлению
и общие лимиты. Тесты исходников проверяют итоговые переопределения, происхождение, завершение
жизни ревизии или области и ограничения ссылок. Тесты панели проверяют блокировку и сохранение
элементов управления без области просмотра и записи исходников. Выполните проверки репозитория и:

```sh
cargo xtask test -- features --only inspector,inspector-fixture --output target/test/inspector
```

Обоим реальным потребителям нужны нативные кадры и ввод, доступ с клавиатуры, прокрутка,
сохранение состояния, перенос между окнами и неизменность снимков исходников и истории.
Сценарий строит проверенную поставку и запускает изолированные процессы редактора. Сценарий
исходников копирует `tests/fixtures/test_project`, читает существующие исходники `Inspector/`,
не генерируя проект или префабы. Независимый потребитель выбирает
`editor://fixtures/inspector.scene.ron` через отладочный `--scene`, используя композицию из
исходников и нативные значения через рефлексию. Luau `inspector.presentation` подаёт ввод для
обновления и стандартного режима; Rust независимо проверяет точность, специализацию, возврат
к стандартному виду и сохранение состояния. Нативные адаптеры сохраняют регистрацию, обновление
только для чтения и раскрытие. Независимость от владельца документов не означает зависимость
runtime от editor.

Сценарии подают ввод в Bevy и синхронизируют чтение кадров GPU; физический системный ввод
требует отдельной проверки. Временные кадры удаляются, поэтому отчёты не содержат PNG или
эталонных снимков. Результаты проверок хранятся в `target/`. Независимые эталоны должны
происходить из Figma, не из кадров приложения. Нативная проверка этой ревизии ещё не подтверждена.
