# Контракт взаимодействия Inspector с исходниками

Inspector показывает значения исходников по
[ADR 0015](https://github.com/kedra-engine/kedra/blob/main/docs/decisions/0015-inspector-panel.md),
[ADR 0011](https://github.com/kedra-engine/kedra/blob/main/docs/decisions/0011-universal-reflected-inspector.md)
и
[ADR 0009](https://github.com/kedra-engine/kedra/blob/main/docs/decisions/0009-property-editing-and-inspector.md).
Эта же архитектура рассчитана на поддержку редактирования. Просмотр, поиск, блокировка цели
и стандартное представление описаны в [руководстве](../../../manual/editor/inspector.md).
Нативное представление `scene.transform` и встроенный Luau-drawer `ui.caption` поддерживают
изменения в памяти и историю исходников. Размеры Primitive, цвет/metallic/roughness Surface
и цвет/illuminance Sun используют тот же нативный типизированный адаптер исходников.
Поддерживаемые скалярные UI-значения используют тот же адаптер и пассивное обновление.
Bool/unit-enum показаны нативными checkbox/меню; payload-enum требуют нативных defaults
или явных конструкторов предметной области. Default view остаётся только для чтения.
Классы, плотности изображений и тени используют прямые проверяемые изменения полей
и целые структурные предложения без Apply/Cancel. Типизированные ресурсные поля
показывают записанные логические пути, поиск и drop из Asset Browser с проверкой типа
и историей исходника. Команды компонентов и выполнение проекта недоступны.
Save существующего активного исходника принадлежит хосту
и отказывает при незавершённых черновиках. Полный протокол завершения ввода остаётся предложением
за пределами поддерживаемых live-полей и структурных предложений.

## Владельцы и слои

| Владелец | Ответственность |
| --- | --- |
| `kedra_ui::fields` | Общие сохраняемые строки, подписи, области значений, диагностика, нативное взаимодействие только для чтения и адаптивная компоновка |
| `kedra_ui::popup` | Нативное размещение привязанной поверхности и ограничения размера/фокуса; действия и закрытие принадлежат потребителю |
| `kedra_inspector` | Обнаружение через рефлексию, ограниченный просмотр, выбор представлений, стандартная и специализированная композиция, сохраняемые представления значений |
| `kedra_inspector_luau` | Ограниченная конечная Luau-композиция, нативные поля и завершение владельца runtime |
| `kedra_editor::inspector` | Следование за целью исходника, её блокировка, происхождение и жизненный цикл стыкуемой панели |
| `kedra_editor::documents` | Принятая рабочая область, активный документ и постоянный выбор с областью экземпляров |
| Существующий компилятор исходников | Итоговые типизированные значения и разрешение ссылок |

Runtime UI не должен зависеть от inspector, authoring или editor. `kedra_inspector` относится
к слою editor; его рабочие зависимости — только Bevy и `kedra_ui`, без authoring/desktop/editor.
Архитектурная проверка разрешает ему зависимости внутри рабочей области только на слои core/runtime.
Обычный редактор также использует те же элементы просмотра значений через рефлексию без привязки
к документу. Общие элементы интерфейса должны находиться в `kedra_ui::fields`, а не в частных
копиях панели. Модели — обычные значения; сущности остаются в адаптерах UI.

Общие примитивы префабов и CSS используют существующую поставку. Элементы управления Rust получают
явные скомпилированные шаблоны и контекст темы: они не ищут UUID редактора и не читают его ресурсы.
Хост задаёт идентичность выбора и контекст исходника при композиции.

## Binding, заимствования и исходники

Цель просмотра включает идентичность области исходников, ID документа и полный `NodeAddress`
с областью вложенных экземпляров. Значения определяются ключом компонента, версией схемы,
представляемым нативным типом и путём рефлексии Bevy. Подписи, переводы, порядок показа и сущности
рендерера не привязывают данные. Просмотр исходника не требует работающей области просмотра
или поставки ресурсов рендерера.

Адаптер перечисляет компоненты собранного узла из исходников, не сгенерированные `Name`, компоненты
иерархии или рендеринга. `Workspace::open_compiled` предоставляет начальные неизменяемые результаты
компиляции. Адаптер документов фиксирует полный набор рабочих ревизий и при изменении повторно
компилирует текущий рабочий каталог, используя принятые символические ссылки без загрузки ресурсов
и записи исходников. Кэш заменяется только после успешной компиляции всего каталога. Существующий
`ReflectComponent` читает итоговые значения с учётом переопределений; метаданные происхождения
хранятся отдельно, вычисленная компоновка UI не подменяет заданную в исходнике. Устаревшая ревизия
цели или зависимости запрещает просмотр до успешного обновления, а не возвращает старое значение
под новой ревизией.

Inspector замечает успешное обновление исходников независимо от выбора и блокировки цели,
обновляет сохранённые контролы и удаляет представления компонентов, удалённых из исходника.
Без изменений повторная компиляция не выполняется. Нативное принятие Transform и Undo/Redo
обновляют кэш и открытые графы. Scene View повторно компилирует привязки рендерера, проверяет
неизменность топологии и остальных компонентов, обновляет сохранённые Transform
и пассивные UI-значения,
принадлежащие виду mesh/material примитивов и сценовый свет, требует новый readback.
Все ресурсы и производные bounds проверяются до замены нативных значений; handles,
сущности и камера сохраняются. Общее согласование между представлениями
и публикация новых документов не реализованы.

Точные нативные целые/float не проходят через общий f64. Предложение оси Vec3 сохраняет
остальные оси целого вектора. SDR-цвет сохраняет нативное представление sRGB/linear и
точные каналы при no-op. Hex вводится в sRGB с необязательной alpha; HDR/другие пространства
получают диагностику/default view без неявного clamping. Общий просмотр leaf не разрешает
изменение неподдержанных значений и ссылок. Образец цвета раскрывает точные RGBA-каналы,
выбор пространства хранения и именованную палитру; палитра сохраняет alpha и представление.
Нативные предложения enum конструируют
полное значение, точно сохраняя текущий payload. Конструкторы Primitive принадлежат
адаптеру предметной области редактора.

Дискретный `ControlEvent` сохраняет исходную идентичность `Arc<ControlBinding>`, цель/путь
и набор ревизий. Заменённый контрол или устаревшее меню не могут заимствовать новые права.
Редактор проверяет доступ, видимого владельца и черновики, затем полностью компилирует
типизированный кандидат перед синхронной публикацией. Checkbox не меняет состояние
оптимистично до обновления исходника.

`PropertySession` поднимает индексные/составные изменения и изменения под существующим
override родительского поля/компонента в точную замену всего компонента. Нативное
конструирование и `Reflect::set` исключают семантику изменения размера через `try_apply`.
Символические ссылки и эффективные соседние поля сохраняются; индексы не становятся ID.

`PassiveView::prepare_refresh` подготавливает обновление UI с прежней топологией без
интерактивной гидратации. Публикация проверяет исходную идентичность экземпляра/снимка.
Обновляются только изменённые исходные поля: соседние изменения не сбрасывают компоновку
stylesheet. Отсутствующие представления/зависимости запрещают изменение сохранившихся UI-узлов.

`UiLayout` собирает смысловые группы над исходным нативным Node. Выборочное обнаружение
полей исключает соседние поддеревья до расходования бюджета строк, не создавая отдельное
значение рефлексии. Вложенные TreeView делегируют владение раскрытием и фильтрацию через
`ValueEditorView`. Length предлагает целый Val: число и единица находятся в одной строке,
числовое изменение сохраняет точную нативную единицу.

## Прямое редактирование коллекций {#immediate-collections}

`kedra_inspector::collections` сохраняет представление нативного списка, временные
стабильные идентичности элементов и выделение. Поля получают обычные полные пути
`SourceField`/`SourceControl`. Только добавление, удаление и перестановка предлагают
целый нативный список. Предложения выполняются после нативной фазы редактирования
Bevy и фиксируют исходные binding/ревизию; проверка и публикация принадлежат
существующему адаптеру исходников. Отдельного Apply/Cancel и оптимистичной локальной
мутации нет. Принятые локальные структурные изменения сохраняют уцелевшие контролы
и обновляют их индексные нативные пути.
Host связывает отображения элементов, выделение и раскрытие без копий значений с точным
source `HistoryId`. Undo/Redo запрашивает это вложение явно, не сопоставляя значения списков;
фокус восстанавливается после перепривязки полей только для доступных представлений.
Эти вложения не выполняют Undo и не публикуют исходники.
Вне сохранённых соответствий обновление той же длины сохраняет позиционные контролы;
смена длины сбрасывает идентичности и выделение без догадки о том, кто сохранился.

Невалидный/непринятый текст, очередь действий и ожидающие предложения остаются
незавершёнными даже при скрытой панели, блокируя историю, Save, смену цели и Close.
Структурное предложение исключает из проверки только себя, не текст или другое действие.
Вложенные Color/Val получают нативные значения. Add использует уникальный валидный
класс или нативный конструктор; плотность копирует существующий валидный ресурс.
Пустой список обязательных изображений открывает типизированный picker, если есть
варианты из соответствующей delivery. Первый нативный элемент создаётся только после
выбора, проверки и загрузки; отмена/ошибка сохраняет пустой список. Без вариантов Add
выключен. Конструктор не ослабляет исходную валидацию `UiImage`: невалидный пустой
документ по-прежнему не принимается, удаление последнего обязательного изображения
остаётся невалидным.

Нижние Add/Remove, grip и Alt+Up/Down предлагают структурные изменения. Наведение,
drop снаружи, Escape, потеря доступа и перенос окна ничего не публикуют. Потеря
binding/окна/доступа завершает drag, а не позволяет ему ожить после возврата прав.
Нативная приёмка охватывает узкие/плавающие панели и выделение/фокус через историю
исходника в пределах сохранённых соответствий. Autoscroll длинных списков и drag
между окнами ещё требуют приёмки.

## Типизированные ресурсные ссылки {#typed-resource-references}

`CompiledPrefab::dependency_path` читает точные записанные пути source/subasset;
чужая или неоднозначная идентичность не имеет пути. Копируемое поле не даёт
редактировать UUID. `ReferenceEvent` сохраняет исходный binding и запрашивает
точный логический путь либо Clear для optional. Поиск, подсветка и drag hover
относятся только к представлению.

Редактор проверяет ревизии, нативный тип и членство в соответствующей проверенной
delivery до загрузки и повторяет проверки перед публикацией. Готовность загрузки
не выдаёт права. Ожидающий запрос блокирует Save/навигацию; отмена, ошибка и timeout
не публикуют. Проверенный no-op того же пути или пустого optional не запускает
загрузку и сохраняет историю/Redo. Нативное reflection-клонирование сохраняет
владение strong handle до перехода к динамическому восстановлению.
Нативная приёмка ресурсов охватывает фильтрацию/Escape picker, optional Clear, no-op
того же пути, drops изображений/моделей, отказ несовместимого drop, отмену drag и Undo/Redo.
Drops между окнами и управляемые отказы/timeout ожидающей загрузки ещё требуют приёмки.
Обновление Environment сохраняет камеру и учитывает студийное освещение.
Model заранее собирает проверенные нативные потомки вне рабочего вида, проверяет
владение, бюджет и bounds, затем заменяет только записанное импортированное дерево.
Отмена/ошибка сохраняет рабочее дерево; чужие потомки запрещают замену. Пути picker
берутся из загруженных нативных scene handles GLTF. Назначение Model через picker/drop
и Undo/Redo заменяют нативное дерево без сброса камеры.
Путь родительского ассета из Asset Browser может выбрать его единственный объявленный
нативный subasset; несколько сцен требуют явного выбора, а не догадки о Scene0.

## Принятие Transform и история

Общий Rust-drawer выдаёт типизированные метаданные `TransformField`. Редактор связывает их
с исходной областью, узлом, компонентом и точными ревизиями через общий TextField. Конечное
число f32 заменяет одну ось, сохраняя остальные. Вращение вводится в градусах YXZ и хранится
как quaternion; неизменная проекция сохраняет исходный quaternion без ошибки преобразования.

Адаптер документов принимает `PropertySession` в отдельном клоне рабочего набора с полной
проверкой каталога, типов и принятых символических ссылок. Нативное подтверждение должно
завершиться до синхронной замены рабочего набора и кэша. Отказ не меняет исходники/историю;
no-op сохраняет redo. Файлы, снимок открытия и сохранённые ревизии не записываются.

Поддерживаемые скалярные поля используют `LiveTextField`: завершённые нативные изменения
сразу проходят полную проверку исходников до подтверждения и публикации. Некорректный
текст остаётся видимым и не меняет исходник. `EditGroup` объединяет принятые значения
одного поля за сеанс ввода в один шаг Undo; каждое изменение сохраняет отдельную ревизию.
Enter, Escape и потеря фокуса завершают сеанс. Подтверждение Save завершает группу
истории; сохранение остаётся отдельным действием. Обновление собственного принятого
значения сохраняет набранную форму числа, например `1.`, вместо нормализации при вводе.

Черновики переживают обновление, скрытие и перенос панелей. Смена цели, default-режима и
сворачивание откладываются при черновике. Изменение исходной ревизии делает его устаревшим,
не перебазирует автоматически. Enter явно запрашивает принятие; Escape отменяет только
непринятый текст, не уже опубликованные изменения. История исходников отказывает при
незавершённых черновиках, включая скрытые Inspector. Завершённое live-поле направляет
Undo/Redo в историю исходников; некорректный текст сохраняет локальный Undo.
Закрытие главного окна блокируется
до разрешения изменений; явный discard всех исходных изменений восстанавливает снимок
открытия, очищает историю и завершает прежнюю идентичность области исходников.
Действия представления ожидают завершения очереди нативного фокуса/выделения и затем
заново проверяют исходный токен binding и все черновики. Завершение очереди не принимает
текст, не разрешает устаревшее раскрытие и не обходит завершение черновиков коллекций.

Общий `ValueBinding` получает неизменяемое значение через рефлексию, непрозрачный токен хоста,
доступ с причиной и метаданные. Изменяемый World исходников или игры ему не передаётся.
Аргументы World в обработчиках относятся только к представлению. Хост владеет снимком всё время
заимствования; обработчики не должны удерживать `ValueBinding`, строки обнаруженных полей или
заимствованные поля после возврата mount/update либо замены снимка. Удаление цели или завершение
жизни области даёт Target unavailable, а не одноимённую замену. Lock фиксирует идентичность,
но не замораживает значения.

Ссылкам нужен символьный контекст от хоста, не временные номера сущностей. Адаптер исходников
явно сообщает об ограничениях представления `Entity` и `Option<Entity>`: непривязанный порт
после преобразования в нативное представление нельзя показывать как явно заданный в исходнике
`None`. Если существующий API не позволяет восстановить точное намерение, нужно показать
ограничение, а не вводить второй декодер.

## Discovery и детерминированная специализация

Обнаружение использует Bevy `TypeRegistry`, информацию представляемого типа `TypeInfo`,
`PartialReflect` и нативные пути. Строки — временные проекции, не новая сериализованная схема,
реестр типов или универсальная модель значений. Примитивы и строки сохраняют тип и точность;
структуры, кортежи, кортежные структуры, активные варианты перечислений и ограниченные коллекции
раскрывают структуру. При непрозрачном типе или отсутствии возможностей сохраняются тип и причина.
Не допускается нормализация всех чисел через `f64` или промежуточная сериализация значений
в строки. Точные числа форматируются так, чтобы обратное чтение сохраняло значение.

Обычная регистрация в Rust сначала выбирает явно заданный редактор поля по нативному типу
владельца и разобранному пути Bevy. Затем проверяются редактор точного типа, стандартное
структурное представление и представление неподдерживаемого значения. Повторная регистрация
с тем же ключом и приоритетом завершается ошибкой, не заменяя запись. Порядок регистрации,
короткие имена и пространства имён не определяют выбор редактора.

Специализированные редакторы отвечают за монтирование, обновление и удаление, собирают общие
элементы управления и рекурсируют с общим бюджетом. Обновление той же цели меняет сохраняемые
представления; смена представляемого типа или редактора удаляет только затронутое поддерево.
При ошибке монтирования нужно освободить ресурсы, выделенные обработчиками. Ошибка должна
оставаться видимой, а пользователь должен иметь возможность явно открыть стандартное представление.
Стандартный режим обходит специализации всего выбранного поддерева, включая потомков. Оба пути
используют ту же неизменяемую привязку, нативные значения, доступ и диагностику. Специализация
не разрешает запись и не скрывает неподдерживаемое содержимое молча. Встроенная регистрация
не вводит динамическую загрузку кода проекта или стабильный ABI расширений.

Тестовые представления точного типа и вложенного поля проверяют сами элементы управления,
не только ID выбора редактора. Панель передаёт действия раскрытия только для деревьев компонентов
верхнего уровня. Потребитель рекурсивного специализированного представления должен сам передавать
действия внутренних деревьев. Поставляемые плоские образцы не подтверждают общую работу
вложенных раскрытий.

## Ограниченная Luau-композиция

`kedra_inspector_luau` реализует существующий `ValueEditor` через `kedra_script`.
Хост разрешает один конечный запуск при mount; регистрация и Open не дают разрешения
на код проекта. `ctx.fields.add(native_path, label)` собирает общий kit внутри тела
своего владельца; заголовки и раскрытие остаются у базового Inspector. Встроенный скрипт
UiCaption выбирает `text`, `justify`, `wrap`; Rust выдаёт точные String/bool/unit-enum
предложения через `ReflectedField`, без дублирования схемы caption.

Обычный ограниченный обход рефлексии допускает до 32 поддержанных полей. Drawer резервирует
до 32 контролов из общего бюджета; пути, подписи и текст ограничены отдельно. До успешного
завершения всей композиции поля доступны только для чтения. Ошибка запрещает изменение
частичных полей и показывается через существующую диагностику с доступным default view.
Завершение представления отзывает владельца runtime. Доступа к World, исходникам, рендереру
и Save нет. Принятие использует тот же staged-адаптер свойств и историю, что Transform.
Проекция caption обновляет пассивные Text/TextLayout и эпохи UI canvas/пространственного
target, не камеру. Динамическая Luau-компоновка, Lua-проверки отдельных полей, поиск кода
проекта и hot reload не входят в профиль. Save исходников принадлежит хосту. См.
[ADR 0036](https://github.com/kedra-engine/kedra/blob/main/docs/decisions/0036-scoped-luau-inspector-drawers.md)
(English).

## Сохранение, бюджеты и нативный текст

Раскрытие, поиск, стандартный режим и блокировка локальны для представления. Обновление той же
цели сохраняет элементы управления, раскрытие, нативное выделение и прокрутку. Поиск сохраняет
цель и контекст предков и компонентов; фильтрация и сворачивание не меняют выбор документа.
Фокус инструмента не активирует другой документ. Hide/Reopen, Float/Redock и разворачивание
используют сохраняемый инструмент, общий механизм размещения панелей и действий.

Общие пределы перестроения: глубина рефлексии 32, 128 элементов коллекции, 2048 обнаруженных строк,
4096 скалярных значений Unicode на предварительный просмотр. Раскрытие, поиск и рекурсия
специализированных представлений используют общий бюджет; фильтрация не запускает неограниченный
обход. Исчерпание бюджета видно пользователю. Усечённый просмотр не является полным значением
для копирования и не меняет источник. Коллекции показывают первый ограниченный сегмент без
постраничного просмотра. Ключам отображений и элементам множеств не приписывается позиционная
идентичность поля. Непрозрачные для Bevy типы, например `BTreeSet`, требуют своего представления.

Текст только для чтения использует нативное выделение и копирование там, где они поддерживаются.
Он не имитируется редактируемым полем с игнорируемой записью или отдельным текстовым редактором.
Поиск не является сеансом правки исходника. Перед заявлением поддержки копирования и вставки
нужно отдельно проверить системный буфер обмена. `kedra_ui/system-fonts` включает поиск системных
резервных шрифтов Bevy/Parley без поставки проприетарных шрифтов. Наличие CJK-шрифтов зависит
от хоста; предупреждения ICU о сегментации сложных письменностей остаются. Поддержка IME
и универсальное покрытие глифов не сертифицированы.

## Визуальный источник и acceptance

`kedra_inspector::builtin::editors` подключает нативные представления Vec2/Vec3/Vec4, Quat
и Transform в панели исходников и независимом потребителе значений. Они используют общий
`kedra_ui::fields::VectorView`; Transform собирает строки Position / Rotation / Scale
на всю ширину области свойств. Полноширинный drawer получает тело секции, а не управление
заголовком компонента. Заголовки, сворачивание, сохранение контролов и состояние секции
при переключении default/custom принадлежат базе Inspector, как у обычных групп рефлексии.
Корневой компонент использует существующий заголовок без дублирования. Заголовок, компоновка
и поисковые подписи не меняют binding.
Вращение показывается в градусах с порядком YXZ Bevy (Y yaw, X pitch, Z roll).
Нормализуется только копия для отображения в пределах допуска исходника;
исходный quaternion не переписывается. Некорректное вращение даёт диагностику с доступным
default view. Редактирование углов включает только исходный адаптер Transform.
Непрерывность между принятыми жестами и сохранение полных оборотов пока не реализованы.
Эти представления и поля сами по себе не предоставляют права записи исходников.

Канонический [UI-kit provenance](../ui/design-provenance.md#inspector-and-shared-controls):
Flat compact A `131:20213` (320px) и `131:20388` (480px). Блок идентичности — 40px,
заголовки — 24px, элементы управления — 22px с рамками. Связанные строки имеют зазоры 2px,
группы и секции — 4px. Стопка образца Window glyph занимает 394px с неизменными значениями
и единицами; это не универсальная высота схемы. Отступы области прокрутки — 8px по вертикали /
12px по горизонтали, без повторения во вложенных группах. Типографика — 12/16, иконки — 16px;
при ширине тела свойств ниже 296px подписи размещаются над значениями. Нативная компоновка,
семантические токены, точные экспорты и общие ресурсы из исходников остаются определяющими.
Transform/Mesh/Material — примеры, не фиксированные схемы. Представления математических типов
и Transform используют описанную выше проекцию вращения; raw/default сохраняет нативный вид.

Add/Remove доступны только для допустимых исходных целей; не показывайте неподдерживаемые
Reset, Apply/Revert или действия перехода к ресурсу.
До выпуска владелец должен проверить отсутствие выбора, недоступную или заблокированную цель,
пустые компоненты, отсутствующие возможности, ошибки специализированных представлений, лимиты,
отсутствие совпадений, узкий и плавающий вид. Базовый образец эти состояния не проверяет.
Недостающие композиции требуют согласования с владельцем дизайна. Физический ввод, системный
буфер обмена и IME, программы чтения с экрана, точное соответствие пикселей и одобрение
диагностических и узких состояний владельцем ещё не проверены.

## Проверка

API реализации находятся в
[`kedra_inspector`](https://github.com/kedra-engine/kedra/blob/main/crates/kedra_inspector/src/lib.rs),
[`documents/inspection.rs`](https://github.com/kedra-engine/kedra/blob/main/crates/kedra_editor/src/documents/inspection.rs)
и
[`inspector`](https://github.com/kedra-engine/kedra/blob/main/crates/kedra_editor/src/inspector/mod.rs).
Публичные контракты Inspector проверяют нативную точность и структуру, неподдерживаемые типы,
выбор редактора, ошибки специализаций, сохранение состояния, возврат к стандартному представлению
и общие лимиты, изоляцию черновиков коллекций, целые предложения и завершение нативного
ввода элементов. Тесты исходников проверяют итоговые переопределения, происхождение, завершение
жизни ревизии или области и ограничения ссылок. Тесты панели проверяют блокировку и сохранение
элементов управления, права целого Apply и отказ при устаревших/некорректных предложениях
коллекций без области просмотра и записи исходников. Выполните проверки репозитория и:

```sh
cargo xtask test -- features --only inspector,inspector-ui,inspector-collections,inspector-fixture --output target/test/inspector
```

Обоим реальным потребителям нужны нативные кадры и ввод, доступ с клавиатуры, прокрутка,
сохранение состояния, перенос между окнами и неизменность снимков исходников и истории.
`inspector` проверяет пространственные поля, caption и Save; отдельный `inspector-ui`
владеет сгруппированным Layout, Apply/Cancel коллекций, защитой скрытых черновиков и Save коллекций.
`inspector-collections` владеет вводом черновиков плотностей/теней, сохранением ресурсов,
превью/историей, узкими вложенными полями и Save существующего документа.
Сценарий строит проверенную поставку и запускает изолированные процессы редактора. Сценарий
исходников копирует `tests/fixtures/test_project`, читает существующие исходники `Inspector/`,
не генерируя проект или префабы. Независимый потребитель выбирает
`editor://fixtures/inspector.scene.ron` через отладочный `--scene`, используя композицию из
исходников и нативные значения через рефлексию. Luau `inspector.presentation` подаёт ввод для
обновления и стандартного режима; Rust независимо проверяет точность, специализацию, возврат
к стандартному виду и сохранение состояния. Нативные адаптеры сохраняют регистрацию, обновление
только для чтения и раскрытие. Независимость от владельца документов не означает зависимость
runtime от editor.

Сценарии подают ввод в Bevy и синхронизируют чтение кадров GPU; физический системный ввод
требует отдельной проверки. Временные кадры удаляются; явно сохранённые кадры проверки
остаются в приватной нативной сессии, а не в публичных отчётах или эталонных снимках.
Результаты проверок хранятся в `target/`. Независимые эталоны должны
происходить из Figma, не из кадров приложения. Нативная проверка этой ревизии ещё не подтверждена.
