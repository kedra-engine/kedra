# Соглашения о контексте и значениях

Эти соглашения помогают читать сигнатуры общего [runtime](runtime.md) и API хостов.
Установка описана в разделе интеграции хоста.

Идентификаторы типов Luau используют описательные имена без префикса бренда проекта.

## Форма контекста

`ctx` передаётся точкам входа, а не публикуется глобально. Его внешняя таблица неизменяема.
Общие поля: `params`, `log` и, для привязанных программ, `entity`.
Только Behavior получают `events` и `sequences`; другие поля добавляет хост.
При установке привязок хост должен замораживать вложенные таблицы возможностей.

Аннотация контекста описывает форму, а не разрешение. Файл деклараций, импорт модуля,
загрузка сцены или открытие проекта не устанавливают возможности и не запускают программу.
Граница Rust и входные декларации описаны в [интеграции хоста](integration.md).

## Сигнатуры и ошибки

Сигнатуры сохраняют идентификаторы деклараций. `T?` означает необязательное значение или nil;
`Nullable<T>` означает `T | JsonNull`. Сериализованный null — это `json.null`,
а не отсутствующее поле. Важное исключение для отсутствующей цели — `ctx.app.node`:
эта функция возвращает nil. Непрозрачные дескрипторы сущностей, строки ID наблюдений
и сохранённые ID исходников — разные типы.

Привязки вызывают ошибки Luau при неверных аргументах, отказе в доступе или обращении после
отзыва возможностей. Неперехваченная ошибка завершает запуск. Уже применённые нативные
изменения не откатываются. См.
[границы JSON-совместимых значений](runtime.md#json-совместимые-значения)
и [поля структурированных ошибок](runtime.md#логирование-и-структурированные-ошибки).

## Граница изоляции

Кооперативные бюджеты и ограниченные возможности **не** гарантируют безопасную песочницу
для враждебного кода или изоляцию процесса. При необходимости контролируйте нативные операции
из внешнего процесса. [Лимиты runtime](runtime.md#время-жизни-и-лимиты-ресурсов)
различают прерывание по времени обработчика и ошибки выделения памяти;
[руководство по времени жизни](../../manual/programming/lifetime-and-capabilities.md)
объясняет модель доступа.
