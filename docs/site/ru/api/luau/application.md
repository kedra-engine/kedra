# Автоматизация приложения

Используйте конечные debug Sequence для наблюдения UI и выполнения нативных операций.
Для изменения игровых объектов служит [игровой API живых объектов](bevy.md). Общие ожидания
и значения находятся в [справочнике runtime](runtime.md).

Декларации:
[application.d.luau](https://github.com/kedra-engine/kedra/blob/main/crates/kedra_app/types/application.d.luau)
(English).
Реализация вспомогательных функций:
[native.luau](https://github.com/kedra-engine/kedra/blob/main/crates/kedra_app/src/scripting/native.luau)
(English).
Привязки: `crates/kedra_app/src/scripting/{bindings.rs,native.luau}`.
Реестр/время жизни: `crates/kedra_app/src/scripting.rs`.

`ctx.app` устанавливает только доверенный хост вызовом `install_app_api`. Модуль и сервисы
ввода/захвата существуют только при `debug_assertions`. Общее игровое выполнение скриптов
доступно в release, но этот API автоматизации — нет. Debug-сервисы неактивны до настройки;
сетевой сервер требует явного включения удалённого доступа.
См. [настройку подключения](../../manual/automation/connecting.md), не установщик из скрипта.

## Публичные функции

```luau
ctx.app.window: () -> WindowId
ctx.app.node: (id: string) -> Node?
ctx.app.wait_node: (id: string) -> Node
ctx.app.input: (window: WindowId, input: Input) -> Delivered
ctx.app.resize: (window: WindowId, width: number, height: number,
    dpr: number?) -> Delivered
ctx.app.capture: (window: WindowId) -> Frame
ctx.app.click: (id: string) -> Delivered
ctx.app.field: (id: string, value: string) -> ()
```

`window` и `node` — синхронные наблюдения; другие функции могут приостанавливаться
и предназначены для Sequence, а не для обработчиков жизненного цикла или событий Behavior.

| Функция | Результат и ошибки |
| --- | --- |
| `window()` | Возвращает десятичную строку ID основного окна; ошибка, если пригодного основного окна нет |
| `node(id)` | Первый видимый узел с указанной UI-меткой или nil; неполное/неоднозначное наблюдение — ошибка |
| `wait_node(id)` | Ждёт видимый узел до 40000 ms; по истечении срока — ошибка |
| `input(window, input)` | Ждёт подтверждение доставки, но не принятия ввода конкретной функцией приложения |
| `resize(window,w,h,dpr?)` | Ждёт изменения размера нативного окна; размеры в логических пикселях |
| `capture(window)` | Ждёт отрисованный кадр, а не синтетическое изображение узлов |
| `click(id)` | Ждёт видимую цель, отклоняет недоступную, затем отправляет щелчок по элементу |
| `field(id,value)` | Кликает, ждёт фокус, выделяет всё, вводит текст, ждёт точного значения |

Нативное наблюдение выбирает первую сущность с `PrimaryWindow`; уникальность этого маркера
не проверяется. Хост должен обеспечить единственное основное окно.

`field` отдельно ждёт фокус и нужное значение, по 40000 ms на каждое ожидание. Нативные
операции опрашивают подтверждения до 12000 ms и вызывают ошибку при отказе. Общий бюджет
Sequence тоже действует и может закончиться раньше срока вспомогательной функции.
Устаревшие окна, неверный ввод и нативные ошибки не считаются успешной доставкой.
Отмена запрещает будущие действия скрипта, но не откатывает ввод, изменение размера,
захваты или работу, уже поставленную в нативную очередь.

Нативная проверка (`crates/kedra_app/src/input.rs`) требует ширину/высоту окна в
`320..=3840`, необязательный DPR в `1..=4`, все значения конечные. Позиции указателя
должны быть конечными и внутри `[0,width) × [0,height)`. Компоненты wheel должны быть
конечными с модулем не больше `10000`; текстовый ввод — не больше 16 KiB UTF-8.
Щелчок требует ровно одно из `element` или `position`. Конфликт удерживаемого ввода
с окном и занятая очередь могут привести к отказу.

## Идентификаторы, геометрия и узлы

`WindowId`, `EntityId`, `OperationId` — строки. Числовые нативные поля
`id`, `entity`, `parent`, `window` преобразуются в десятичные строки без округления;
не переводите их в числа Luau и не используйте как `EntityHandle`.
`Point` — две логические координаты окна; `Rect` —
`{left,top,right,bottom}` в логических пикселях. Длины массивов проверяются runtime,
а не аннотациями `{number}`.

Поля `Node`:

| Поля | Значение |
| --- | --- |
| `id`, `entity`, `parent`, `window` | Стабильная UI-метка, наблюдаемая сущность, родитель/окно или null |
| `rect`, `visible`, `enabled`, `center_unclipped` | Измеренная геометрия и состояние взаимодействия |
| `focused` | Нативное состояние фокуса |
| `text`, `value` | Отображаемый текст / редактируемое значение или null |
| `font` | `{source, size, weight}` или null; source может быть null, size/weight — строки |
| `background`, `color` | Массивы четырёх байтов sRGBA в `0..=255` с индексацией от единицы или null |

Сериализованные отсутствующие свойства используют `json.null`. `node(id)` вместо этого
возвращает nil, если нет видимого совпадения. Привязка отклоняет неполные списки узлов
и повторяющиеся видимые метки внутри одного окна, но не требует глобальной уникальности
между окнами: выбирается первое видимое совпадение ID. Используйте уникальные метки хоста,
особенно с плавающими окнами. Снимки — независимые копии; правки таблицы не меняют UI
и не доказывают показ кадра.

## Варианты ввода

Вариант `Input` определяется меткой. Используйте точные `kind` и поля:

| `kind` | Дополнительные поля |
| --- | --- |
| `close_window` | Нет |
| `modifier` | `modifier: "shift" \| "control" \| "alt" \| "super"`, `pressed: boolean` |
| `button` | `pressed: boolean` (основная кнопка указателя) |
| `click` | Либо `element: string`, либо `position: Point` |
| `move` | `position: Point` |
| `drag` | `from: Point`, `to: Point` |
| `wheel` | `delta: Point` (двухкомпонентная дельта в пикселях, не позиция внутри окна) |
| `key` | `key: Key` |
| `text` | `text: string` |

Значения `Key`: `enter`, `escape`, `tab`, `shift_tab`, `space`, `backspace`,
`delete`, `left`, `right`, `up`, `down`, `home`, `end`, `f1`, `f2`, `f3`, `f4`, `f5`,
`f6`, `f7`, `f8`, `f12`, `select_all`, `copy`, `paste`, `cut`.
Это не произвольная автоматизация клавиатуры/ОС. Проверка нативного ввода и его подтверждения
определяют реальное поведение; см. [ввод/захваты](../../manual/automation/input-and-captures.md).

`Delivered` — `{delivered: boolean}`. После доставки отдельно проверяйте состояние
функции приложения. `Frame` содержит `path`, физические размеры `width`/`height`,
`uniform`, `window`, `frame`. Путь указывает на файл результатов хоста, не на исходный ресурс
и не возможность доступа скрипта к файловой системе. Неоднородность кадра сама по себе
не доказывает ожидаемое содержимое.

## Программы реестра

Нативный реестр предоставляет `app.input`, `app.resize`, `app.capture`, `app.field`,
`app.click` — конечные Sequence хоста. Другие Sequence хост регистрирует явно.
Одновременно активен только один сценарий приложения. Регистрация не запускает код;
`app.scenario` выбирает имя реестра с собственными аргументами, не удалённый исходник.
Сессии, идемпотентность и отмену описывает
[протокол автоматизации](../../manual/automation/programs-and-diagnostics.md).

Публичный `ctx.app` не содержит `submit` или `receipt`. Эти типы деклараций относятся
к [внутренней инициализации](integration.md), а не к вызовам из скрипта.

## Пример из исходников и тесты

Фрагмент `crates/kedra_editor/src/catalog/prepare.luau` требует уже смонтированный
хостом образец компонента. Он не монтирует стенд и не предоставляет API каталога:

```luau
function run(ctx: AppContext, args)
    local app = ctx.app
    local window = args.window
    app.resize(window, 640, 360, 1)
    wait.until_true("measured specimen", function()
        local target = app.node("specimen.target")
        return target ~= nil and target.rect[3] > target.rect[1] + 1
    end, 12000)
    return {window = window, delivered = true}
end
```

Фрагмент опускает последующую подготовку наведения, нажатия и фокуса.
`crates/kedra_app/src/scripting/tests.rs` проверяет путь через очередь и VM, непрозрачные ID,
отказ неизвестным запросам, переданным исходникам и устаревшим запросам, единственный активный
запуск, идемпотентный допуск, восстановление после ошибок и отмену без отката. Нативный ввод
и отрисованные кадры требуют отдельных нативных тестов.
