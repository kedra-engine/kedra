# Операции с живыми объектами

Эти операции игрового runtime читают или меняют локальную позицию и фон UI привязанного
к запуску объекта. Отладочный ввод и команды тестовых стендов используют отдельные API.
Обработчики и ожидания описаны в [общем runtime](runtime.md).

Декларации:
[bevy.d.luau](https://github.com/kedra-engine/kedra/blob/main/crates/kedra_script_bevy/types/bevy.d.luau)
(English).
Нативная реализация:
[lib.rs](https://github.com/kedra-engine/kedra/blob/main/crates/kedra_script_bevy/src/lib.rs)
(English).
Привязки: `crates/kedra_script_bevy/src/lib.rs`, а именно `install_transform`,
`install_ui` и `ScriptBevyPlugin`. Это отдельно подключаемые возможности, не поля,
автоматически предоставляемые `LuauPlugin`, `KedraAppPlugin` или контекстом редактора.

## Доступность и доступ к цели

Хост явно устанавливает каждую возможность; см. [интеграцию Rust](integration.md).
Нужна привязанная живая цель. Операции синхронно получают доступ к World и разрешают
только собственную цель запуска. Дескриптор другой сущности не даёт права работать с ней.
Чужие, устаревшие и не принадлежащие программе цели отклоняются до изменения.
Отзыв возможностей также запрещает доступ.

`TransformContext` и `UiContext` описывают отдельные формы контекста с
`entity`, `params`, `log` и соответствующей возможностью. Хост может объединить обе;
аннотации ничего не устанавливают. Эти таблицы не дают доступа к компонентам через рефлексию.

## Локальный Transform

```luau
type Position = {x: number, y: number, z: number}
ctx.transform.get_position: (target: EntityHandle) -> Position
ctx.transform.set_position: (target: EntityHandle, position: Position) -> ()
```

`get_position` копирует локальный `Transform.translation` привязанной сущности в новую
таблицу `{x,y,z}`. Изменение таблицы не меняет компонент.

`set_position` требует все три координаты, конечные и представимые конечным `f32`.
Меняет только локальную позицию, сохраняя поворот и масштаб. Отсутствие `Transform`
вызывает `invalid_input`; автоматического добавления компонента нет. Ошибки преобразования,
неконечные/слишком большие координаты отклоняются без изменения позиции.

Нет преобразований мировых координат, `GlobalTransform`, смены родителя, синхронизации
физики, запросов к ECS, произвольного поиска сущностей или правки исходников сцен/prefab.

Следующий пример адаптирован из контракта объектов, Rust-хост которого устанавливает
привязки Transform и привязывает цель с `Transform`:

```luau
function run(ctx: TransformContext, args)
    local position = ctx.transform.get_position(ctx.entity)
    position.x = 99
    ctx.transform.set_position(ctx.entity, {x = 1, y = 2, z = -3})
end
```

Правка локальной таблицы сама не меняет компонент; изменение делает явный вызов функции записи.
Это не автоматически доступная функция игры или редактора.

## Фон retained UI

```luau
ctx.ui.set_background: (target: EntityHandle, rgba: {number}) -> ()
```

`rgba` должна содержать ровно четыре элемента с индексами `1..4`: целые байты sRGB
в `0..=255`, по порядку красный, зелёный, синий, альфа. Лишние элементы, дробные, выходящие
за диапазон или неконечные каналы, неверная форма и отсутствие `BackgroundColor`
отклоняются до изменения. Операция меняет существующий Bevy `BackgroundColor`, не создаёт
виджет, не сохраняет стиль в исходниках и не даёт доступа к другим полям. Неизменяемая таблица
возможности отделена от изменяемого входного значения.

Дочерняя Sequence тестовой игры
`tests/fixtures/test_project/scripts/Native/switch_activate.luau` использует эту возможность:

```luau
function run(ctx: UiContext, args: {color: {number}})
    ctx.ui.set_background(ctx.entity, args.color)
    ctx.log.info("Switch activated")
end
```

Родитель передаёт `{30,100,190,255}` из проверенного хостом параметра; дочерняя Sequence
получает его как args, а не наследует параметры. См. [авторизацию игрового хоста](game-host.md).

## Передача native Activate

`ScriptBevyPlugin` наблюдает нативный `bevy::ui_widgets::Activate`, затем ставит копию
пустого объекта под именем `"activate"` в очередь подписанных Behavior. Хост отдельно
допускает имя события в `Program.events`; установка плагина не подписывает программы.

Используйте [события runtime](runtime.md#подписки-на-подсистемы):

```luau
ctx.events.on(ctx.entity, "activate", function(_payload)
    ctx.sequences.start("./switch_activate", {color = ctx.params.color})
end)
```

Это фрагмент `start` в Behavior переключателя. Обработчики не могут
приостанавливаться; для такой работы запускайте разрешённую конечную дочернюю Sequence.
Доставка идёт на границе Last в runtime, не рекурсивно в нативном наблюдателе. Жизненный цикл
виджета остаётся у Bevy; адаптер не создаёт вторую систему событий UI.

## Ошибки и граница проверки

Успешная запись выполняется синхронно. Последующая ошибка обработчика или отмена её не откатывает.
Для постоянных изменений документов нужны API редактирования исходников, а не эти операции
с живыми компонентами. Обработчики stop не могут использовать отозванные возможности Scope.

`crates/kedra_script_bevy/tests/contracts/owned_objects.rs` проверяет сохранение остальных
полей Transform, собственные копии, отказ чужим/устаревшим целям, неверные цвета,
отсутствующие компоненты и маршрут Activate → Behavior → дочерняя Sequence.
Эти тесты без окна не проверяют физический ввод указателя или отрисованный цвет;
для этого нужны нативные тесты UI.
