# Игровые скрипты

Используйте Behavior для постоянного состояния экземпляра, конечную Sequence для работы
с ожиданиями и обычные модули для общего кода. Rust-хост игры разрешает каждый запуск
и выбирает возможности. Универсального встроенного `ctx.game` нет.

## Выберите операцию

| Мне нужно… | Справочник |
| --- | --- |
| Объявить обработчики, прочитать параметры или подождать | [Общий runtime](runtime.md) |
| Обработать допущенное событие подсистемы | [Подписки](runtime.md#подписки-на-подсистемы) |
| Запустить, проверить или отменить разрешённую дочернюю Sequence | [Дочерние Sequence Behavior](runtime.md#дочерние-sequence-принадлежащие-behavior) |
| Прочитать или изменить локальную позицию привязанного объекта | [Локальный Transform](bevy.md) |
| Изменить фон привязанного UI-объекта | [Фон retained UI](bevy.md#фон-retained-ui) |

Runtime и адаптер живых объектов доступны в release. Для операций с объектами хост должен
установить привязки; общего доступа к World они не дают. Полное объяснение настройки
хоста и переключателя находится в [руководстве программирования](../../manual/programming/luau.md),
а не в примерах debug-автоматизации.

## Реальная авторизация игры: switch

Исходники: `tests/fixtures/test_project/src/{main.rs,scripting.rs}` и
`scripts/Native/{switch_behavior.luau,switch_activate.luau,switch.luau}` в этом проекте.
Проект — тестовый стенд и пример потребителя, не поставляемый игровой SDK.

1. Хост устанавливает `KedraAppPlugin` (с общим Luau) и `ScriptBevyPlugin`.
2. `scripting::bind` находит уже смонтированный элемент `game.switch`; без совпадения ничего
   не делает.
3. Rust создаёт Behavior в `scripts/Native/switch_behavior.luau`, допускает только
   `activate`, задаёт `{color=[30,100,190,255]}`, проверяет ровно одно поле `color`
   с четырьмя беззнаковыми байтами и допускает `scripts/Native/switch_activate.luau`.
4. `attach(world,target,program,Value::Null)` явно разрешает выполнение на этой цели.
5. Родитель получает операции работы с событиями и дочерними Sequence, но не функцию изменения
   UI. Хост вызывает `install_ui` только для дочерней Sequence. У неё своя VM и пустые параметры
   по умолчанию; цвет передаётся в `args`.

[Справочник UI](bevy.md#фон-retained-ui) содержит тело дочерней функции;
[пример runtime](runtime.md) — обработчик родителя.
При повторной активации родитель отменяет предыдущую дочернюю Sequence. Удаление сущности
или отзыв возможностей снимает
доступ; уже применённый цвет остаётся. Этот игровой маршрут не ограничен
`debug_assertions`.

## Где заканчивается игровой API

Операции проекта — только те, которые устанавливает его Rust-инициализатор. Загрузка
сцены, монтаж UI, декларации LSP и модуль с именем `@game` не дают выполнения или доступа
к World. Play внутри редактора и автоматическое обнаружение кода проекта не реализованы.
Требования к нативным привязкам описаны в [интеграции Rust-хоста](integration.md).

Регистрации `scene.remote` и `scene.switch` стенда в `src/main.rs` — debug-only
автоматизация приложения. Удалённый метод `game.state` сообщает идентификатор рендерера,
но **не** является привязкой Luau `ctx.game.state`. Команды его проекции панелей относятся
к [справочнику тестового стенда](testing.md#projection-api-только-этого-стенда), не к этому
игровому API. Тесты без окна и проверки нативного ввода/кадров выполняются отдельно.
