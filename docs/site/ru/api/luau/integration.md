# Интеграция Rust-хоста

Подключайте или расширяйте Luau из Rust, разрешая запуск программ и устанавливая их
возможности. Настройка и примеры приведены в
[руководстве программирования](../../manual/programming/index.md).
[Руководство Rust API](../index.md) ведёт к локальному rustdoc.

## Допуск и установка

`kedra_script::LuauPlugin` предоставляет общий runtime. Rust `start` разрешает запуск;
`attach` также предоставляет живую цель и связывает с ней время жизни. Установка плагинов,
загрузка сцен, открытие проектов, импорт модулей и загрузка деклараций не разрешают
выполнение. Общий World API и произвольное удалённое выполнение исходников не предоставляются.

| Возможность | Нативная установка | Справочник |
| --- | --- | --- |
| Глобальные имена и контекст | `LuauPlugin` и явный допуск | [Runtime](runtime.md) |
| Локальный Transform / фон UI | `install_transform` / `install_ui` | [Живые объекты](bevy.md) |
| Debug-операции приложения | `install_app_api` | [Автоматизация](application.md) |
| Наблюдения редактора | Инициализатор привязок редактора | [Диагностика редактора](editor.md) |
| Поля проекта | Инициализатор и авторизация проекта | Контракт проекта, не универсальный `ctx.game` |

## Пользовательские bindings: обязанности хоста

Инициализатор хоста получает `Lua`, отзываемый `Scope` и таблицу контекста.
Он выбирает имена и семантику API, проверяет аргументы, замораживает вложенные таблицы
возможностей и возвращает независимые снимки ограниченного размера. Захватывайте Scope, а не
заимствования компонентов или сильные ссылки Lua; заново получайте синхронный доступ через
`Scope::with_world`.

Для операций с собственным объектом разрешайте цель через `Scope::resolve_entity`.
Один `EntityHandle::resolve` проверяет World и существование сущности, но не разрешение
на операцию. Аннотации скрипта не заменяют эти проверки. Загрузка новой программы внутри
активного нативного обработчика запрещена; планируйте допуск после обработки вызова.
Дочерним Sequence нужны свои привязки, параметры, исходники и бюджеты; API родителя
они не наследуют.

Нативный поиск сцен/prefab использует полные логические пути с указанием источника, например
`editor://prefabs/button.prefab.ron`, через существующий каталог загруженных источников.
Проверяются принадлежность каталогу и опубликованная ревизия. Это не пути входных модулей
вроде `scripts/Native/switch_behavior.luau`. Нельзя искать ресурсы по жёстко заданным в
нативном коде UUID или превращать сохранённый ID исходника в право доступа к сущности.

## Входные декларации и редактирование

| Файл | Объявленный контракт |
| --- | --- |
| `crates/kedra_script/types/runtime.d.luau` | Глобальные имена, значения, контексты, дочерние Sequence, события |
| `crates/kedra_script_bevy/types/bevy.d.luau` | Операции с принадлежащими программе Transform/UI |
| `crates/kedra_app/types/application.d.luau` | Наблюдение и автоматизация приложения |
| `crates/kedra_editor/types/editor.d.luau` | Наблюдения редактора и именованная диагностика панелей |
| `tests/fixtures/test_project/types/projection.d.luau` | Собственный debug-only API тестового проекта |

Это входные данные типизации, а не сгенерированные привязки runtime или манифест разрешений.
LSP видит файлы на диске; runtime — только явно допущенный снимок исходников.
Аннотируйте внедряемые параметры `ctx` и `self`: LSP не выводит авторизацию Rust.
Выбор профиля и порядок деклараций описывает
[руководство по настройке](https://github.com/kedra-engine/kedra/blob/main/tools/luau/README.md)
(English). Общие подсказки редакторного профиля могут описывать возможности, которых нет
у более узкой программы приложения или игры. Прежде чем полагаться на форму декларации,
проверьте [ограничения реализации](limitations.md).

## Внутренний bootstrap приложения

`NativeApp` объявляет внутренние `submit`, `receipt`, `window`, `node`. Фабрика
захватывает их при установке; публичный `ctx.app` **не** содержит `submit` или `receipt`.
`Receipt` описывает внутренние состояния операции pending/succeeded/failed,
`request_hash` и `detail` с результатом, ошибкой или null;
это не публичный API произвольных методов.
Внутри допускаются только фиксированные `app.input`, `app.resize`, `app.capture`.
Идентификаторы сессии и эффектов задаёт нативный хост, а не скрипт. Ссылки на исходники
и вспомогательные функции находятся в [автоматизации приложения](application.md).

## Владельцы исходников

[Контракт крейта runtime](https://github.com/kedra-engine/kedra/blob/main/crates/kedra_script/README.md)
(English) определяет время жизни и лимиты на стороне Rust. Справочники возможностей ссылаются
на декларации и реализации привязок. Для изменения привязок или их документации используйте
[руководство участника](../../contributing/index.md). Проверяйте работу runtime, нативный ввод
и отрисовку отдельно от чтения исходников.
