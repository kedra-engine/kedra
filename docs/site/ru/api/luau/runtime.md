# Общий runtime API

Общая основа игровых скриптов, диагностики редактора и автоматизации. Дополнительные
операции хоста выбираются через [список задач](index.md). Обозначения контекста и правила
ошибок описаны [один раз для всех областей](conventions.md).

Декларации:
[runtime.d.luau](https://github.com/kedra-engine/kedra/blob/main/crates/kedra_script/types/runtime.d.luau)
(English).
Инициализация runtime:
[vm.rs](https://github.com/kedra-engine/kedra/blob/main/crates/kedra_script/src/vm.rs)
(English).
Привязки: `crates/kedra_script/src/{vm.rs,parameters.rs,diagnostics.rs,jobs.rs,events.rs}`.
Реализации ожиданий/значений: `src/{wait.luau,values.luau,values.rs,vm/sequence.rs}` в этом крейте.
Эта область общая для редакторных и игровых хостов и не ограничена debug-сборкой.

## Точки входа и общий контекст

```luau
start(self, ctx)
update(self, ctx, dt)
fixed_update(self, ctx, dt)
stop(self, ctx, reason)
run(ctx, args)
```

Behavior объявляет хотя бы одну из первых четырёх функций на верхнем уровне. У него свой
изменяемый `self`; обработчики жизненного цикла и событий не могут приостанавливаться.
`start` вызывается один раз перед первым обработчиком update/fixed.
`dt` — игровая дельта Bevy в секундах. При паузе виртуального времени update продолжает
вызываться с нулевой дельтой; обработчики fixed следуют реальным FixedUpdate.
Порядок между экземплярами не гарантирован.

Sequence объявляет `run`, может приостанавливаться ожиданиями и возвращает одно независимое
JSON-совместимое значение. Отсутствие результата/nil становится JSON null. У неё нет обработчиков
Behavior или `self`. Вычисление входного файла не может приостанавливаться или выполнять
операции Scope, в том числе через `require`.

Поля `RuntimeContext`:

| Поле | Значение |
| --- | --- |
| `entity: EntityHandle?` | Непрозрачная привязанная живая цель; отсутствует без привязки |
| `params: {[string]: JsonValue}` | Проверенный хостом снимок параметров, неизменяемый на всех уровнях |
| `log: Log` | Независимая структурированная телеметрия, в том числе при загрузке/остановке |
| `profiler: Profiler` | Ограниченные CPU-метки, логические операции и counters, без права запуска записи |

`ctx.params` отделён от `args` Sequence и `self` Behavior. По умолчанию валидатор хоста
принимает только пустой объект. Параметры проверяются до выделения ресурсов или замены;
это не автоматическая схема свойств сцены и не API сериализации.

В `BehaviorContext` поле `entity` тоже необязательно. Для операций с привязанной целью
нужно сузить его тип либо использовать контекст хоста, гарантирующий привязку; см.
[аннотации привязки](limitations.md#аннотация-привязки-behavior).

## Инструментирование профилирования

`ctx.profiler.scope(name, callback, ...)` выполняет синхронный CPU scope, возвращает
результаты callback и сохраняет ошибки. Yield запрещён.
`ctx.profiler.operation(name, callback, ...)` записывает логическую длительность,
включая ожидания Sequence; это не CPU execution time. Оба используют API движка,
не прямые вызовы tracing/Perfetto. Отзыв владельца закрывает незавершённые операции.

`ctx.profiler.counter(name, value, unit?)` записывает абсолютное конечное число.
Единицы: `count` (по умолчанию), `bytes`, `ms`, `percent`. Единицу имени нельзя менять
внутри run. Точность чисел — Luau, не произвольные native integers. Имена квалифицированы
программой: 1..=96 UTF-8 байтов без управляющих символов. На run допускается 64 определения
CPU-меток, 64 counters, 64 имени операций и 32 одновременные операции. Некорректные запросы
и переполнение не меняют существующие определения или чужие runs.

API доступен обычным контекстам, но не пишет события без явно включённого native recorder.
Он не даёт Start/Stop, доступ к сети, файловой системе или World.
См. [запись и локальный анализ в Perfetto](../../manual/testing/performance.md).

## Часы и ожидания

```luau
runtime.elapsed_ms: () -> number
wait.updates: (count: number) -> ()
wait.fixed: (count: number) -> ()
wait.game_seconds: (seconds: number) -> ()
wait.real_seconds: (seconds: number) -> ()
wait.until_true: (label: string, predicate: () -> boolean, timeout_ms: number) -> ()
```

- `elapsed_ms` — монотонные миллисекунды с допуска запуска, включая приостановки.
- `updates` / `fixed` требуют целые значения в `1..=1000000` и считают будущие выполнения
  расписаний, не отрисованные кадры. Fixed-ожидание не переносит продолжение в FixedUpdate.
- Секунды должны быть конечными, положительными и не больше `1000000`. Игровое ожидание
  использует установленные виртуальные часы Bevy; реальное всё равно требует обновлений.
- `until_true` требует строковую метку, функцию и срок ожидания в `(0, 600000]` миллисекунд.
  Проверяет сразу, затем раз за будущее обновление; при успехе ничего не возвращает.
  Реализация принимает любое истинное в условиях Luau значение; декларация требует boolean.
  Истечение срока вызывает ошибку. Deadline проверяется до и после предиката; поздний успех
  отклоняется, просроченное ожидание не вызывает предикат снова. Это не прерывает нативные
  вызовы или вложенные ожидания. Нельзя удерживать заимствования через приостановку.

Sequence возобновляются в Last на `ScriptSystems::Run`. Инициализация модуля, требуемого
живой Sequence, может приостановиться по её правилам ожиданий/бюджета/отмены;
обработчики Behavior и вычисление входного файла не могут приостанавливаться.

## JSON-совместимые значения

```luau
json.null: JsonNull
type Nullable<T> = T | JsonNull
type JsonValue = boolean | number | string | JsonNull
    | {JsonValue} | {[string]: JsonValue}
```

Аргументы, результаты, параметры, данные событий и структурированные поля передаются
независимыми копиями: не более 64 KiB сериализованного JSON, глубина 32, целые
в `-9007199254740991..=9007199254740991`. Циклические таблицы, неподдерживаемые значения
и неконечные числа отклоняются. Пустые таблицы по умолчанию декодируются как объекты.
Нативные идентификаторы полной разрядности должны быть непрозрачными строками или дескрипторами,
не числами Luau. Изменение таблицы наблюдения не меняет нативное состояние.

## Логирование и структурированные ошибки

```luau
ctx.log.info: (message: string, fields: JsonValue?) -> ()
ctx.log.warn: (message: string, fields: JsonValue?) -> ()
ctx.log.error: (message: string, fields: JsonValue?) -> ()
```

Логи записывают program/path/phase и source/line, когда они доступны. Сообщения и доступные
стеки вызовов ограничены 8 KiB. Диагностический приёмник хоста хранит последние 256 записей
по порядку и считает перезаписанные. Логирование не даёт доступа к World.

`ScriptError` содержит `kind`, `message`, `path`, `phase`; последние два имеют тип
`Nullable<string>`. Коды: `invalid_input`, `capacity`, `load`, `runtime`, `budget`,
`permission`, `stale`. Результаты дочерних Sequence содержат эти поля; выброшенная ошибка не обязана
быть таблицей.

## Дочерние Sequence, принадлежащие Behavior

```luau
ctx.sequences.start: (path: string, args: JsonValue?) -> SequenceHandle
ctx.sequences.status: (handle: SequenceHandle) -> SequenceOutcome
ctx.sequences.cancel: (handle: SequenceHandle) -> ()
```

`start` выбирает только конечную программу из Rust `Program.sequences`, используя стандартное
разрешение относительных путей и псевдонимов модулей без вычисления её входного файла.
Без args передаётся
null. Допуск происходит в Last после событий, перед возобновлением Sequence. Ошибки
доступа/пути/ёмкости могут быть синхронными; отложенный отказ допуска отражается в результате.

`status` возвращает новый снимок: `{state="queued"}`, `{state="running"}`,
`{state="completed", result=...}`, `{state="cancelled"}` или
`{state="failed", error=...}`. `cancel` идемпотентен, пока область владельца жива;
чужие дескрипторы и отозванные владельцы вызывают ошибку. Отмена не откатывает прежние эффекты.

У каждой дочерней Sequence свои VM, параметры, модули, привязки и бюджет. Она наследует
цель/время жизни, **не** возможности родителя. Sequence не создают дочерних программ.
Отмена, замена, ошибка или удаление сущности родителя отзывает ожидающие/активные дочерние
Sequence. Завершённые Sequence освобождают нативных владельцев; дескрипторы сохраняют результаты.
Behavior удерживает не более 32 дескрипторов, включая завершённые с живыми ссылками;
завершённые без ссылок освобождаются при последующих запусках.
Общий лимит Sequence действует отдельно.

## Подписки на подсистемы

```luau
ctx.events.on: (target: EntityHandle, name: string,
    callback: (payload: JsonValue) -> ()) -> Connection
connection:disconnect()
```

Этот API получают только Behavior. Цель должна быть собственной привязанной живой сущностью
запуска, имя — входить в `Program.events`. Хост ставит копии данных в очередь через
Rust `events::notify`; скрипты не публикуют в глобальную шину. Подключаемый адаптер Bevy передаёт
`activate`. Обработчики выполняются без приостановки, с доступом и бюджетом своего Behavior.

Отключение удаляет подписку и ожидающие доставки; повтор безопасен в живой области.
Удаление одной ссылки не отключает подписку. Отзыв очищает все подписки; уведомления до
подписки теряются. Лимиты на владельца: 32 подписки, 128 доставок / 64 KiB в очереди,
16 доставок за обновление приложения. Переполнение завершает владельца ошибкой до следующего
пакета. Порядок локален владельцу; повторно порождённые доставки ждут следующего обновления.
Порядок между владельцами не гарантирован.

## Время жизни и лимиты ресурсов

Для начатого Behavior runtime пытается один раз вызвать stop с `StopReason`:
`cancelled`, `retired`, `replaced`, `despawned`, `failed`, `budget_exhausted`. Возможности Scope
в stop уже отозваны; телеметрия может оставаться доступной. Не начатые Behavior stop
не получают. После остановки расписаний вызов обработчиков при завершении не гарантирован.

Лимиты по умолчанию: 16 MiB кучи Lua, 100 ms на загрузку/вызов; у Sequence дополнительно
45 секунд суммарно и 100000 возобновлений. Ёмкость хоста по умолчанию: 32 Sequence /
256 Behavior. Допуск требует конечных лимитов Sequence, всего не более 600 секунд.
Нативное выделение памяти, компиляция и обработчики хоста не всегда допускают прерывание
или учитываются в лимите кучи Lua. Кооперативное прерывание по времени обработчика завершает
запуск даже через `pcall`: превратить его в успешное продолжение нельзя. Неперехваченные ошибки
лимита памяти завершают запуск с `budget`; завершение после любой перехваченной ошибки
выделения памяти не гарантируется. Суммарное время, число возобновлений и очередь событий
проверяются отдельно на нативной стороне. Прежние эффекты остаются. Эти меры не изолируют
враждебный код; сохраняйте контроль из внешнего процесса.

Отмена из Rust немедленно отзывает возможности; retirement также удаляет владельца.
Удаление сущности родителя отзывает доступ до очистки на границе обработки скриптов.
Проверенная замена создаёт новые глобальные имена, состояние и кеш модулей,
а не переносит состояние.
См. [руководство по времени жизни](../../manual/programming/lifetime-and-capabilities.md).

## Модули и реальный пример

Стандартные `require("./helpers")`, `require("../shared/helpers")` и настроенные псевдонимы
работают только с `Program.sources`: не более 256 файлов / 8 MiB, включая входной файл
и конфигурацию, 64 KiB на файл. Канонические относительные пути исходников отличаются от
путей ресурсов с указанием источника вроде `editor://prefabs/button.prefab.ron`.
Поиска на диске и загрузки внешнего `.luaurc` нет. У каждой VM свой кеш модулей;
импорт не даёт разрешения на выполнение.

Фрагмент Behavior взят из `scripts/Native/switch_behavior.luau` тестовой игры.
Её хост допускает `activate` и путь дочерней Sequence; это не автоматический поиск кода проекта.

```luau
type Context = BehaviorContext & {entity: EntityHandle, params: {color: {number}}}
type State = {activation: SequenceHandle?}

function start(self: State, ctx: Context)
    ctx.events.on(ctx.entity, "activate", function(_payload)
        if self.activation then
            ctx.sequences.cancel(self.activation)
        end
        self.activation = ctx.sequences.start("./switch_activate", {color = ctx.params.color})
    end)
end
```

`Context` сужает `entity`, потому что этот хост использует `attach`; аннотация сама ничего
не привязывает. Rust-авторизация приведена в [полном примере](../../manual/programming/luau.md).
Контрактные тесты этих операций находятся
в `crates/kedra_script/tests/contracts/{behaviors,parameters,children,events,modules,budgets,
lifecycle,diagnostics}.rs`.
