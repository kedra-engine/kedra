# Жизненный цикл и полномочия

Точные вызовы жизненного цикла и возможностей описаны в
[Luau runtime](../../api/luau/runtime.md) и [привязках Bevy](../../api/luau/bevy.md).

**Разрешённая возможность (capability)** — конкретная операция, которую приложение-хост
решило открыть скрипту, а не право искать любые компоненты. Далее такие права называются
**полномочиями**. Приложение-хост определяет операцию; `Scope` runtime проверяет,
может ли этот запуск ещё её выполнять. Не смешивайте эти две ответственности.

## Привязка узкой операции

Чтобы предоставить скрипту счёт, возвращайте значение, а не заимствование ресурса.
Этот **фрагмент** примера интеграции runtime предполагает нативный ресурс `Score(u32)` и импорты
`kedra_script::{Scope, lua::{self, Lua}}`. `ctx.game` — пример API приложения-хоста,
а не встроенная служба.

```rust
fn bindings(lua: &Lua, scope: Scope, ctx: &lua::Table) -> lua::Result<()> {
    let game = lua.create_table()?;
    game.set("score", lua.create_function(move |_, ()| {
        scope.with_world(|world| Ok(world.resource::<Score>().0))
    })?)?;
    game.set_readonly(true);
    ctx.set("game", game)
}
```

Захватывайте `Scope`, а не заимствование ECS или сильный дескриптор Lua. `with_world`
заново получает исключительный доступ только во время активного вызова этого запуска
и возвращает данные без заимствований; заимствование нельзя удерживать при приостановке.
Он отклоняет чужой контекст выполнения, неактивного/удалённого владельца и вызовы при загрузке.
Замораживайте вложенные таблицы API сами: runtime замораживает внешний контекст после
инициализации. Ограничивайте нативную работу отдельно: кооперативный бюджет Lua
не прерывает зависший обратный вызов Rust.

Прикреплённые программы получают непрозрачный `ctx.entity`, не число и не общий API сущности.
Вызывайте `Scope::resolve_entity` внутри `with_world`, чтобы ограничить адаптер целью запуска.
Один `EntityHandle::resolve` проверяет World и существование, но не предметные полномочия.
Доверенный Rust получает доступ к World; скриптам общая привязка World не предоставляется.

Необязательный адаптер Transform читает/пишет только локальную позицию, сохраняя поворот
и масштаб. Нужны существующий `Transform` и конечные координаты f32; нет смены родителя,
синхронизации физики или преобразования мировых координат. UI-адаптер меняет существующий
`BackgroundColor` по ровно четырём целым байтам sRGB, но не создаёт виджеты.
Чужая/устаревшая цель, неверные значения и отсутствующий компонент отклоняются до изменения.
Тесты также проверяют неизменность и чужой цели, и цели вызывающего скрипта.

## Параметры, события и владение дочерними программами

`Program::params` становится глубоко неизменяемым `ctx.params`. Функция приложения-хоста
`validate_params` проверяет обычные JSON/предметные типы до выделения VM или замены.
По умолчанию принимается только пустой объект. Параметры отделены от изменяемого `self`
Behavior и `args` Sequence; автоматической сериализации сцены или второй схемы свойств нет.

Behavior подписывается только на имена из `Program::events` и на свою прикреплённую цель.
Нативные подсистемы публикуют ограниченный собственный JSON через `events::notify`;
скрипты не получают издатель или глобальную шину. Доставка отложена и не входит в VM
рекурсивно. Обработчики не могут ждать и используют полномочия и бюджет Behavior.
Уведомления до подписки теряются. `connection:disconnect()` идемпотентен и очищает также
ожидающие доставки; потеря ссылки на соединение не отключает его. Отзыв полномочий
очищает все подписки.

Только Behavior запускают элементы списка `sequences`, заданного приложением-хостом.
Допуск дочерней программы происходит в `Last`, после доставки событий и перед
возобновлением Sequence. У каждой свои привязки, параметры, снимок и бюджеты; наследуются
лишь цель и время жизни владельца. Дочерние программы не могут запускать следующие.
Наличие модуля не разрешает запуск дочерней программы.

`ctx.sequences.status(handle)` возвращает сведения о состоянии без заимствований:
`queued`, `running`, `completed` с `result`, `cancelled` или `failed` со структурированной
ошибкой `error`. Здесь же видны отложенные ошибки загрузки или превышения числа программ.
Отмена дочерней программы идемпотентна и отзывает активные эффекты. Дескрипторы завершённых
дочерних программ сохраняют результат и после освобождения нативных владельцев.

На Behavior допускается 32 сохраняемых дескриптора дочерних программ, включая терминальные,
на которые ещё ссылается Luau. Недостижимые терминальные дескрипторы освобождаются при
следующих запусках. На владельца разрешены 32 подписки, 128 ожидающих доставок / 64 KiB
и 16 доставок за обновление приложения. Переполнение завершает владельца ошибкой до
следующей порции, а не молча теряет отдельное событие. Порядок очереди сохраняется внутри
владельца; порядок между владельцами не обещан. Повторно порождённые уведомления ждут
следующего обновления.

## Отзыв полномочий — не откат

`cancel` немедленно отзывает эффекты Scope и освобождает дескрипторы VM, сохраняя
терминальные сведения. `retire` удаляет также владельца. Удаление родителя немедленно
отзывает доступ; очистка VM и stop завершаются на границе скриптового вызова.
Запрошенная внутри нативного обратного вызова очистка ждёт его возврата.
Отмена, ошибка, замена и удаление родителя также отзывают ожидающие/активные дочерние
программы. Исходные ассеты и другие экземпляры не являются такими дочерними объектами.

Запущенный Behavior получает одну попытку `stop` с причиной `cancelled`, `retired`,
`replaced`, `despawned`, `failed` или `budget_exhausted`. Обычные эффекты уже отозваны;
телеметрия без эффектов может остаться. Приостановка, ошибка или тайм-аут stop не блокируют
очистку. Не начавшийся Behavior не получает stop. Остановка приложения не обещает хуки
после прекращения расписаний, хотя нативные владельцы всё равно освобождаются.

`replace` проверяет новую VM до удаления старого поколения. Ошибка сохраняет старый запуск,
в том числе при полной ёмкости; успех возвращает новый дескриптор со свежим состоянием VM.
Стеки не переносятся, применённые эффекты не откатываются. Ошибки runtime терминальны,
повторов нет. Если скрипт изменил значение, а затем завершился ошибкой, изменение остаётся.

## Часы и бюджеты выполнения

Обновления Behavior работают в `Update`, фиксированные вызовы — на каждом фактическом
`FixedUpdate`. При паузе виртуального времени update продолжает работать с нулевой игровой
дельтой; автоматические фиксированные шаги следуют политике часов Bevy.
Автоматического enable/disable или обратного вызова готовности сцены нет.
`wait.updates`/`wait.fixed` считают будущие выполнения расписания, не кадры GPU.
`wait.game_seconds` учитывает паузу виртуального времени; `wait.real_seconds` использует
монотонное время, но для возобновления нужны обновления приложения. `wait.until_true`
опрашивает сразу, затем при обновлениях, с конечным положительным сроком в миллисекундах.
Срок проверяется между вызовами предиката, а не прерывает вложенное ожидание;
не удерживайте заимствование через приостановку.

По умолчанию VM получает 16 MiB кучи Lua и 100 ms на загрузку/вызов. Sequence дополнительно
ограничена 45 секундами всего и 100,000 возобновлений; конечные пределы обязательны,
общий срок — максимум 600 секунд. Behavior по умолчанию не имеет общего срока/предела
возобновлений, но каждый обратный вызов ограничен. Начальный start и первый update делят
один бюджет вызова. `Capacity` приложения-хоста по умолчанию допускает 32 Sequence /
256 Behavior; это не гарантия общего времени кадра. Исчерпание бюджета прерываний
окончательно завершает запуск с ошибкой, даже внутри `pcall`.

Аргументы/результаты — собственные JSON-совместимые данные: до 64 KiB, глубина 32,
целые в точном диапазоне double. Для явного null используйте `json.null`, для полноразрядных
ID наблюдения — непрозрачные строки. Нативные выделения/компиляция не полностью покрыты
пределом кучи Lua. Это не изоляция враждебного кода или процесса; для зависаний нужен
внешний watchdog.

## Найдите границу, на которой произошёл сбой

Ошибки допуска/управления и `Status::Failed` содержат `ScriptError`: `kind`, ограниченное
сообщение, доступную трассировку, программу/путь/фазу, когда они известны. Коды:
`invalid_input`, `capacity`, `load`, `runtime`, `budget`, `permission`, `stale`;
дочерние ошибки используют те же коды. При ошибке допуска проверьте параметры/путь/бюджеты,
при load — допущенные снимки, при отсутствующем API — установленные привязки,
при permission/stale — владение и отзыв. Не выбирайте восстановление по тексту сообщения.

`ctx.log.info/warn/error(message, fields?)` записывает ограниченный JSON и исходник/строку,
когда они доступны. `Diagnostics::drain` приложения-хоста забирает последние 256 записей
по порядку; `dropped()` считает перезаписанные. Сообщения/трассировки — до 8 KiB.
Логи и ошибки также выводятся в stderr. Логирование остаётся без эффектов при load/stop
и не требует консоли редактора.

Прочитайте `status` до `retire`, если нужен итог выполнения. Успешный результат
подтверждает лишь контракт программы, а не физический ввод или отрисованное изображение.
См. [примеры Luau](luau.md) и [разделение исходников и живого состояния](rust-components.md).
