# Программирование

Точные интерфейсы описаны в [руководстве Rust API](../../api/index.md) и
[обзоре Luau API](../../api/luau/index.md). Для изменения самой Kedra начните с
[руководства участника](../../contributing/index.md).

Kedra расширяет обычное приложение Bevy. Компоненты Rust хранят данные, системы реализуют
игровую логику, а плагины подключают выбранные приложением службы. Luau — необязательный
интерпретируемый слой с явными полномочиями под управлением приложения-хоста, а не замена ECS.

Выбирайте механизм интеграции по задаче:

| Задача | Текущий механизм Kedra |
| --- | --- |
| Данные компонентов и игровая логика во время выполнения | Обычные компоненты, ресурсы, системы и плагины Bevy |
| Данные, сохранённые в сцене или префабе | Явные политики отражаемых компонентов и компиляция исходников |
| Состояние скрипта и обратные вызовы отдельного объекта | Behavior Luau, явно разрешённое и прикреплённое кодом Rust |
| Конечная операция, похожая на корутину | Sequence Luau с собственными аргументами, результатом и сроками выполнения |

Каждый механизм подключается явно. Чтобы хранить компонент Rust в исходном документе,
зарегистрируйте его схему; чтобы выполнить скрипт, разрешите его в приложении-хосте.
Файл деклараций Luau помогает редактору понимать имена, но не предоставляет полномочий.

- [Программы и модули Luau](luau.md): выбор Behavior или Sequence, разрешение выполнения

- [Жизненный цикл и полномочия](lifetime-and-capabilities.md): узкие привязки API,

Если исходные документы и экземпляры вам пока незнакомы, начните со

[API изменения исходников и протокол Save](../scenes/source-editing.md), а не запись
в игровой World.

## Чем управляет приложение-хост на Rust

**Приложение-хост** — нативное приложение Rust, которое создаёт Bevy `App`. Оно выбирает:

1. Нативные плагины и порядок их работы, включая ассеты и адаптеры представления.
2. Проверенные источники ассетов и явный каталог источников сцен и префабов.
3. Ключи компонентов авторинга, точные версии схем и валидаторы без побочных эффектов.
4. Стартовую сцену и её нативную функцию монтирования/гидратации.
5. Исходники скриптов, привязки API, параметры, допустимые события и дочерние программы,
   ограничения выполнения.
6. Момент разрешения выполнения, отмены и удаления владельцев.

Устанавливайте `AssetPlugin` Bevy до `kedra_script::LuauPlugin`. Приложение с
`kedra_app::KedraAppPlugin` получает Luau и общие службы ассетов через этот плагин;
не устанавливайте второй backend Luau. Сам `KedraAppPlugin` не создаёт окно или рендерер.
Скриптовые адаптеры нативного UI и Transform подключаются отдельно.

Этот **фрагмент инициализации** из безоконного контрактного теста адаптера использует
Bevy напрямую, без `KedraAppPlugin`. Он устанавливает службы, но не разрешает ни одну программу:

```rust
let mut app = App::new();
app.add_plugins((
    MinimalPlugins,
    AssetPlugin::default(),
    kedra_script::LuauPlugin,
    kedra_script_bevy::ScriptBevyPlugin,
));
```

`App`, `MinimalPlugins` и `AssetPlugin` здесь импортированы через `bevy::prelude::*`.

Обычный исполняемый файл `kedra-test-project` в репозитории показывает такую сборку.
Он проверяет две поставки ресурсов, регистрирует их источники, подключает нативные плагины,
регистрирует схемы, устанавливает `PrefabPlugin` и настраивает явную стартовую сцену.
Его функция монтирования разрешает скрипт переключателя только после получения целевого
объекта из UI-проекции. Используйте его как тестовый пример интеграции,
а не как полный игровой SDK или шаблон игры.

## Текущие границы выполнения

Открытие проекта, загрузка сцены и импорт модуля не разрешают выполнение.
Автоматического поиска или компиляции Rust-кода проекта, загрузки расширений проекта,
Play в редакторе и автоматической загрузки программ Luau проекта нет. Потребители
встроенных скриптов явно передают исходник, например через `include_str!`, затем вызывают
`start` или `attach`. Ни регистрация источника, ни отладочная подмена сцены не выбирают
новые нативные плагины.

Общая конфигурация запуска сохраняет обычную стартовую сцену приложения-хоста в release.
Переопределение `--scene` и удалённая диагностика доступны только при debug assertions.
Игровой Luau может оставаться в release; `kedra_app::scripting` и его адаптер управления
приложением существуют только в debug. Адаптер запускает зарегистрированные конечные
программы, а не вычисляет полученный удалённо исходный код.

Полномочия — это отобранные API вроде «изменить локальную позицию этого принадлежащего
скрипту объекта», а не общий `World`, доступный скрипту. Доверенный нативный Rust по-прежнему
имеет прямой доступ к Bevy; области доступа и бюджеты скриптов не создают вокруг него
песочницу безопасности.

Безоконные тесты VM и расписаний подтверждают контракты runtime, но не реальный ввод
в виджеты, готовность рендерера или показ кадров. Завершённая Sequence не
доказывает, что физический щелчок принят или кадр GPU уже появился.
