# Упаковка и лицензии

Команда `package` нужна, когда помимо сборки для запуска требуются распространяемые
артефакты. Она всегда собирает release, проверяет реальное содержимое пакетов и только
затем записывает опись успешной поставки. Создание файлов не равно публикации или
подтверждению готовности релиза.

## Нативные инструменты

Начните с [подготовки к сборке](build-and-run.md) и [метаданных](configuration.md)
приложения. Нативный хост должен совпадать с выбранной целью:

| Хост/цель | Настроенные выходы | Дополнительно для упаковки |
| --- | --- | --- |
| Windows x64 MSVC | Установщик NSIS `.exe` и переносимый `.zip` | Поддерживаемый 7-Zip, `7z` в PATH; инструменты NSIS upstream |
| Linux x64 GNU | `.AppImage` и переносимый `.tar.gz` | Ubuntu 24.04 для проверки происхождения библиотек, `pax-utils`/`lddtree`, `dpkg-query`, `tar`, файлы copyright/common-license дистрибутива |
| macOS ARM64 или Intel | `.dmg` с `.app` | Системные `hdiutil` и `ditto`, а также `codesign`/`plutil` |

Общий инструмент принимает обе архитектуры macOS на соответствующих нативных хостах.
Для распространения редактора выбрана только Apple Silicon наряду с Windows/Linux x64;
это не подтверждает доступность релиза редактора для Intel. `--target` — не опция
кросс-компиляции.

В Linux пакеты дистрибутива, из которых взяты библиотеки, определяются с помощью
`/usr/bin/python3 /usr/bin/lddtree` из дистрибутива, а не Python виртуального окружения.
Для другого дистрибутива нужен отдельный адаптер проверки происхождения библиотек;
подбирать предположительно подходящие файлы лицензий нельзя. Docker на нативном x86-64 Linux нужен
для отдельного теста перелинковки получателем, но не для обычной упаковки.

Поддерживаемый packager может скачивать инструменты в кеш ОС и выполнять их. Некоторые
скачивания upstream не закреплены криптографически: это не герметичная сборка.
Нативный worker работает из каталога манифеста приложения; unattended-режим `CI=true`
задаётся только дочернему процессу. Относительные нативные настройки принадлежат приложению.

## Настройка сборщика лицензий

При наличии `license-config` сборке и упаковке нужен `cargo-about 0.9.2`. Отсутствие
сборщика — ошибка, а не повод для автоматической установки. Явная команда настройки:

```sh
cargo kedra tools install-about --output /OUTSIDE_CARGO_WORKSPACE/about-tool
```

Замените заполнитель новым пользовательским каталогом инструментов вне **любого** workspace
Cargo; не используйте поддерево вывода примеров сборки. Нужны сеть, Cargo и cargo-deny.
Настройка проверяет checksum архива исходников upstream, разрешает отдельный обновлённый
lockfile инструмента, проверяет advisories до компиляции и устанавливает этот граф
с `--locked`. Самостоятельно добавьте полученный каталог `bin` в PATH.

Эта явная команда скачивает и компилирует инструмент; это не проверка наличия без изменений.
Существующие каталоги установки сохраняются. Сохраните разрешённый lockfile как свидетельство:
проверенный граф может меняться между датами установки. Не понижайте версии зависимостей
приложения ради совместимости с замороженным upstream-графом сборщика лицензий.

## Создание пакетов

После настройки, из корня репозитория на поддерживаемом нативном хосте:

```sh
cargo kedra package --package kedra --output target/documentation/examples/build-and-distribution/editor-package-01
```

Вывод должен быть новым; для package `--output` обязателен. Цель определяется по хосту;
можно также явно передать совпадающий `--target`. У `package` нет флага `--release`,
так как release-компиляция обязательна. Упакованное приложение не запускается.

Инструмент готовит сборку для запуска, затем создаёт и проверяет нативные пакеты.
NSIS извлекается через 7-Zip: при обычной упаковке установщик никогда не выполняется.
DMG проверяется и монтируется только для чтения; проверяются идентичность/подпись копии app.
Переносимые архивы распаковываются и сверяются с промежуточной сборкой. Реальный AppImage
дополнительно проходит проверки происхождения runtime и включённых библиотек.

Имена итоговых артефактов имеют вид `<package>-<version>-<target>` с расширением формата.
Вывод также включает:

- `build-result.json`: проверенный результат сборки приложения для запуска.
- `artifact-inventory.json`: схема `1`, приложение/версия/цель, ревизия исходников,
  имена артефактов, форматы, размеры в байтах и хеши SHA-256.
- `SHA256SUMS`: контрольные суммы записанных артефактов поставки.

Промежуточные `application/`, `packages/` и файлы нативной конфигурации/отчётов могут
сохраняться для диагностики. Одно их наличие не доказывает успех. Используйте только
проверенные результаты успешной команды и сохраняйте все ресурсы/уведомления в артефактах.

## Сохраняйте лицензии и исходники

Kedra распространяется под MIT OR Apache-2.0; зависимости и ассеты сохраняют собственные
условия. Поле license в Cargo не даёт прав на посторонние сторонние материалы. Отдельно
изучите шрифты, графику, изменённые зависимости и собственные материалы приложения.

Настроенные уведомления копируются в `licenses/`. При наличии `license-config` cargo-about
собирает сведения о лицензиях зависимостей для цели и сохраняет полные тексты copyright
и лицензий в `dependency-notices.html`. Для зависимостей crates.io под MPL-2.0 добавляются
исходные `.crate`-архивы в `licenses/covered-sources/`, проверенные по `Cargo.lock`.
Неизвестное происхождение покрываемых лицензией исходников вне реестра вызывает ошибку;
архив реестра не заменяет изменённые Git/локальные файлы. Сохраняйте доступ получателей
к исходникам и их права по MPL.

В Linux дополнительно включаются:

- `licenses/native-libraries/`: сведения о пакетах-владельцах библиотек и их версиях,
  полные файлы copyright и указанные в них тексты common-license. Идентичность включённого
  ELF-файла должна однозначно соответствовать пакету-владельцу. Допускаются только
  проверенные варианты уведомлений Brotli, bzip2, libffi, libpng и Wayland; изменение
  уведомления или добавление семейства библиотек требует проверки.
- `licenses/appimage-runtime/`: закреплённые исходные материалы runtime/libfuse/squashfuse,
  upstream-патч libfuse, полные уведомления, статические объекты/заголовки и инструкции
  пересборки получателем. Префикс выбранного runtime и AppRun сверяются с проверенными входами.

Runtime AppImage включает libfuse под LGPL и код запуска/runtime GCC с GCC Runtime Library
Exception. Сохраняйте полные условия, материалы пересборки/перелинковки и право получателя
изменять/отлаживать LGPL-компоненты. Объекты запуска компилятора берутся из обычного
toolchain получателя; архивы библиотек не предоставляют их все. Отдельная проверка
перелинковки сохраняет реальные свидетельства linker/toolchain и не заявляет идентичную
перекомпиляцию. Нативная приёмка перелинковки и установленных материалов остаётся условием
релиза: изучение исходников само по себе её не доказывает.

Редактор также использует изменённый публичный fork Winit. Сохраняйте его уведомления
Apache-2.0 и доступ к точным изменённым исходникам. Шрифты сохраняют уведомления OFL;
графика — собственные сведения о происхождении. Созданные уведомления о зависимостях
не заменяют эти обязательства и юридическую проверку.

## Доверие, ошибки и ограничения релиза

В macOS по умолчанию подписывается весь bundle подписью ad-hoc, а не Developer ID;
notarization не выполняется. Целостность подписи не доказывает доверие Gatekeeper.
Пакеты Windows остаются неподписанными. У prerelease-артефакта macOS `v0.1.0` есть известный
дефект подписи bundle: ему нужна локальная переподпись. Он не доказывает приёмку текущего
пути сборки bundle. Не отключайте защиты операционной системы глобально ради запуска пакета.

Чистый Git workspace, корень которого совпадает с workspace Cargo, даёт `source_revision`.
Изменённые, вложенные или не-Git workspace записывают `null` и не допускаются к публикации.
Контрольные суммы обнаруживают изменение байтов, но не подтверждают личность издателя.
Чистая ревизия и опись сами по себе также не разрешают публикацию релиза.

При ошибках нативных инструментов, скачивания исходников, уведомлений, подписей или проверки
сохраните диагностику и частичный вывод, исправьте причину и повторите в новом каталоге.
Не пропускайте проверки происхождения, не исключайте исходники и не ослабляйте политику
ради получения описи.

Установка и поведение упакованного приложения для этого примера остаются непроверенными.
Перед распространением релиза независимо проверьте поиск установленных ресурсов, доступ
к уведомлениям/исходникам, нативную перелинковку там, где она нужна, установку/удаление,
отрисованные кадры и физический ввод на каждой целевой платформе. Минимум редактора —
macOS 15; совместимость Linux glibc/GPU/FUSE и минимальная Windows ещё требуют нативной
приёмки. AppImage не даёт универсальной совместимости. Успешность текущих hosted-проверок
пакетов/публикации и перелинковки получателем этими примерами руководства не установлена.

Разработчикам сборки, проверки происхождения и публикации следует читать
[контракт распространения](../../contributing/contracts/distribution.md): в нём заданы гарантии
и проверки для независимого потребителя. Канонические
[обязательства перед третьими сторонами (English)][third-party] и оригинальные тексты лицензий
остаются юридическими источниками; этот рецепт не заменяет лицензионную политику.

[third-party]: https://github.com/kedra-engine/kedra/blob/main/docs/third-party.md
