# Создание и открытие проекта

В окне Projects можно создать каталог исходников или открыть существующий проект Kedra.
Нужен работающий редактор с проверенной поставкой его ресурсов.
Для создания также нужен существующий родительский каталог с правом записи; для открытия —
доступный для чтения корень проекта с `kedra.toml` и указанным в нём каталогом ассетов.

Для первоначального запуска выполните
[подготовку ресурсов и запуск редактора](../getting-started/launch-editor.md).
Требования к сборке описаны в [Начале работы](../getting-started/index.md), подробности поставок —
в разделе [Обработка и проверка ассетов](../assets/pipeline.md).

## Создание пустого проекта

1. В Projects выберите **New project**.
2. Введите **Project name**, например `My Game`.
3. В **Location** укажите существующий родительский каталог через **Browse…** или вводом пути.
4. Проверьте путь назначения под подписью **Create new folder**: родительский каталог
   плюс имя проекта.
5. Нажмите **Create & open**.

Например, выбор существующего родительского каталога `Projects` и имени `My Game` создаёт
`Projects/My Game/kedra.toml` и пустой каталог `Projects/My Game/assets/`.
Редактор переходит в рабочую область проекта; исходников игры и стартовой сцены
для просмотра ещё нет.
Структура результата и поля манифеста описаны на странице [Проекты](index.md#манифест-проекта).

Имена сохраняют Unicode, включая варианты вроде `Кедра 日本語`. Ограничение — 160 байт UTF-8,
а не 160 символов. Отклоняются пустые имена, пробелы по краям, точка в конце, управляющие символы,
`.` и `..`, а также `< > : " / \ | ? *`. Имена устройств Windows, например `CON` и `lpt1.txt`,
отклоняются на всех платформах ради переносимости имени каталога.

Назначение не должно существовать даже в виде пустого каталога или символической ссылки.
Create не превращает существующую папку в проект и не перезаписывает её содержимое.
Форма проверяет, свободно ли имя, но не резервирует его; при создании проверка повторяется.

## Открытие существующего проекта

1. В Projects выберите **Open folder…**.
2. В **Project folder** укажите каталог с `kedra.toml`, а не сам манифест
   или дочерний `assets/`. Можно воспользоваться **Browse…**.
3. Нажмите **Open project**.

Формы принимают абсолютный нативный путь каталога. Они также раскрывают `~` и `~/…`
относительно домашнего каталога текущей учётной записи; произвольных подстановок оболочки нет.
Относительный путь, введённый в этих формах, отклоняется.

В качестве наполненного примера из рабочей копии Kedra выберите `tests/fixtures/test_project`
через Browse. В его манифесте указаны имя **Kedra Test Project** и каталог `assets/`.
В открывшейся рабочей области можно просматривать исходники тестового проекта,
включая `Hud.prefab.ron`.
Перед внешними изменениями сделайте полную копию; не меняйте канонический тестовый проект.
Открытие проекта не открывает документ автоматически и не гарантирует его отрисованное превью.

Продолжите [первым документом](../getting-started/first-document.md) для изучения тестового проекта.

### Выбор проекта при запуске

CLI редактора принимает существующий корень проекта как позиционный аргумент.
Из корня репозитория, если поставка ресурсов редактора уже подготовлена в `target/editor-assets`:

```sh
cargo run -p kedra -- tests/fixtures/test_project --assets target/editor-assets
```

Команда запускает тот же проверяемый процесс открытия проекта, что и окно Projects.
Она не собирает ассеты проекта. Без `--project-assets` не следует ожидать готовой к отображению
поставки для его исходников. Эта опция требует явно указанного позиционного проекта
и отдельно подготовленной соответствующей поставки; она не создаёт проект и не запускает его код.
В текущем исполняемом файле редактора нет CLI-подкоманды создания проекта.

Прежде чем ожидать отображения содержимого, изучите
[требования привязки превью](../assets/pipeline.md#editor-previews-need-matching-sources).

## Подготовка и ошибки

Быстрая подготовка может сразу открыть рабочую область без отдельного окна загрузки.
Если работа длится дольше, может появиться окно загрузки. Краткое или отсутствующее окно
загрузки не означает, что проверка пропущена.

При ошибке проверки в форме исправьте имя или каталог и отправьте форму повторно.
Если ошибка возникла позже, изучите сообщение и журнал запуска. После устранения причины
неудачный Open можно повторить. Для неудачного Create автоматического повтора нет:
вернитесь в Projects и проверьте назначение перед новой попыткой создания.

Типичные причины:

- Отсутствующий, нечитаемый или некорректный `kedra.toml`, неизвестные поля
  или неверный UUID проекта.
- Неподдерживаемый `format`: открытие не мигрирует и не переписывает проект.
- Отсутствующий каталог ассетов, абсолютный путь к нему или выход его корня за пределы проекта.
- Существующее назначение создания, отсутствующий родительский каталог или отказ в доступе.

Открытие не меняет исходники проекта, в том числе при отказе.
Создание публикует манифест последним и не перезаписывает существующее назначение.
Тем не менее прерывание может оставить неполный каталог. Не считайте отмену или закрытие окна
откатом уже опубликованных файлов; самостоятельно сохраните и проверьте неожиданное содержимое.
Проверки файловой системы не защищают от одновременной подмены путей другим процессом.

## Недавние проекты

Успешная подготовка запоминает до 20 проектов, начиная с последнего,
без повторов канонического корня.
Выберите доступную строку и используйте её элемент Open. Отсутствующие расположения остаются
в списке с элементами восстановления, а не удаляются молча. Укажите новый корень перемещённого
проекта через Browse: список не обнаруживает перемещения по UUID.

История хранится отдельно от исходников. Повреждение истории показывается пользователю,
а файл остаётся нетронутым; сохранение истории отключается на этот сеанс.
Ошибка записи истории выдаёт предупреждение, но не отменяет успешное открытие проекта.
При одновременной записи истории сохраняется результат последнего записавшего процесса.

## Границы проверки

Проверьте системный выбор папки, клавиатуру/IME, оформление окна и работу с разной плотностью
пикселей на целевом компьютере. Проверки на платформах ещё не завершены; проверка исходников
и сборка документации не проверяют эти взаимодействия.
