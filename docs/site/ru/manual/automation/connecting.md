# Подключение к отладочному приложению

Диагностический адрес принадлежит одному работающему процессу приложения. Нет
обнаружения без аутентификации, привязки к публичному сетевому интерфейсу или режима
удалённого управления в release. Используйте доверенный локальный клиент, способный
сохранить bearer-токен в тайне.

## Подготовка и явное включение

Хост устанавливает обычные плагины Bevy для ассетов, ввода, окон и рендеринга по
необходимости, затем `kedra_app::KedraAppPlugin` и API своих нативных возможностей.
Общий плагин не создаёт ни окно, ни рендерер. Только явная настройка удалённого доступа
открывает порт; подключения крейта или установки плагина недостаточно.

Хост включает `kedra_app::launch::LaunchOptions` или `RemoteOptions` в свой CLI.
Поля удалённого доступа существуют только с debug assertions. `--remote-port` и
`--remote-credentials` требуют друг друга; порт `0` выбирает доступный loopback-порт.
`--remote-artifacts` задаёт каталог захватов, по умолчанию `target/test/captures`.
Он отделён от исходников проекта и учётных данных.

Подготовьте подходящую поставку ресурсов редактора в `target/editor-assets`, затем
запустите редактор с новыми приватными путями диагностики:

```sh
cargo run -p kedra -- --assets target/editor-assets \
  --remote-port 0 --remote-credentials target/test/local-session.json \
  --remote-artifacts target/test/local-captures \
  --state-directory target/test/isolated-state
```

`--assets` и `--state-directory` — аргументы редактора, а не универсальные удалённые поля.
Обычная подготовка ресурсов описана в [Начале работы](../getting-started/index.md).
Не добавляйте `--remote-port`, `--remote-credentials` или `--remote-artifacts`
release-приложению: его парсер не предоставляет эти debug-only параметры.

## Публикация учётных данных — граница готовности

Целевой путь учётных данных не должен существовать, в том числе как символическая ссылка. Сервис
синхронно привязывается к `127.0.0.1` и готовит приватный временный файл учётных данных.
Возвращённый адрес и сообщение запуска пока имеют статус **pending**.

Публикация без перезаписи происходит только после первого цикла обработки запросов
и очистки BRP в основном мире Bevy и подтверждённого запуска HTTP-среды и слушающего сокета. Если
инициализация или публикация завершается ошибкой, приложение запрашивает аварийный выход,
а не считает неполную настройку успешной. Если целевой путь появился во время запуска,
публикация также отклоняется.

Внешний супервизор должен ограничивать время ожидания публикации и отслеживать выход процесса.
Публикация файла не доказывает монтирование формы, загрузку проекта, подтверждение
нативного окна или готовность рендерера. Для этого нужны последующие наблюдения и кадры.

Файл — JSON `Endpoint` со следующими точными полями:

| Поле | Значение |
| --- | --- |
| `url` | Текущий endpoint `http://127.0.0.1:PORT/` |
| `token` | Случайный bearer-токен доступа к зарегистрированным операциям этого процесса |
| `session` | Идентификатор процесса для отклонения запросов к устаревшим целям |

Значение токена здесь не приводится. Читайте настоящий файл локально; не вставляйте
его в чат, не коммитьте, не выводите в протокол команд и не прикладывайте к отчёту.
Токен не является аргументом CLI, и средство запуска его не печатает.

В Unix файлы учётных данных доступны только владельцу. В Windows содержащий каталог
уже должен иметь подходящий ACL; сервис не устанавливает ACL этого каталога.
Защитите также родительский каталог и приватные журналы клиента.

## Аутентифицируйте каждый запрос

Отправляйте HTTP `POST` на обнаруженный URL с `Content-Type: application/json` и
`Authorization: Bearer TOKEN`, подставляя приватный токен внутри клиента. Это описание
формата заголовка, а не рекомендация раскрывать токен через аргументы оболочки или
публичные журналы.

Начните с запроса `app.describe`:

```json
{
  "jsonrpc": "2.0",
  "id": "describe-1",
  "method": "app.describe"
}
```

`result` ответа сообщает `protocol: 1`, `session`, `methods`, `operation_capacity`,
описания координат/ввода и `scripting`. Используйте возвращённый список, а не
предположение, что методы редактора существуют у игрового хоста.
Эффекты и опрос описаны в [Наблюдении и операциях](observation-and-operations.md).

Любой заголовок `Origin` отклоняется, включая браузерные origin с того же компьютера.
Нет CORS с разрешением для любых источников или обнаружения через браузер. Отсутствующая/неверная
аутентификация даёт HTTP 401; заголовок Origin — 403. Это не квитанции сбоя операции.

## Завершение сеанса и устаревшие учётные данные

При обычном освобождении ресурсов сервис останавливает поток HTTP-сервера и ждёт его завершения.
Удаляется только успешно опубликованный обычный файл этого экземпляра, если его сеанс
и токен всё ещё совпадают. Подменённые файлы и символические ссылки не удаляются вслепую.

Принудительно остановленный процесс может оставить устаревший файл. Не используйте его
сеанс или ID окон в другом процессе и не перезаписывайте путь автоматически. Выберите
новое расположение учётных данных для следующего сеанса; изучение и очистка устаревших
приватных материалов остаются ответственностью супервизора.

Успешное завершение — факт жизненного цикла процесса, а не HTTP-квитанция. Запрос
закрытия может удалить собственную цель до завершения квитанции ввода. Хост также
может отказать в закрытии. См. [Ввод и захват кадров](input-and-captures.md).

## Если подключение не удалось

Синтаксис запуска описан в [опциях CLI редактора](../cli/editor-and-assets.md).
Готовность процесса и очистка под надзором — в [Нативных сценариях](../testing/native-scenarios.md).

- Файла ещё нет: проверьте приватную диагностику запуска и процесс в пределах срока.
- Путь занят: выберите новый; не удаляйте незнакомое пользовательское содержимое.
- HTTP 401/403: проверьте источник учётных данных и заголовки, а не готовность UI.
- Сервер отвечает, но UI нет: отдельно изучите окна и состояние нужной функции.
- Таймаут после эффекта: запросите его операцию, прежде чем решать, нужен ли повтор.

[Исходник транспорта][transport] (English) определяет жизненный цикл учётных данных и
лимиты транспорта; [общий исходник запуска][launch] (English) — отладочные поля CLI.
