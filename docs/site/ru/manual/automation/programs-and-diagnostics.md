# Программы и диагностика

Точные вызовы внутри программ описаны в [Luau API приложения](../../api/luau/application.md),
[диагностике редактора](../../api/luau/editor.md) и
[API тестовых стендов](../../api/luau/testing.md).

Зарегистрированные программы приложения объединяют диагностические действия внутри
работающего приложения. Это конечные Luau Sequences, выбираемые по имени, а не удалённо
переданный исходник, произвольное вычисление или Play в редакторе. Rust-хост владеет
исходниками, привязками, допущенными модулями и разрешением на выполнение.

## Сначала узнайте доступные программы

`app.describe.scripting` сообщает `language: "Luau"`, имена программ и `source_eval: false`.
Общие встроенные программы: `app.input`, `app.resize`, `app.capture`, `app.click` и
`app.field`. Первые три оборачивают нативные операции; click находит стабильный ID UI,
а field ждёт фокуса, выделения, доставки текста и наблюдаемого значения.

Имена программ и нативных методов выбирают разные операции, даже при одинаковом написании.
`app.input` как метод JSON-RPC принимает целочисленный идентификатор окна и параметры эффекта.
Программа `app.input` запускается через `app.scenario`; её API приложения использует
десятичные строки нативных идентичностей, чтобы избежать округления чисел Luau.

Когда цель `projects.new` редактора готова, вызовите общую программу щелчка.
Замените сеанс и используйте новый UUID:

```json
{
  "jsonrpc": "2.0",
  "id": "scenario-1",
  "method": "app.scenario",
  "params": {
    "session": "SESSION",
    "id": "123e4567-e89b-42d3-a456-426614174003",
    "scenario": "app.click",
    "arguments": {"id": "projects.new"}
  }
}
```

Опрашивайте UUID операции через `app.operation`; допуск не означает завершения.
Неизвестные программы, старые сеансы, поля source/eval и одновременные запросы сценариев
отклоняются. Аргументы — отдельные JSON-данные с ограничениями, не код: до 64 KiB,
глубина 32, целые в диапазоне точного представления double. Лимит тела HTTP включает
также оболочку запроса, поэтому не даёт дополнительных 64 KiB только для аргументов.

Одновременно активен только один сценарий приложения. Совпадающие повторы используют
квитанцию повторно; конфликтующее использование ID отклоняется. Нативные методы работают
внутри процесса через те же зарегистрированные системы Bevy, без HTTP-вызовов к себе.
Ввод из очереди по-прежнему проходит через виджеты. Завершение сценария не превращает
внедрённые события в физический ввод. См. [Ввод и захват кадров](input-and-captures.md).

## Отмена отзывает доступ, но не откатывает эффекты

`app.scenario_cancel` принимает `session`, **новый** `id` отмены и `operation` с UUID
активного сценария. Это разные идентичности операций. Его квитанция может сообщить
`{"cancelled":"UUID","rollback":false}` в `detail`.

Отменённый сценарий затем завершается ошибкой. Уже доставленный ввод, опубликованные
артефакты и изменения приложения не откатываются. Устаревшая/неактивная операция не может
отменить другой запуск. Сохраняйте внешний надзор за процессом: корутина внутри
приложения не может контролировать собственное падение или остановившийся цикл кадров.

## Наблюдения и программы редактора

Редактор регистрирует `editor.state` для фазы запуска, задач, готовности, ошибки/уведомления,
проекта и настоящих черновиков формы. `editor.workspace` сообщает, привязана ли рабочая
область, её логическое состояние стыковки и документов, а также привязку к нативному окну.
Значения `bound` или `native_alive` не подтверждают отрисовку кадра или работу ввода.

`editor.project` — семантический адаптер к тому же проверяемому жизненному циклу проекта,
что использует UI. Он может открыть формы, обновить черновики или запросить операции
проекта с учётом правил запуска, монтирования и занятости. Семантическое изменение
черновика не доказывает клавиатурный ввод. Запуск явной сцены отклоняет команды проекта
до допуска операции.

Программа редактора `editor.startup.forms` получает `ctx.editor` с ограниченной областью доступа
и наблюдениями `state()` и `workspace()` только для чтения, наряду с `ctx.app`. Она проверяет
геометрию DPR 1/2, модальный фокус, ввод Unicode, сохранение данных при ошибке валидации
и отмену с синхронизацией рендерера. Запускайте её на том компьютере и той ревизии,
которые нужно проверить.

Другие хосты могут регистрировать иные конечные программы. Не считайте специфичные для
фикстуры `scene.switch`, `projection.exercise` или docking-диагностику универсальным
игровым API. Жизненный цикл runtime-программ и модули описаны в
[Программировании](../programming/index.md) и [контракте Luau runtime][runtime] (English).

## Определите уровень сбоя

| Симптом | Значение и следующая проверка |
| --- | --- |
| HTTP 401 / 403 | Отказ по учётным данным, заголовку или Origin; это не квитанция операции приложения |
| HTTP 413 / 429 | Тело больше 64 KiB или заняты все 16 одновременных слотов транспорта |
| HTTP 408 | Истёк внешний шестисекундный срок HTTP; эффекты ещё могут завершиться |
| JSON-RPC `-32600` | Неверная оболочка запроса или число запросов в пакете вне 1..16 |
| JSON-RPC `-32601` | Неизвестный метод или неподдерживаемый потоковый запрос `+watch` |
| JSON-RPC `-32602` | Неверные параметры, устаревшая цель, отказ из-за лимита или занятости, неизвестная или вытесненная квитанция |
| JSON-RPC `-32000` | Сбой или таймаут пятисекундного ожидания почтового ящика; неизвестно, выполнилась ли операция |
| Квитанция `failed` | Принятая работа завершилась ошибкой; изучите приватный `detail` и проверьте, что нужное состояние не изменилось |
| Квитанция остаётся `pending` | Обновления или считывание могли остановиться; продолжайте внешний надзор с ограничением времени |

Транспорт принимает пакеты запросов JSON-RPC с ограниченным размером, но не потоковые наблюдения.
Уведомления не имеют ID запроса JSON-RPC и не возвращают обычный ответ; для ошибок и
квитанций эффектов используйте запросы с ID. Ответ только на уведомления — HTTP 204.
Не считайте пакет атомарной транзакцией: ранние команды уже могут иметь эффекты.

Среда скриптов также имеет структурированные категории `ScriptError` и ограниченную
диагностику. Не предполагайте, что каждая нативная RPC-квитанция сохраняет эту структуру:
адаптер сценариев превращает терминальные ошибки скрипта в текст сбоя квитанции.
Храните приватную диагностику локально; передавайте только проверенные отчёты, пригодные
для публикации, без учётных данных, необработанных наблюдений ошибок и полных журналов.

## Владельцы интеграции и свидетельств

[Программирование](../programming/index.md) описывает интеграцию скриптов под управлением хоста;
[Нативные сценарии](../testing/native-scenarios.md) — работу внешнего супервизора.
Команду выбирайте через [карту задач CLI](../cli/index.md).

`RemoteAppExt` регистрирует реализованные системы возможностей; повторные имена — ошибки
программиста, а не механизм удалённого расширения. Общий API приложения не даёт
универсального доступа к World или редактору. Клиент `kedra_test` на стороне инструментов
явно выбирает программы ввода/resize/захвата; путь `operation` вызывает ровно указанный
нативный метод без скрытой замены другим способом. Внешние Rust-сценарии готовят приложение,
проверяют результат, ограничивают время работы процесса и публикуют отчёты.
См. [контракт автоматизации][automation]
и [руководство по тестированию][testing]; программа внутри приложения —
не полноценный независимый проверяющий.
