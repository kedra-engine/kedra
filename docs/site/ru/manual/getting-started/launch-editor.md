# Подготовка ресурсов и запуск редактора

Выполняйте команды из корня репозитория после [подготовки](index.md).
Kedra загружает интерфейс из обработанной поставки ресурсов, а не напрямую из авторского
каталога `assets/editor`. В этом маршруте сборки из исходников нет шага с установщиком.

## 1. Соберите поставку ресурсов редактора

Каталог назначения **не должен существовать**, даже если он пуст. Родитель может существовать.
Примеры создают результаты в `target/documentation/examples/getting-started/`, вне авторских
исходников. Если каталог уже существует, выберите новое имя и используйте его во всех
последующих командах. Не удаляйте и не перезаписывайте поставку ради повторного запуска.

```sh
cargo run --locked -p kedra -- assets build assets/editor target/documentation/examples/getting-started/editor-delivery --namespace editor
```

Ожидаемый результат: ход обработки, проверка загрузки нативных зависимостей и итоговое
сообщение `SUCCESS: … assets delivered`. Сборка не записывает изменения в эти исходники.
У исходников редактора уже есть sidecar-файлы; не запускайте для них `assets init`.

## 2. Проверьте поставку ресурсов

```sh
cargo run --locked -p kedra -- assets verify target/documentation/examples/getting-started/editor-delivery
```

Ожидаемый результат: `SUCCESS: … assets verified`. Проверка работает только на чтение,
проверяет манифест, хеши и метаданные загрузчиков. Она не открывает окно и не проверяет
отрисовку. Не меняйте поставку во время работы редактора.

## 3. Откройте Projects

Следующая команда **запускает нативное приложение**; выполните её, когда будете готовы
работать с окном редактора. Отдельный каталог состояния позволяет не затрагивать
ваши обычные настройки редактора:

```sh
cargo run --locked -p kedra -- --assets target/documentation/examples/getting-started/editor-delivery --state-directory target/documentation/examples/getting-started/editor-state
```

После проверки ресурсов окно **Projects** предлагает **Open folder** и **New project**.
Заставки нет. Подготовка проекта может сразу открыть рабочее пространство или ненадолго
показать окно загрузки; ни один из вариантов не пропускает валидацию.

Установленному приложению нужны и исполняемый файл, и обработанная поставка редактора;
ассеты UI Kedra не встроены в исполняемый файл. Без `--assets` поиск использует `KEDRA_ASSETS`,
затем платформенное расположение относительно исполняемого файла, не рабочий каталог или
исходники. Переносимые/разрабатываемые сборки используют соседний `assets`; app bundle macOS —
`Contents/Resources/assets`, а расположение Linux `usr/bin` — `usr/lib/<executable>/assets`.

1. Нажмите **Open folder**.
2. Через **Browse** выберите `tests/fixtures/test_project` внутри своего репозитория.
   Нужен каталог с `kedra.toml`, а не `assets/` или сам файл манифеста.
3. Если заполняете **Project folder** вручную, введите абсолютный нативный путь.
   Относительный текст вроде `tests/fixtures/test_project` эта форма не принимает.
4. Нажмите **Open project**.

Ожидаемый результат: рабочее пространство **Kedra Test Project** с инструментами Assets,
Hierarchy и Inspector и пока пустой областью просмотра документа. Открытие проекта не
открывает документ автоматически. Перейдите к [первому документу](first-document.md).

## Дополнительно: прямой запуск с отрисовкой превью

Перед повторным запуском закройте редактор. Соберите и проверьте отдельную поставку проекта:

```sh
cargo run --locked -p kedra -- assets build tests/fixtures/test_project/assets target/documentation/examples/getting-started/project-delivery --namespace game
cargo run --locked -p kedra -- assets verify target/documentation/examples/getting-started/project-delivery
```

В обеих командах оставьте профиль по умолчанию **`editor-desktop`**. Пространство имён —
`game`, но профиль `game-desktop` не соответствует требованиям привязки превью редактора.
В тестовом проекте метаданные уже есть; не инициализируйте и не меняйте его канонические исходники.

Следующая команда открывает тестовый проект напрямую с обеими поставками ресурсов:

```sh
cargo run --locked -p kedra -- tests/fixtures/test_project --assets target/documentation/examples/getting-started/editor-delivery --project-assets target/documentation/examples/getting-started/project-delivery --state-directory target/documentation/examples/getting-started/editor-state
```

Позиционный путь проекта может быть относительным к корню репозитория в терминале, в отличие
от формы Projects. `--assets` задаёт ресурсы редактора, `--project-assets` — ресурсы превью
проекта и требует явного позиционного проекта. Ни один параметр не собирает ассеты при
запуске и не выполняет код проекта. Соответствие исходникам проверяется при открытии документа.

## Если подготовка завершилась ошибкой

- При ошибках компилятора, линкера или отсутствующих библиотек проверьте
  [требования платформы](index.md).
- Если каталог результата уже существует, выберите новый; не используйте неполную сборку повторно.
- При отсутствии маркера поставки или неверных хешах соберите доверенные неизменённые исходники
  в новый каталог и проверьте его. Сам `assets/editor` не является поставкой ресурсов.
- При ошибке проверки проекта проверьте выбранный корень и прочитайте диагностику запуска;
  см. [восстановление после ошибок](../projects/create-open.md#подготовка-и-ошибки).
- При ошибке превью после успешного запуска см.
  [условия соответствия поставки][preview-matching].

Для нового пустого проекта используйте [Создание пустого проекта][empty-project], а не
копируйте манифест тестового проекта как шаблон.

Участникам, меняющим время начальной загрузки, асинхронную подготовку или время жизни окон,
следует прочитать [инженерный контракт запуска](../../contributing/contracts/startup.md).
