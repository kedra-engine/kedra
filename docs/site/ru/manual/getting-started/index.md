# Начало работы

Соберите Kedra из открытых исходников, откройте готовый тестовый проект и изучите первый
документ. Настольный редактор поддерживает правки исходников и явный Save.
Этот маршрут не создаёт и не запускает игру; Play пока недоступен.

## Перед началом

Модель продукта и ограничения описаны на странице [Что такое Kedra?](../introduction/index.md).

Нужны Git, [rustup](https://rustup.rs/), доступ к сети для первой загрузки зависимостей и
нативный компилятор с линкером для вашей платформы:

| Платформа | Требования для нативной сборки |
| --- | --- |
| macOS | Xcode Command Line Tools |
| Windows | Visual Studio C++ Build Tools и Windows SDK |
| Linux | Компилятор C и линкер, `pkg-config`, библиотеки разработки ALSA/udev и Wayland/X11; поиск системных шрифтов также использует Fontconfig |

В Debian/Ubuntu установите набор инструментов компиляции (например, `build-essential`) и
следующие пакеты разработки. Эта команда предназначена только для Debian/Ubuntu, не для
других дистрибутивов Linux или macOS:

```sh
sudo apt-get install pkg-config libasound2-dev libudev-dev libwayland-dev libxkbcommon-dev libx11-dev libxcursor-dev libxi-dev libxrandr-dev libfontconfig1-dev
```

Обработка ассетов без окна не требует GPU. Для запуска редактора и отрисовки превью нужна
работающая графическая среда рабочего стола. Для Linux, Windows и macOS настроены проверки
CI, но ни один набор настольных платформ не сертифицирован по физическому вводу, IME и
работе с разными DPI. Редактор не предназначен для веба и мобильных устройств.

Node.js и Bun относятся к инструментам сайта документации. **Они не нужны для сборки и
запуска нативного редактора.** Закрытая инфраструктура и AI-сервисы также не требуются.

## 1. Получите исходники и закреплённый Rust

Клонируйте репозиторий в новый каталог и выполняйте дальнейшие команды из его корня:

```sh
git clone https://github.com/kedra-engine/kedra.git
cd kedra
rustup show active-toolchain
```

Файл `rust-toolchain.toml` закрепляет Rust **1.98.0** с `rustfmt` и `clippy`.
Внутри репозитория rustup использует эту версию; не заменяйте её произвольной последней
версией. Если нужный набор инструментов отсутствует, установите его явно:

```sh
rustup toolchain install 1.98.0 --profile minimal --component rustfmt --component clippy
```

Приведённые далее команды используют `--locked`, сохраняя разрешение зависимостей из
`Cargo.lock`. При первом запуске Cargo компилирует зависимости, что может занять заметно
больше времени, чем последующие запуски. Оставьте терминал открытым: там видны ход работы
и диагностические сообщения.

## 2. Подготовьте ресурсы и запустите редактор

Перейдите к странице [Подготовка ресурсов и запуск редактора](launch-editor.md).
Вы соберёте поставку ресурсов интерфейса редактора, проверите её и выберете запуск через
окно Projects или прямое открытие наполненного тестового проекта из репозитория.

Для первого знакомства используйте готовый тестовый проект, а не **New project**:
у нового проекта каталог `assets/` пуст и нет сцены для открытия.
Этот отдельный маршрут описан в разделе [Создание и открытие проекта](../projects/create-open.md).

## 3. Изучите документ

На странице [Открытие и изучение первого документа](first-document.md) вы найдёте готовый
префаб, выберете его узел в Hierarchy и прочитаете компоненты в Inspector. Для изучения
исходных данных поставка ресурсов проекта необязательна, но для отрисовки превью она нужна.

Управление панелями описано в [Рабочем пространстве редактора](../editor/index.md).
Проверьте нативное взаимодействие и отрисовку на своей машине: успешная сборка
или команда verify не подтверждает, что редактор отрисовал кадр.
