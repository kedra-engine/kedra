# Scene View

Scene View показывает превью поддерживаемых сцен/префабов и исходных PNG/статических GLB.
Камера, варианты освещения, сетка и рамки выбора служат просмотру. Они не перемещают
исходные узлы. Инструменты трансформации отдельно редактируют выбранный пространственный узел;
Play пока отсутствует, сохранение исходника выполняется явно.

Откройте исходник через [Assets](asset-browser.md). Вкладка документа разделяет выбор
с [Hierarchy](hierarchy.md) и [Inspector](inspector.md); превью отдельных ассетов
не создают узлы исходного документа.

Данные рендеринга для этих превью описаны в разделе
[графики и UI](../rendering-ui/index.md), замена освещения и владение холстами — в разделе
[сцен предпросмотра](../rendering-ui/preview-stages.md).

## Подготовка ресурсов {#prepare-resources}

Принятие исходников и отрисовка — разные этапы. Hierarchy и Inspector могут работать
без отрисованного кадра. Scene View дополнительно требует проверенную поставку ресурсов
того же проекта, привязанную к его корню исходников и namespace `game`, с совпадающими
принятыми байтами и идентичностями.

Соберите поставку проекта и запустите редактор с путём проекта, `--assets PATH`
для редактора и `--project-assets PATH` для проекта. Полный порядок приведён
в [описании поставок](../assets/pipeline.md#editor-previews-need-matching-sources).
Open не собирает ресурсы и не создаёт отсутствующие метаданные. Для смены привязки
поставки нужен перезапуск; другой проект не может незаметно использовать прежнюю привязку.

Профиль превью принимает документы, PNG, статические GLB, CSS и шрифты с сохранением байтов.
Корректная поставка общего назначения не обязательно подходит: преобразованный результат
без требуемых сведений о происхождении отклоняется. Проверяется принятый набор,
а не только текстура видимого узла.

## Поддерживаемое содержимое

| Цель | Поведение превью |
| --- | --- |
| Пространственная сцена/префаб | Поддерживаемые трансформации, кубоиды/сферы, непрозрачные поверхности, направленный свет, окружение сцены и статические модели. |
| Пассивный UI-документ | UI из исходников на фиксированном холсте 1280 × 720 с вписыванием без искажения пропорций. |
| Смешанный пространственный/UI-документ | Пространственный вид по размеру области просмотра и отдельно вписанный прозрачный UI поверх него. |
| `.png` | Превью с пропорциями изображения, без пространственного управления камерой. |
| Статический `.glb` | Просмотр `Scene0` в принадлежащей редактору сцене предпросмотра, сначала с Editor lighting. |

Поддерживаемые пространственные ключи: `scene.transform`, `scene.primitive`, `scene.surface`,
`scene.sun`, `scene.environment` и `scene.model`. Primitive и surface нужны вместе.
Данные UI требуют `ui.layout`; UI и пространственные данные размещаются на разных узлах,
а пространственный узел/узел без layout не может быть потомком UI-layout.
Обязательные внешние порты и неподдерживаемые схемы компонентов дают диагностику,
а не игнорируются. Навигация по исходникам может оставаться доступной.

Пассивный UI не является работающим интерактивным интерфейсом. Его кнопки не отправляют
команды, поля не получают фокус, скрипты не выполняются. Изменение размеров/docking
вписывает фиксированный холст, не меняя исходную компоновку. В смешанном документе
это не добавляет поля пространственной камере и не сужает область выбора мешей.

Камеры, свет и анимации импортированных моделей отключены; skins и morphs отклоняются.
Это не поддержка всех возможностей рендерера Bevy или всех форматов моделей. Тени,
skybox/IBL и произвольные специализации материалов не входят в этот профиль.

## Управление камерой

Управление доступно только для готового пространственного вида. Колесо управляет областью
просмотра под указателем без переноса фокуса. `F` работает с активной сценой после выбора
в Hierarchy; текстовые поля и модальные элементы сохраняют свой клавиатурный ввод.
LMB, MMB и RMB ниже — левая, средняя и правая кнопки мыши.

| Жест/клавиша | Действие |
| --- | --- |
| Alt + перетаскивание LMB | Орбита вокруг сохранённой опорной точки. |
| Перетаскивание MMB | Панорамирование. |
| Колесо над областью просмотра | Приближение/отдаление в перспективе; масштаб в ортографической проекции. |
| Удержание RMB и движение мыши | Осмотр с временно захваченным и скрытым курсором. |
| W/A/S/D при удержании RMB | Движение вдоль осей камеры вперёд/вправо. |
| Q / E при удержании RMB | Движение вниз/вверх вдоль мировой оси Y. |
| Shift при полёте | Увеличение скорости. |
| Колесо при удержании RMB | Настройка скорости полёта в допустимых пределах. |
| `F` при активной сцене, вне текстовых полей | Frame selection; при отсутствии границ — диагностика. |
| Escape | Прерывание навигации/выравнивания и освобождение захвата. |

Отпустите начавшую жест кнопку для завершения перетаскивания или полёта. Потеря фокуса,
изменение docking и скрытие/удаление представления тоже прерывают навигацию. Жест принадлежит
одному виду и окну; ввод в другой панели или окне не должен управлять этой камерой.

Контрол ориентации следует за камерой в системе Y-up. Щёлкните конец оси с нужным знаком
для выравнивания; повторите выбранное направление для перехода на противоположное.
Перетаскивание диска или конца оси включает орбиту. Выравнивание указателем выполняется
плавно и может быть прервано; настройка reduced motion делает его мгновенным.
В общей полосе инструментов есть Frame selection. Панорамирование — перетаскивание MMB,
приближение — колесо мыши.
Кнопка Perspective / Orthographic под контролом ориентации переключает проекцию.
Эти действия меняют вид, а не трансформацию выбранного объекта.

## Панель инструментов и меню

В существующей панели внутри viewport сгруппированы иконки **Move**, **Rotate**, **Scale**
и **Snap** (магнит) вместе с Frame selection и Settings в одном ряду внутри viewport;
отдельного верхнего тулбара нет. `W` / `E` / `R` включают
инструменты вне текстовых полей и полёта камеры.
Кнопка с рукой отключает текущий инструмент трансформации и скрывает манипулятор,
сохраняя выбор и навигацию камерой. Иконка инструмента или W/E/R снова включает редактирование.
Move использует мировые оси, кольца Rotate и ручки Scale — локальные. Кубик на оси меняет
одну компоненту масштаба; центральный кубик при горизонтальном перетаскивании масштабирует
равномерно, сохраняя пропорции и знаки. Переход масштаба через ноль отклоняется.
При неравномерном масштабе родителя кольца вращения следуют эллиптическим плоскостям.
Отпускание создаёт одну операцию Undo, Escape отменяет предпросмотр. Snap задаёт шаг
в одну единицу, 15 градусов или 0.1 множителя масштаба от начала жеста независимо от сетки.
Save сохраняет только принятые изменения. Настройка шага и переключение World/Local пока
не реализованы; качество физического ввода и разные DPI между мониторами ещё не проверены.

Меню **View settings** содержит **Frame all**, **Clear selection**, **Toggle selection outlines**, **Toggle grid**
и выбор освещения. Frame all помогает вернуться к содержимому после навигации.
Стандартные виды выбираются контролом ориентации, проекция — кнопкой под ним
с сохранением видимого масштаба у опорной точки.
Без выбора документа Clear selection отключена. В низких/маленьких областях
недостижимые контролы навигации скрыты.

- **Toggle selection outlines:** скрывает/возвращает рамки выбора, включая UI. Не скрывает исходные объекты,
  не очищает выбор, не меняет сетку и не удаляет границы для кадрирования.
- **Toggle grid в View settings:** переключает бесконечную сетку и цветные оси X/Z. Шаг — одна единица исходника,
  а не автоматический перевод в единицы проекта.
- **Освещение в View settings:** выбор **Scene lighting** или **Editor lighting**.
  Документы начинают со Scene lighting, превью отдельного GLB — с Editor lighting.

Editor lighting заменяет фон/ambient этого вида и подавляет вклад его исходного света,
а не добавляет ещё один свет сверху. Scene lighting возвращает принятые исходные настройки.
Сцена без окружения не получает скрытый студийный вариант. Эти режимы не изменяют
ассеты окружения и исходные источники света.

Положение камеры, проекция, опорная точка и скорость полёта сохраняются при переключении
вкладок, изменении размера и Float/Redock в сеансе. Это не значения исходника и не настройки
для восстановления после перезапуска. Чистый UI и изображения сохраняют фиксированное
представление с отключёнными пространственными командами.

## Выбор исходных узлов

Завершённый обычный щелчок LMB выбирает ближайший подходящий **непрозрачный треугольник меша**
в представлении документа. Пустое место очищает выбор. Навигационные перетаскивания
и щелчки с модификаторами не выбирают сквозь область просмотра. Части импортированной модели
сопоставляются с её точным исходным узлом, включая область вложенного экземпляра префаба;
вспомогательные объекты и другие виды исключены.

Это не выбор UI и не попиксельный визуальный выбор. UI, поверхности с alpha mask/blending
и обратные стороны не поддерживаются как цели выбора. Подходящий непрозрачный меш за
неподдерживаемой поверхностью может оказаться выбранным. Для UI и неотрисовываемых узлов
используйте Hierarchy.

Выбранные в Hierarchy пространственные узлы получают границы без перемещения камеры.
UI-узлы получают неинтерактивную рамку по фактическому layout, трансформации и унаследованному
отсечению. Выбор UI-родителя обводит его собственный прямоугольник, а не объединение потомков.
У скрытых, пустых или вырожденных прямоугольников рамки может не быть. Изменение layout
не требует повторного выбора. Это работает для чистых UI- и смешанных документов.

## Пример: просмотр смешанной сцены

Подготовка тестового проекта и поставки описана в
[инструкции запуска](../getting-started/launch-editor.md) и
[первом документе](../getting-started/first-document.md).
Различия исходника и проекции объясняет раздел [Сцены и префабы](../scenes/index.md).

В тестовом проекте из репозитория с соответствующей поставкой ресурсов откройте
`Composed.scene.ron`:

1. Выберите **Warm sphere** в Hierarchy: Inspector последует за выбором, камера останется.
2. Нажмите **Frame selection** рядом с контролом ориентации, затем Alt-перетаскивание для орбиты вокруг сферы.
3. Переключитесь на **Orthographic** под контролом ориентации и выберите +Z для вида спереди.
4. Выберите узел **title** под **Passive UI fixture** в Hierarchy. Его рамка следует за
   вписанным HUD; щелчок по надписи в Scene View не выбирает UI-узел.
5. Откройте `ship.glb` в Assets. Появится превью модели без исходной цели Hierarchy.
   Возврат к вкладке документа восстановит выбранный UI-узел.

Файл `ship.glb` из тестового проекта — сгенерированная модель с двумя материалами,
а не внешний игровой ассет.
`Hud.prefab.ron` показывает тот же пассивный UI без пространственной сцены.

## Загрузка и диагностика

Вид готов к работе, когда ресурсы загружены и рендерер выдал актуальный кадр.
При недоступности, ошибке и завершении жизни вида управление отключено. После изменения
размера может потребоваться свежий кадр; скрытые вкладки прекращают отрисовку и создают
цели заново при показе. Отсутствующая/устаревшая поставка, неподдерживаемые схемы,
ошибки зависимостей и исчерпанные бюджеты ресурсов сопровождаются диагностикой.
Чёрный вид сам по себе не доказывает ни ошибку принятия исходников, ни успешную отрисовку.

Цели ограничены 2048 пикселями по каждой стороне и общим бюджетом цветовых целей 64 МиБ.
Вид отклоняет более 4096 узлов представления или 256 генерируемых примитивных мешей.
Это пределы отказа, а не усечение или гарантия общего потребления GPU-памяти.

Работа с физической мышью и трекпадом, захват курсора RMB, панорамирование MMB, IME
и переходы между мониторами/DPI ещё требуют отдельных нативных проверок.
