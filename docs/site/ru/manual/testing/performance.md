# Диагностика производительности GUI

Сначала профилируйте конкретное действие пользователя. Сохраняйте контрольный запуск без
профилировщика: трассировка, RPC-опрос и readback сами создают нагрузку. Не запускайте сборку
или полный набор тестов одновременно с измерениями задержки.

## Сборка и наблюдение

Профиль разработки оптимизирует код workspace на уровне 1, зависимости — на уровне 2,
сохраняя debug assertions и явно включаемую автоматизацию. Release имеет отдельную границу
доступных возможностей. Сравнивайте эквивалентные сборки с записанными командами и окружением.

Явно включённая debug-автоматизация собирает до 4096 интервалов обновления main world и
изменений компонентов UI через диагностику Bevy. Read-only RPC `app.performance` также
доступен как `ctx.app.performance()` в Luau. Он не сериализует дерево UI и текстовые значения,
не сбрасывает историю, не вводит события и не включает HTTP listener.
Параметр `{"include_changed_nodes":true}` добавляет до 32 изменённых Node последнего
обновления: сущности, стабильные ID/родителей и свойства Node, без текстовых значений.

Результат содержит `enabled`, `frame`, суммарный `inventory`, статистику `update_intervals`
(количество/ёмкость, среднее, минимум, p50/p95/p99, максимум в миллисекундах) и `ui_changes`
(последнее/среднее число изменённых Node/Text/TextFont/UiTransform за обновление).
`focus_events` считает события фокуса окна за время включённого сбора и помогает
отбросить замер, прерванный сменой фокуса.
Без включённой автоматизации сбор неактивен, недоступные значения равны null.

История скользящая, не ограниченная одним действием. Change detection не доказывает реальное
изменение значения или перестроение всего поддерева. Интервалы включают ожидания и pacing:
это не длительность CPU-работы, GPU или физическая задержка от ввода до изображения.

Редактор использует явную политику Winit со страховочным опросом idle раз в 100 ms.
События окна/ввода и публикация через адаптеры задач/progress пробуждают его сразу.
Дедлайны подсистем сокращают ожидание; active work использует интервал 1/60 s при
фокусе или 100 ms без фокуса. Видимые обслуживаемые Scene Views требуют Continuous
в обоих состояниях фокуса, включая состояние готового кадра. В текущем общем World
это оставляет активным весь App редактора. Это политики ожидания, не точный FPS cap
и не изолированные часы симуляции. Игровые приложения их не наследуют. Бесконечный
сон редактора не поддерживается; см.
[ADR 0045](../../../../decisions/0045-bounded-reactive-editor.md).

## Запись CPU-профиля и просмотр

Runtime-пакет `kedra_profiling` владеет явно запускаемой ограниченной CPU-записью.
Feature `capture` подключает backend Perfetto SDK через существующий log layer Bevy.
Прикладной код использует API Kedra, а не типы backend. Обычная сборка не включает
записывающий backend и его CLI-флаги. Для записи не нужны debug-автоматизация или RPC.

Соберите редактор с `--features profiling`, передайте обычные аргументы проверенных
поставок ресурсов и явный каталог результатов:

```sh
cargo run --locked -p kedra --features profiling -- <editor-arguments> \
  --profile-output target/performance/editor --profile-manual
```

При разрешённом профилировании **F9** запускает/останавливает конечную запись редактора.
По умолчанию максимум — пять секунд, буфер SDK — 32 MiB. `--profile-duration-ms`
принимает 100..=30000, `--profile-buffer-kib` — 1024..=65536 KiB. Без `--profile-manual`
запись начинается на Startup. Это ограничение длительности, не ожидание готовности UI.

CLI показывает состояние и итог записи. Успех указывает новый приватный каталог с
`trace.pftrace` и `recording.json`. Stop и публикация асинхронны; закрытие владельца до
публикации отменяет запись, а не объявляет частичный файл успешным. Существующие записи
не перезаписываются; сохранённые результаты остаются после выхода из приложения.

Откройте [Perfetto UI](https://ui.perfetto.dev/) и выберите локальный `trace.pftrace`
через **Open trace file**. Для просмотра используется готовый браузерный UI, без
WebView или собственного viewer. Локальное открытие не требует загрузки трассы на сервер;
не используйте sharing/upload для приватных записей по умолчанию. Проверьте статистику
потерь/ошибок и незавершённые граничные slices: сохранение файла не доказывает полноту.

[Самостоятельный пример Bevy][profiling-crate] использует тот же recorder без редактора,
окон, assets и автоматизации. Host настраивает штатный log hook Bevy и `Recorder`,
не устанавливая второй глобальный subscriber или scheduler.

## Собственные метки и counters

### Локальный семантический обзор

`--profile-label menus` явно задаёт сценарий записи. Host/build/session identity и
метка сохраняются в `recording.json` и событии `kedra.recording`. Отсутствующая метка
означает неизвестный сценарий; перезапись кольцевого буфера может удалить контекст.

[Набор локального анализа Perfetto](../../../../../tools/profiling/README.md)
содержит ограниченные SQL-запросы здоровья/рейтинга и макрос штатного UI для
категорий, интервалов updates и связи с CPU render. Перед анализом проверьте потери
адаптера в manifest и ошибки/потери processor. Опциональная feature `render`
передаёт явный update identity через Bevy extraction. Это не GPU-время или момент
показа на экране. Редактор включает интеграцию; headless-приложения не обязаны её включать.

`Category` принадлежит фасаду движка: используйте `Marker::with_category`,
`Counter::with_category` и `Operation::begin_in`. Luau использует Scripts.
Категории Bevy определяются по именам и не гарантируют атрибуцию. Рейтинг исключает
scheduling internals и логические операции, но сохраняет их в исходной трассе.
ОС всё ещё может обрезать названия потоков. Выполнение SQL не доказывает визуальное
удобство макроса.

Rust-код использует фасад движка:

```rust
static REFRESH: kedra_profiling::Marker =
    kedra_profiling::Marker::new("editor.inspector.refresh");
let _scope = REFRESH.enter();
let objects = kedra_profiling::Counter::new("game.visible_objects", kedra_profiling::Unit::Count)?;
objects.sample(42_i64)?;
```

Переиспользуйте handles. Counter записывает абсолютное значение с неизменной единицей,
не автоматическое приращение или rate. Имена различают приложения/подсистемы внутри
процесса. Целые samples сохраняют signed 64-bit precision; дробные должны быть конечными.
CPU guard привязан к потоку и не должен переживать await/yield. Для логических операций
через ожидания используйте `Operation::begin` / `finish`; Drop без Finish означает отмену.

Каждый scoped Luau context также предоставляет:

```lua
ctx.profiler.scope("refresh", function()
    ctx.profiler.counter("visible_objects", 42, "count")
end)
ctx.profiler.operation("load", function()
    wait.updates(2)
end)
```

`scope` запрещает yield; `operation` включает ожидания и не означает CPU execution time.
Оба сохраняют результаты/ошибки callback. Имена квалифицированы программой: 1..=96
UTF-8 байтов без управляющих символов. На run допускается 64 определения CPU-меток,
64 counters, 64 имени операций и 32 одновременные операции. Единицы — `count`
(по умолчанию), `bytes`, `ms`, `percent`; единицу имени нельзя менять внутри run.
Luau сохраняет свою числовую точность, не произвольные 64-bit integers. Отмена/ошибка/
despawn закрывают оставшиеся операции. API не даёт Start/Stop, доступ к World,
файловой системе или сети и не пишет события без включённой записи.

Трассы содержат имена scopes и выбранные диагностические имена; не помещайте приватные значения
в имена. Self-profiling включает стоимость наблюдения/UI. Анализируйте остановленные
записи, не перестраивая дорогой live viewer во время измерения. GPU, allocation stacks,
физическая задержка и платформенная приёмка — отдельные возможности, не предоставляемые recorder.

## Системные инструменты

`perf` исследует CPU-стеки, `strace` — блокирующий I/O, `pidstat`/`iostat` — нагрузку,
Heaptrack — аллокации, RenderDoc — реальные проходы и ресурсы Vulkan. Сначала проверяйте запись
и чтение маленьким процессом. При необходимости повышайте права только профилировщику,
подключённому к собственному процессу, не редактору. Не ослабляйте глобальные ограничения
ядра и не добавляйте file capabilities. Данные сохраняйте в `target/`.

Проверяйте простой, ввод, меню, прокрутку, выделение, Inspector, resize и docking. Различайте
размер проекта, видимые/скрытые панели, Wayland/Xwayland, масштаб, монитор, драйвер и питание.
RPC round trip включает транспорт и скриптовое расписание; это не физическая задержка ввода.
Приёмка физического ввода и macOS/Windows остаётся отдельной.

Общие runtime/UI-оптимизации должны использовать одну библиотечную реализацию в редакторе
и независимой игре. Включайте применимые native features у обоих потребителей и проверяйте
обе интеграции до заявления общей приёмки; цифры редактора не доказывают ускорение игровых
сцен. Каноническая native-игра включает `kedra_ui/render` через обычную runtime-зависимость
и AuthoredUiPlugin. Headless-потребителям не нужен renderer; редакторские polling и
авторизация не становятся настройками игр.

Явно вызываемая программа `editor.profile.menus` выполняет 1..64 цикла открытия/закрытия
меню внутри приложения (`iterations`, по умолчанию 20), возвращая длительности и диагностику
до/после. Вызов идёт через `app.scenario` с обычными session/operation. Нужно открытое рабочее
пространство; программа не входит в функциональный набор по умолчанию. Внешний RPC-опрос
не входит в её времена, но ожидания помощников входят; физическая/визуальная приёмка не доказана.

Канонический [английский контракт](../../../en/manual/testing/performance.md) содержит полную
границу измерений; [план GUI][gui-plan]
отделяет будущую работу.
