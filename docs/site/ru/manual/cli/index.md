# Справочник командной строки

Выбирайте между тремя командными интерфейсами: исполняемым файлом редактора, локальным
сборщиком проекта и задачами разработки репозитория. Глобально установленный Kedra SDK не нужен.

## Карта задач и команд

Пользователям редактора и ассетов нужны строки редактора/ассетов. Авторы приложений и
сценариев используют строки локального сборщика проекта. Строки `cargo xtask` предназначены
участникам разработки Kedra, проверяющим этот репозиторий, а не для сборки проекта или Play.
Подготовку изменения к ревью начните с [Тестов и ревью](../../contributing/tests-and-review.md).

| Задача | Командный интерфейс | Справочник |
| --- | --- | --- |
| Открыть редактор или существующий авторский проект | `cargo run -p kedra -- …` | [Редактор](editor-and-assets.md) |
| Инициализировать sidecar-файлы источников | `cargo run -p kedra -- assets init SOURCE` | [Ассеты](editor-and-assets.md) |
| Обработать или проверить поставку | `cargo run -p kedra -- assets …` | [Ассеты](editor-and-assets.md) |
| Собрать отдельное Cargo-приложение | `cargo kedra build` | [Сборщик](build-tool.md) |
| Собрать и явно запустить приложение | `cargo kedra run` | [Сборщик](build-tool.md) |
| Создать нативные пакеты распространения | `cargo kedra package` | [Сборщик](build-tool.md) |
| Создать значки или явно установить сборщик лицензий | `cargo kedra icons` / `cargo kedra tools install-about` | [Сборщик](build-tool.md) |
| Выполнить Rust-сценарий тестирования проекта | `cargo kedra test` | [Сборщик](build-tool.md) |
| Проверить Rust-код, политики или features репозитория | `cargo xtask TASK` | [Репозиторий](repository-and-tests.md) |
| Выполнить нативные сценарии или сравнить готовые кадры | `cargo xtask test -- …` / `cargo xtask visual …` | [Тесты](repository-and-tests.md) |

Авторский проект с `kedra.toml` не становится Cargo-приложением автоматически.
Его открытие не собирает Rust-код и не реализует Play в редакторе. Документированной
команды `kedra init` для шаблона игры нет. `assets init` инициализирует идентичность
ассетов, а не игру или проект.

## Рабочий каталог и подготовка

Если не указано иное, примеры выполняются из корня репозитория Kedra. Относительные
входные и выходные пути разрешаются в рабочем каталоге команды; у метаданных
распространения отдельные правила относительно пакета. Пути с пробелами заключайте
в кавычки.

Файл `.cargo/config.toml` репозитория задаёт псевдонимы `cargo kedra` и
`cargo xtask`. Они компилируют локальные Rust-программы запуска в отдельные bootstrap-каталоги.
Другому проекту нужны свои программа запуска и псевдоним; установка Cargo сама по
себе не устанавливает эти подкоманды. См.
[сборку и распространение](../build-and-distribution/index.md).

Используйте закреплённый Rust toolchain и нативные зависимости из
[начала работы](../getting-started/index.md). Cargo может требовать сеть и выполняет
доверенные скрипты сборки и процедурные макросы, даже когда операция приложения
работает без окна. Упаковка может загружать и выполнять нативные вспомогательные
инструменты. Явная установка инструментов записывает их в пользовательский каталог.
Нативные тесты могут собирать приложения, открывать окна и внедрять ввод в сеанс рабочего стола.

Перед выполнением проверяйте проекты и инструменты. Ни проверка поставки, ни
ограничение выходных путей не изолируют выполнение кода. Не запускайте нативные
наборы на занятом рабочем столе. Ни одна команда здесь не доказывает приёмку всех платформ.

## Разделители — часть команды

```sh
cargo run -p kedra -- assets verify target/editor-assets
cargo kedra run --package kedra --output target/cli-run -- --help
cargo xtask test -- features --only hierarchy --output target/cli-hierarchy
```

В первом примере `--` завершает опции Cargo и начинает аргументы редактора.
Псевдоним `cargo kedra` уже содержит разделитель между Cargo и программой запуска; показанный
разделитель начинает аргументы свежесобранного приложения. Последний пример
передаёт всё после `--` Rust-цели сценариев репозитория. Это не фильтр для `cargo test`.

Где требуется, каждый раз выбирайте новый выходной путь; не удаляйте существующие
результаты ради повторного использования пути из примера.

## Справка и ошибки

Парсеры clap принимают следующие запросы справки:

```sh
cargo run -p kedra -- --help
cargo run -p kedra -- assets build --help
cargo kedra --help
cargo kedra build --help
cargo kedra test --help
cargo xtask --help
cargo xtask test -- --help
```

Cargo может скомпилировать программу запуска до появления справки. В частности, последняя
команда собирает исполняемый файл сценариев перед запросом справки; это не проверка
без сборки. Сам разбор help/version сборщика не требует метаданных приложения или
инструментов упаковки. `cargo xtask` принимает значение задачи, а не подкоманды:
используйте общую справку, не предполагая отдельной схемы `cargo xtask features --help`.

Неизвестные опции и неполные команды завершаются ошибкой, а не выбирают похожую
операцию. Ненулевой код означает неудачу; изучите текущую диагностику. Успешная
сборка, принятый запрос запуска, нативный поведенческий тест и сравнение снимков
доказывают разные вещи; ни одно не означает наличие Save или Play в редакторе.
