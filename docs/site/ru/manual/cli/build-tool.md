# Справочник локального сборщика проекта

`cargo kedra` — локальный псевдоним команды Cargo в проекте. В этом репозитории он запускает
`tools/kedra`, который без изменения передаёт аргументы ОС в `kedra_build::run_cli`.
Установленный редактор не требуется; это не глобальная команда игрового SDK.
Псевдоним изолирует программу запуска в `target/kedra-build-bootstrap`.

## Выбор приложения

У `build`, `run` и `package` общие опции:

| Опция | Значение по умолчанию и ограничение |
| --- | --- |
| `--manifest-path PATH` | `Cargo.toml` относительно CWD вызывающего процесса |
| `--package NAME` | Можно опустить, только если ровно один пакет workspace имеет метаданные packager |
| `--target TRIPLE` | Текущий поддерживаемый нативный host; должен совпадать с ним |

Допустимые целевые тройки: `x86_64-pc-windows-msvc`, `x86_64-unknown-linux-gnu`,
`aarch64-apple-darwin` и `x86_64-apple-darwin`. Выбор другой цели не устанавливает
SDK и не включает кросс-компиляцию. Взаимодействие с нативным приложением нужно
проверять отдельно на каждой платформе.

Выбранному пакету нужны ровно одна цель исполняемого файла, стандартные
`package.metadata.packager` и `package.metadata.kedra.distribution`. Cargo определяет
имя, версию и идентичность исполняемого файла. Пути распространения задаются относительно
пакета и должны оставаться внутри Cargo workspace. Одного `kedra.toml` недостаточно.
См. [конфигурацию приложения](../build-and-distribution/index.md).

## Build, run и package

Полный маршрут описан в разделах [Сборка и запуск](../build-and-distribution/build-and-run.md)
и [Упаковка и лицензии](../build-and-distribution/packaging-and-licenses.md).

```sh
cargo kedra build --release --package kedra --output target/cli-build
cargo kedra run --package kedra --output target/cli-run -- --help
cargo kedra package --package kedra --output target/cli-package
```

- `build [APP_OPTIONS] [--release] [--output PATH]` собирает и проверяет готовое
  к запуску приложение. Без `--release` используется сборка для разработки.
- `run` принимает те же опции плюс `[-- ARGUMENTS…]`; собирает и проверяет свежий
  результат, затем запрашивает запуск. Старый результат не выбирается.
- `package [APP_OPTIONS] --output PATH` всегда использует release. Отдельный флаг
  `--release` не принимается; выходной каталог нужно указать явно.

Без `--output` build/run резервируют свежий каталог внутри target-каталога Cargo.
Явный выход тоже должен быть новым и не может находиться внутри исходных ассетов.
При ошибках частичный результат сохраняется для диагностики, предыдущий не заменяется.
Build и package не запускают игру или CLI приложения, но выполняют доверенный код
сборки Cargo и инструменты упаковки. Только `run` запрашивает запуск приложения.

Проверенная сборка записывает `build-result.json`. Успешная нативная упаковка также
создаёт список файлов и контрольные суммы; файлы результатов не являются конфигурацией
исходников. Упаковка может загружать вспомогательные программы сторонних разработчиков.
Нативные инструменты и
настроенный сборщик лицензий уже должны быть доступны; отсутствие зависимостей
вызывает ошибку, а не неявную установку SDK/инструментов.

Аргументы после `run --` принадлежат приложению, включая `--help`. Поэтому пример
собирает и запускает приложение, а не показывает справку сборщика. Запуск использует
проверенную установленную структуру каталогов, а не исходный рабочий каталог, и не добавляет
`KEDRA_ASSETS`. В Windows/Linux stdin дочернего процесса закрыт, stdout/stderr
сохраняются в журналах выходного каталога; macOS использует Launch Services для настоящего bundle.
Успешный запрос запуска не доказывает готовность GUI, успешное завершение приложения
или физический ввод. При ошибке отправки запроса проверенная сборка сохраняется.

## Идентичность ассетов и значки

```sh
cargo kedra assets init assets
cargo kedra icons assets/editor/startup/project-mark-compact.svg --output target/cli-icons
```

`assets init SOURCE` — единственная подкоманда ассетов в парсере сборщика.
Для отдельной сборки/проверки поставки используйте [CLI редактора](editor-and-assets.md).
Инициализация добавляет недостающие sidecar, не заменяя существующие идентификаторы.

`icons SOURCE --output PATH` принимает самодостаточный SVG и новый выходной каталог
с уже существующим родительским каталогом.
Она создаёт файлы значков для нативной упаковки, включая PNG размеров 16–1024, ICO и ICNS,
без компиляции приложения. Значки не устанавливаются в проект. Инициализация пишет
исходники ассетов; генерация значков — только свой выходной каталог.

## Явная подготовка инструмента лицензий

Синтаксис: `tools install-about --output PATH [--archive PATH]`.

```sh
cargo kedra tools install-about --output /OUTSIDE_CARGO_WORKSPACE/about-tool
```

Эта явная операция получает проверенные по контрольной сумме исходники cargo-about 0.9.2,
разрешает зависимости в изолированном файле блокировки, проверяет их и устанавливает этот граф.
Требуются
Cargo и cargo-deny. Необязательный `--archive` задаёт локальный архив исходников;
контрольная сумма всё равно проверяется. Используйте новый выход вне любого Cargo workspace и
добавьте полученный каталог `bin` в PATH. Обычная сборка не устанавливает отсутствующий
сборщик. Это установка кода/инструмента, а не диагностика только для чтения.

У нативной упаковки есть дополнительные платформенные инструменты и ограничения
происхождения. Перед установкой зависимостей см.
[распространение](../build-and-distribution/index.md); эта команда не устанавливает
системные SDK и не гарантирует полноту лицензионных обязательств.

## Rust-цель сценария проекта

Подготовьте рабочий стол и решите, какие результаты записывать, по
[Нативным сценариям](../testing/native-scenarios.md).

Синтаксис: `test --manifest-path PATH --package NAME (--bin NAME | --example NAME)
[-- ARGUMENTS…]`.

```sh
cargo kedra test --manifest-path tools/test/Cargo.toml --package kedra-test \
  --bin test -- features --only hierarchy --output target/cli-hierarchy
```

Манифест и пакет обязательны; должна присутствовать ровно одна опция `--bin`
или `--example`. Команда собирает обычную цель с `--locked`, находит исполняемый файл
через сообщения Cargo и запускает его из каталога манифеста. Нужен существующий
файл блокировки. Границы аргументов и Unicode сохраняются; это не опции Cargo. Опции сборщика
`--release`, `--target` и `--output` здесь не применяются; выходная опция после `--`
принадлежит сценарию.

Цель отвечает за подготовку, результаты проверок и завершение нативного приложения;
ненулевой код цели означает неудачу команды. Запуск произвольной цели — выполнение доверенного кода,
а не песочница или универсальный контракт тестирования приложений. Пример сценария
репозитория может открывать окна и внедрять ввод. См.
[тесты репозитория](repository-and-tests.md).

## Разбор аргументов и ошибки

Разбор help/version не требует проекта или нативных инструментов упаковки, хотя
Псевдоним Cargo может сначала собрать программу запуска. Неизвестный/неполный синтаксис даёт
код 2; ошибки выполнения выводят `FAILED:` и код неудачи. Прогресс/диагностика
дочерних процессов видны. Здесь нет интерактивного выбора задачи или флага сборщика
`--non-interactive`; упаковка без участия пользователя настраивается в дочернем процессе.
