# Запуск редактора и команды ассетов

Приложение `kedra` в `apps/kedra` открывает нативный редактор, если подкоманда не
указана. Подкоманды `assets` работают без окна. Из корня репозитория
`cargo run -p kedra --` выбирает это приложение; токены после разделителя принадлежат
приложению, а не Cargo.

## Аргументы запуска

```sh
cargo run -p kedra -- --assets target/editor-assets
cargo run -p kedra -- /PATH/TO/PROJECT --assets target/editor-assets \
  --project-assets target/game-assets --state-directory target/cli-state
```

| Аргумент | Значение и значение по умолчанию |
| --- | --- |
| `[PROJECT]` | Необязательный корень существующего проекта; проверяется обычным открытием |
| `--assets PATH` | Проверенная поставка редактора; доступна и подкомандам ассетов |
| `--project-assets PATH` | Явная поставка пространства game для Scene View проекта; требует `PROJECT` |
| `--state-directory PATH` | Переопределяет хранилище локальных настроек; иначе обычное хранилище редактора |

Без `PROJECT` запуск использует обычный маршрут менеджера проектов/истории. Это
не команда создания пустой работающей игры. `--project-assets` задаёт ресурсы
предпросмотра, но не обрабатывает источники и не разрешает выполнение кода проекта.
Требования к авторскому проекту см. в [открытии проектов](../projects/index.md).

Поставка редактора выбирается так: явный `--assets`, затем `KEDRA_ASSETS`, затем
платформенный путь относительно исполняемого файла. По умолчанию поиск не идёт в
текущем рабочем каталоге или исходниках. У пакетов приложений macOS и установленных приложений Linux
есть платформенные пути ресурсов. Явно переданный относительный путь всё равно
разрешается от рабочего каталога вызывающего процесса.

## Общие опции запуска только для debug

Работа с учётными данными описана в [Подключении к приложению](../automation/connecting.md),
а интеграция стартовой сцены — в [жизненном цикле сцены](../scenes/lifecycle.md).

Сборки с debug assertions включают общие опции запуска приложения в CLI редактора:

| Опция | Контракт |
| --- | --- |
| `--scene PATH` | Переопределяет стартовую сцену host; по умолчанию переопределения нет |
| `--remote-port PORT` | Включает аутентифицированную loopback-диагностику; беззнаковый 16-битный порт, `0` выбирает свободный |
| `--remote-credentials PATH` | Новый закрытый файл учётных данных; требуется с `--remote-port` и наоборот |
| `--remote-artifacts PATH` | Каталог артефактов renderer; по умолчанию `target/test/captures` |

В release-схемах отсутствуют все четыре опции; Cargo features их не возвращают.
Переопределение сцены не загружает плагины и не разрешает выполнение скриптов.
Общий валидатор отклоняет пустые, превышающие 4096 байт и синтаксически неверные
пути сцен; жизненный цикл запуска дополнительно проверяет допуск каталога источников
и принадлежность сцены. Используйте полные логические пути с источником, например
`editor://fixtures/catalog.scene.ron`, а не пути файловой системы или UUID-константы
в нативном коде хоста. Сериализованные идентификаторы документов и ассетов остаются UUID.

Диагностика включается явно. Токен не передаётся в командной строке; учётные данные
и кадры должны храниться отдельно от исходников проекта и публичных отчётов.
Настройка удалённого доступа требует установленной службы приложения хоста и
отклоняет пустой каталог артефактов. Публикация учётных данных не доказывает готовность
рендерера или UI.

## Инициализация идентичности источников

```sh
cargo run -p kedra -- assets init /PATH/TO/PROJECT/assets
```

`assets init SOURCE` записывает недостающие нативные sidecar-файлы `.meta`, сохраняя
существующие идентификаторы/настройки. Это явная запись авторских данных, в отличие
от проверки. Сначала изучите дерево источников; перемещайте ассеты вместе с sidecar.
Инициализация не делает неподдерживаемые форматы отображаемыми и не создаёт сцену,
шаблон игры или поставку. Сборщик также предоставляет эту операцию как
`cargo kedra assets init SOURCE`.

## Создание новой поставки

Первый пример собирает ресурсы редактора; второй использует `game-desktop` для отдельного
приложения, ожидающего эту метку, а не для превью проекта в редакторе.

```sh
cargo run -p kedra -- assets build assets/editor target/editor-assets --namespace editor
cargo run -p kedra -- assets build /PATH/TO/PROJECT/assets target/game-assets \
  --profile game-desktop --namespace game
```

Синтаксис: `assets build SOURCE OUTPUT --namespace NAME [--profile PROFILE]`.
Оба позиционных пути и `--namespace` обязательны. Профиль по умолчанию — `editor-desktop`.
Текущему превью проекта в редакторе нужен именно этот профиль даже с namespace `game`;
используйте `game-desktop`, только если отдельное приложение ожидает эту метку.
Пространство имён и профиль — разные параметры: выбор пространства не меняет профиль по умолчанию.
Профиль — непустая строка не длиннее 64 байт, а не имя Cargo feature.
Пространство имён — 1–64 ASCII-буквы, цифры, `_` или `-`.

Сборка читает авторские источники/sidecar и публикует новую неизменяемую обработанную
поставку с манифестом, метаданными загрузчиков и хешами. Она не инициализирует
идентичность неявно. `OUTPUT` должен быть новым каталогом; существующие назначения
отклоняются, а не заменяются. Корни источников и поставки не должны пересекаться:
ни один не может содержать другой.
При ошибке публикации пригодной поставки не будет; изучите диагностику перед выбором
нового выходного каталога.

## Проверка без открытия окна

```sh
cargo run -p kedra -- assets verify target/editor-assets
cargo run -p kedra -- assets verify target/game-assets --profile game-desktop
```

Синтаксис: `assets verify [ROOT] [--profile PROFILE]`. Проверка читает элементы
манифеста, хеши и метаданные загрузчиков без записи. Её профиль по умолчанию также
`editor-desktop`. Без позиционного `ROOT` используются `--assets`, затем
`KEDRA_ASSETS`, затем путь относительно исполняемого файла. Явный `ROOT` имеет
приоритет, даже если одновременно указан `--assets`.

Парсер требует конкретной операции: команда `assets` без неё завершается ошибкой.
Флагу вроде `--profile` нужно значение. Ошибки обработки, проверки или запуска
дают диагностику и ненулевой код, а не молчаливый выбор другой поставки. Команды
ассетов без окна выводят прогресс и успех в stderr без запросов пользователю.
Cargo всё равно может компилировать код до их выполнения.

Проверка подтверждает целостность и совместимость формата, но не доверие к
издателю, актуальность относительно изменённых источников, готовность GPU или
правильные пиксели. Соответствующая поставка проекта — отдельное требование Scene View;
см. [обработку ассетов](../assets/index.md) и [предпросмотр редактора](../editor/index.md).
