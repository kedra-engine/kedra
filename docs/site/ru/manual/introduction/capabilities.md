# Текущие возможности и ограничения

Kedra поддерживает перечисленные ниже задачи. Проверки на платформах ещё не завершены,
в том числе проверки нативного ввода и работы с окнами. API и форматы исходников нестабильны.

## Что доступно сейчас

| Область | Текущая реализация | Важное ограничение |
| --- | --- | --- |
| Проекты | Создание/открытие проекта, проверка манифеста и расположения корня ассетов. | Новый проект — не шаблон запускаемой игры. |
| Рабочее пространство | Закрепление панелей и отдельные нативные окна. | Приёмка нативного ввода, IME и мониторов разной плотности не завершена. |
| Asset Browser | Просмотр/поиск, импорт файлов, создание документов/папок, переименование и удаление допустимых элементов. | Файловые операции немедленные, вне истории документов; поставки автоматически не пересобираются. |
| Редактирование сцен/префабов | Создание документов и узлов, переименование, удаление, смена родителя, поддерживаемые поля и компоненты Inspector. | Неподдерживаемые поля только для чтения; произвольные компоненты проекта не загружаются. |
| Scene View | Отрисовка, навигация, выбор и Move/Rotate/Scale допустимых узлов с привязкой. | Для контента с ресурсами нужна соответствующая поставка; для документов без ресурсов — нет. Это не Play. |
| Runtime сцен | Композиция сцен/префабов, переопределения, компиляция зарегистрированных компонентов, создание экземпляров и явная стартовая сцена. | Нужна настройка хоста; загрузка сцены не разрешает запуск скриптов. |
| API авторинга исходников | Проверяемые транзакции, Undo/Redo и защищённый Save, используемые инструментами редактора. | Save явный; нет восстановления несохранённых правок после аварии и полного UI Apply/Revert префабов. |
| Ассеты | Инициализация недостающих метаданных, обработка поддерживаемых профилей и проверка поставок ресурсов для общих загрузчиков. | Не универсальный импортёр всех форматов или возможностей ассетов Bevy. |
| Отдельные приложения | Сборка, проверка, упаковка и явный запуск настроенных настольных Rust-приложений общими инструментами. | Не полный игровой SDK и не процесс сборки/Play в редакторе. |
| Luau | Разрешённые хостом поведения, конечные последовательности и модули из допущенных исходников с ограниченными возможностями доступа. | Нет автоматического поиска/загрузки кода проекта или разрешения запуска при открытии проекта. |
| Диагностика и тестирование | Явно включаемые только в debug удалённое наблюдение, внедрение ввода, захват кадров рендерера и общие средства нативной QA. | Не удалённое управление release-сборкой, не произвольное удалённое выполнение исходников и не доказательство качества физического ввода. |

Чтобы попробовать редактор, перейдите к [Началу работы](../getting-started/index.md).
Для углублённого знакомства с контентом используйте разделы [Проекты](../projects/index.md),
[Ассеты](../assets/index.md) и [Сцены и префабы](../scenes/index.md).
Они описывают поддерживаемые процессы авторинга и их ограничения.

## Работающая основа и запланированный процесс

Поддерживаемые правки сцен/префабов, поля Inspector, Undo/Redo и Save исходников связаны.
Оставшаяся работа и ограничения нативной приёмки описаны в
[руководстве редактора](../editor/index.md).

**Play внутри приложения** следует за авторингом: запустить сцену, наблюдать выполнение,
остановить его и вернуться к редактированию с явными правилами для несохранённых ревизий.
Это не реализовано. Ни превью Scene View, ни команда `run` отдельного CLI не предоставляют
такой процесс.

Инспекторы и окна редактора, определяемые проектом, — более поздний запланированный этап.
Сейчас нет публичного рабочего процесса расширения редактора из проекта. Наличие Luau
не означает автоматическую загрузку кода проекта или выбранную границу выполнения
и изоляции.

Долгосрочные цели runtime включают Linux, Windows и macOS на настольных системах, веб,
а также Android/iOS на мобильных устройствах. Поддержка веба и мобильных платформ —
будущая работа; редактор предназначен только для настольных систем. Эти цели не означают
сертификацию набора платформ сегодня.

## Выберите полезный эксперимент

**Изучить существующий контент.** Откройте подготовленный проект, изучите иерархию
и значения поддерживаемого документа, сравните превью с исходниками. Если отрисовка
не работает, проверяйте готовность поставки отдельно от корректности документа.
Для редактирования используйте личную копию и явно сохраняйте принятые изменения.

**Оценить интеграцию на Rust.** В явно настроенном Bevy-хосте изучите загрузку сцен,
API изменения исходников или скрипты с ограниченными возможностями доступа. Это задачи
интеграции, а не готовый игровой шаблон. Политики, ресурсы и разрешение выполнения
по-прежнему выбирает хост.

**Подготовить приложение.** Общие средства сборки могут собрать настроенное отдельное
приложение без установленного редактора. Нативные зависимости, доверие к пакету
и лицензионные обязательства сохраняются; успешная передача запроса запуска не означает
готовность GUI.

## Границы проверки

Запустите модульные и интеграционные тесты, а также нативные сценарии для той ревизии
и машины, которые вы оцениваете. Нативное поведение проверяется с реальными кадрами
и вводом; проверки без окна и сборка документации эти взаимодействия не проверяют.
В нативном взаимодействии и захвате кадров остаются нерешённые периодические сбои.

Оценивая Kedra, разделяйте три вопроса: существует ли механизм, соответствует ли ваш
контент поддерживаемому профилю и проверено ли нужное взаимодействие на целевой машине?
[Карта продукта](product-map.md) помогает определить, какая часть отвечает за каждый вопрос.
