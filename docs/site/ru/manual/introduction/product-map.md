# Карта продукта: редактор, runtime и инструменты

Редактор, runtime и инструменты Kedra работают с общим контентом, но решают разные задачи.

## Редактор: рабочая среда для изучения контента

Нативный редактор управляет открытием проектов и рабочим пространством с закрепляемыми
панелями и отдельными окнами. Asset Browser позволяет перемещаться по папкам исходников
и открывать поддерживаемый контент. Hierarchy показывает составные узлы активного
документа, Inspector — значения выбранного исходного узла, а Scene View отображает
поддерживаемый контент, если необходимые ресурсы готовы.

Панели связаны через сеанс исходного документа. Выбор в браузере не равен открытию
документа, а выбранный исходный узел — не постоянная игровая сущность. Сейчас редактор
показывает документы только для чтения; использование авторских исходников для его
собственного UI не означает, что пользователь может визуально менять этот UI или
подключать окна редактора из проекта.

## Runtime: сервисы внутри приложения

Здесь **runtime** — общий код, используемый работающим приложением: загрузка ассетов,
композиция сцен и создание экземпляров, поддерживаемая интеграция отрисовки, UI,
а также явно подключённые скрипты и сервисы приложений.

Rust-хост выбирает подключаемые сервисы. Он может выбрать явную стартовую сцену
из загруженного каталога источников и создать её как обычные сущности Bevy. Завершение
запуска сцены означает создание экземпляра, а не готовность GPU-кадра или разрешение
игрового выполнения. Runtime не требует установленного редактора или инструментов
записи исходников.

Это полезная инфраструктура приложений, но ещё не полный игровой SDK с готовой
интеграцией от проекта до Play.

## Авторинг: работа с редактируемым замыслом

**Авторинг** — создание и изменение исходного контента, а не работающей симуляции.
Rust API авторинга Kedra управляют рабочими документами, проверками, ревизиями,
историей и запросами сохранения. Хост интегрирует саму операцию записи и сообщает
её результат через протокол.

Например, изменение переопределения экземпляра в рабочем документе — операция
над исходником, а перемещение живой сущности — нет. Эти API описаны в разделе
[Изменение исходников и сохранение](../scenes/source-editing.md). Сейчас они недоступны
в редакторе как визуальное редактирование или сохранение документов.

## Импорт и инструменты: подготовка контента и приложений

Обработка ассетов превращает допущенные исходники в проверенную неизменяемую **поставку
ресурсов**: ресурсы и метаданные для загрузки потребителем. Поставка ресурсов — производный
результат, а не место для следующей правки исходника. Редактор не пересобирает её скрыто
при открытии документа.

Отдельные инструменты командной строки используют Cargo и нативные средства упаковки
для сборки, проверки и упаковки настроенных Rust-приложений. Приложение запускает только
явная команда `run`; сборка — не Play в редакторе. В отличие от открытия проекта
в редакторе, сборка Cargo-проекта выполняет его build-скрипты и требует доверия к проекту.

## Путь одного элемента контента

```text
Авторские исходники ── обработка + проверка ──> поставка ресурсов
                                                    │
                                    runtime-загрузчики + каталог источников
                                                    │
                                    составная сцена → живой экземпляр

Авторские исходники ── проверенный сеанс редактора ──> проекция только для чтения
                                                    ↑
                                    соответствующая поставка для отрисовки
```

Каталог источников определяет исходники сцен и префабов, допущенные для runtime-композиции;
это не список папок Asset Browser. Загруженная сцена разрешает композицию и значения
зарегистрированных компонентов перед созданием экземпляра. Редактор отдельно хранит
принятый исходный контент для изучения и строит его представление.

Поэтому документ может быть достаточно корректным для изучения, но не отображаться
в превью. Отсутствующая или несовпадающая поставка ресурсов — отдельная проблема,
не равнозначная некорректному исходнику. Диагностика описана в разделе
[Обработка ассетов](../assets/pipeline.md).
