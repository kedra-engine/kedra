# UI из исходных документов

Редактор использует внешние исходные документы и CSS для стартовых форм, повторяемых строк,
рамок, заголовков и оформления dock. Он использует общий механизм UI, а не отдельную ручную
компоновку.

UI использует те же документы сцен и префабов, что и остальное содержимое Kedra.
Исходники описывают дерево нативной компоновки, текста, изображений, стилей и объявленного
поведения виджетов. Приложение удерживает живые узлы дерева между обновлениями и привязывает
к ним действия и текущие значения, а не пересоздаёт дерево каждый кадр.

**Гидратация** — превращение исходных данных в нативное представление: например,
`UiLayout` становится `Node` Bevy, а `UiButton` в обслуживающем виде — нативным виджетом.
Компиляция не помещает эти компоненты представления с hooks в мир исходников.
Гидратация не означает выполнение скрипта, изменение исходника или готовый кадр.

Обслуживающий (serving) вид связывает живые элементы управления с приложением;
пассивный (passive) вид служит изолированному представлению без этого поведения.

## Что может описать документ

Все общие ключи ниже используют схему версии 1:

| Ключ исходника | Роль после гидратации |
| --- | --- |
| `ui.layout` | Данные нативного `Node` Bevy в инертной для исходника оболочке |
| `ui.caption` | Начальный текст, выравнивание и перенос; типографика задаётся CSS |
| `ui.stylesheet`, `ui.classes` | Зависимость stylesheet Flair и явные классы |
| `ui.image` | Упорядоченные варианты растровой плотности и семантический tint |
| `ui.button` | Нативная кнопка для указателя и клавиатуры в обслуживающем виде |
| `ui.editable` | Однострочный нативный ввод; требует caption |
| `ui.modal` | Нативное поведение диалога или барьера в обслуживающем виде |
| `ui.spin` | Вращение UI в реальном времени с паузой и reduced motion |
| `ui.id`, `ui.screen` | Идентификаторы наблюдения обслуживающего UI, не постоянные адреса узлов |
| `ui.background`, `ui.border`, `ui.shadow`, `ui.outline` | Нативные визуальные данные |
| `ui.z`, `ui.global_z` | Данные нативного порядка наложения |
| `ui.pickable` | Политика выбора указателем Bevy |

Это набор допущенных схем, а не отдельный язык разметки. Неизвестные поля нативного layout
и неконечные числовые значения отклоняются при проверке. `UiLayout` сохраняет семантику
значений по умолчанию нативного Bevy `Node`. Текст, кнопки и изображения
требуют layout на том же узле. Классы исходника — уникальные непустые имена без пробельных
символов: до 64 на компонент и до 256 байт в каждом имени.

### Пример: корень HUD со стилями

Это фрагмент карты `components` корня из
`tests/fixtures/test_project/assets/Hud.prefab.ron`, а не полный префаб:

```ron
"ui.classes": (
    version: 1,
    value: (names:["hud"]),
),
"ui.layout": (
    version: 1,
    value: (node:()),
),
"ui.stylesheet": (
    version: 1,
    value: (asset:Path("game://preview.css")),
),
```

Тот же тестовый префаб содержит кнопку с надписью `Launch — inert in preview` и поле
с `autofocus:true`. В Scene View они не становятся интерактивными. Рабочее приложение
должно явно выбрать гидратацию обслуживающего UI и привязать действие, прежде чем кнопка получит
прикладной смысл.

## Монтаж и поддержание жизни обслуживающего вида

Установите `AuthoredUiPlugin` после нужных плагинов Bevy для ассетов, UI, текста,
input-focus, виджетов, picking и tab-navigation. Он включает живые стили, но не создаёт
окно или рендерер и не предоставляет шрифт по умолчанию или тему редактора. Выбирайте
исходники через [загруженный каталог и ревизию](../scenes/lifecycle.md)
по полным логическим путям, а не по жёстко заданным UUID документов.

`UiView::mount` принимает скомпилированный исходник, необязательного родителя, локальные
внешние привязки, область идентификаторов наблюдения и конечную положительную плотность.
Корню обслуживающего вида нужен `ui.layout`. Stylesheets и выбранные варианты изображений
должны быть уже материализованы. Текст требует явной области stylesheet; монтаж caption
без неё завершается ошибкой до выделения живых сущностей.

Если монтирование завершается ошибкой, обработайте её: ручная компоновка или вариант меньшей
плотности не подставляются. Сериализованные значения не выполняют код или произвольные
удалённые операции. В прикладном коде связывайте типизированные действия и данные предметной
области с нативными компонентами, сохраняемыми между обновлениями.

Возвращённый корень владеет иерархией и точной неизменяемой компиляцией. Удаление его
иерархии освобождает вид. `UiView::element` находит обязательные локальные семантические
ключи; `UiView::text` принимает текстовый узел или ровно одну прямую текстовую подпись,
а не угадывает дочерний узел. Отсутствующие и неоднозначные привязки — ошибки.
Прикладной код обновляет нативные значения и классы, сохраняя состояние редактирования
текста и фокус, а не переписывая исходный документ.

`UiView::mount_scene` — адаптер стартовой сцены для обслуживающего UI. Он сохраняет исходные
`ui.id` и `ui.screen`; `mount` может добавлять к ID элементов область `scope/key`,
при этом локальный поиск остаётся по `key`. ID элементов должны быть уникальны в пределах
нативного окна; повтор ключей в одном экземпляре отклоняется при монтаже.
Постоянные адреса узлов исходника и временные handles сущностей Bevy — разные идентичности.

## Обслуживающие элементы и пассивные превью

`UiView::mount_passive` использует те же скомпилированные данные для изолированного
представления, включая UI-поддеревья смешанных графов. Он удаляет `ElementId` и `ScreenId`,
игнорирует picking, показывает редактируемые captions обычным текстом и не устанавливает
кнопки, autofocus, текстовый ввод или модальное поведение. Скрипты и специфичные для
приложения схемы не получают полномочий через этот путь. Визуальные стили и поддерживаемое
представление, включая UI spin, отделены от разрешения на взаимодействие.

Тексту в каждом отделённом UI-дереве нужна область действия таблицы стилей внутри этого дерева.
Таблица на внешнем родителе или за предком без layout не задаёт стили пассивного текста.
Приложение назначает явные камеры и освобождает отделённые деревья вместе с исходным
экземпляром; `PassiveView::retire` учитывает это владение.

`UiReady` означает завершённую гидратацию нативного UI, но не готовность GPU или кадра.
Ошибки ресурсов пассивных изображений записываются локально в `PassiveUi`, а не
в глобальный `UiFailure` рабочего приложения. Так неисправное превью проекта не выдаёт
себя за живой UI редактора и не отключает его. Ввод и область окна описаны далее:
[стили и компоновка](styling-and-layout.md#нативные-элементы-и-область-окна).
