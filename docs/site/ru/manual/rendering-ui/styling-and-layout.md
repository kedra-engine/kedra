# Стили, компоновка и нативные окна

Kedra использует закреплённый Bevy Flair 0.9.0 для разбора CSS, селекторов, переменных,
импортов, каскада и анимаций стилей. Bevy 0.20 отвечает за нативную компоновку UI, текст,
виджеты и рендеринг. Это нативный retained UI, а не webview или второй layout engine Kedra.

Чтобы подключить стили и нативные окна к приложению, используйте интерфейсы из
[руководства Rust API](../../api/index.md) и [контракта общего UI (English)][ui-contract].
Для работы в редакторе см. [управление панелями](../editor/index.md).

## Связь структуры и стилей

Префабы исходников задают структуру и поведение; `ui.stylesheet` ссылается на CSS-ассет
из поставки ресурсов, а `ui.classes` задаёт классы для правил. CSS определяет компоновку,
типографику, цвета и визуальные состояния взаимодействия. Начальные поля Node
в `ui.layout` могут задавать значения, которыми не владеет CSS. Игры выбирают свои sheets,
шрифты и зарегистрированные свойства; общий UI-плагин не наследует тему редактора неявно.

Этот фрагмент CSS взят из `assets/editor/styles/controls.css`:

```css
.button {
    height:var(--control-height); min-height:var(--control-height); min-width:80px; padding:0 6px;
    align-items:center; justify-content:center; flex-shrink:0;
    border-radius:var(--control-radius); background-color:transparent;
}
.button:hover { background-color:var(--hover); }
.button:active { background-color:var(--pressed); }
.button:disabled { background-color:var(--panel); }
```

Это не полная таблица стилей: пользовательские свойства определены в выбранной области темы.
`assets/editor/prefabs/button.prefab.ron` задаёт нативную кнопку, подпись и декоративный
узел рамки фокуса. У рамки явно указано `should_block_lower:false,is_hoverable:false`;
одна лишь прозрачная отрисовка не заставляет нативное наложение пропускать ввод указателя.

Flair поддерживает подмножество CSS, а не полную совместимость с браузером. Ориентируйтесь
на таблицы стилей проекта и реестр свойств закреплённой версии. Не придумывайте отдельный
язык шейдеров и не рассчитывайте на поддержку всех сокращённых CSS-свойств браузера.
Справочник библиотеки:
[Bevy Flair 0.9.0](https://docs.rs/bevy_flair/0.9.0/bevy_flair/).

## Подготовка стилей без создания окна

`StyleAssetsPlugin`, установленный после `AssetPlugin`, регистрирует ассеты stylesheet,
нативные свойства и разбор для headless-потребителей. `StylesPlugin` добавляет живой
каскад и анимации; `AuthoredUiPlugin` включает его. Завершите регистрацию нативных
свойств до запроса stylesheets. Пользовательские свойства принадлежат определившему их
приложению.

Установленный CSS требует `CssStyleLoaderErrorMode::ReturnError` в нативных metadata
загрузчика. Upstream по умолчанию восстанавливается с предупреждениями, что не соответствует
строгому контракту публикации Kedra. Процесс поставки ограничивает CSS-исходники 64 KiB
и отклоняет ошибки разбора, импортов и зависимостей. Допустимый ассет stylesheet ещё не
доказывает правильное вычисление всех динамических переменных во всех состояниях виджета.
См. [поддерживаемые форматы](../assets/supported-formats.md)
и [диагностику поставки](../assets/troubleshooting.md).

Для просмотра поддерживаемого представления в редакторе начните с
[подготовки ресурсов Scene View](../editor/scene-view.md).

Для вложенных областей действия таблиц стилей задавайте явные классы темы и собственные
переменные. Не считайте `:root` селектором произвольного вложенного поддерева. Не меняйте
одно свойство одновременно из разных механизмов: не обновляйте каждый кадр поля Node,
которыми управляет CSS, не задавайте CSS-анимацию вращения узлу с `UiSpin` и не меняйте
изображение отдельно от механизма выбора плотности из исходника. Функции docking задают
динамическую геометрию через объявленные inline-свойства Flair, а не через отдельный каскад.

## Плотность, движение и значения между обновлениями

`ui.image` содержит от одного до восьми положительных, строго возрастающих вариантов
плотности. При монтаже выбирается первый вариант, покрывающий запрошенную плотность;
последующие нативные измерения target могут изменить выбор. Отсутствие покрытия
или исчезновение изображения вызывает ошибку с сохранением прежнего изображения,
а не подстановку масштабированной заглушки. См.
[обработку вариантов изображений](../assets/supported-formats.md).

`UiSpin` использует реальное время независимо от игровых часов. Пауза spin или
`UiMotion.reduced` удерживает вращение в нуле. Это не общий редактор анимаций
и не автоматическое управление reduced motion для всех CSS-анимаций.

Общие `fields::{PropertyRow, SectionView, ValueView}` создают представления с живыми
виджетами, удерживаемыми между обновлениями, из шаблонов исходников приложения.
В строках предусмотрены слоты подписи, редактора и диагностики; секции могут
сворачиваться без замены виджетов значений.
`FieldAccess::ReadOnly` запрещает изменение, сохраняя нативное выделение и копирование.
Эти элементы не владеют reflection, проверкой документов или сохранением и не превращают
Inspector только для чтения в редактор.

## Нативные элементы и область окна

Кнопки обслуживающего UI используют активацию Bevy; текстовые поля — нативные
`EditableText`/`TextInput`, фокус и tab-navigation. `NativeInputPlugin` ограничивает
всплытие keyboard/wheel и обход Tab окном элемента и активной модальной границей.
Authored UI устанавливает адаптер автоматически, только если плагины input-dispatch
и text-input Bevy уже присутствуют; другие нативные приложения устанавливают его явно
после этих плагинов.

Техническим UI-корням нужны `UiTargetCamera` и `TabGroup` с живой камерой, направленной
в окно. Скрытые и отключённые элементы исключаются из навигации. Включение IME, события
и положение курсора направляются владельцу поля в фокусе. Headless-тесты событий не
сертифицируют физическую клавиатуру, IME ОС, мониторы со смешанным DPI или особенности
ввода платформ.

Заголовки окон используют `kedra_ui::window_chrome`: слоты исходника заимствуют содержимое,
а явные области `Client`, `Drag` и `NativeControls` определяют владение вводом.
Отключённый клиентский элемент по-прежнему блокирует область перетаскивания.
`Header::unbind` возвращает заимствованное содержимое к парковочным родителям до удаления
заголовка; прямое удаление обходит этот жизненный цикл. Недопустимые, устаревшие,
циклические привязки и привязки другого окна отклоняются без перемещения существующего
содержимого.

Адаптер редактора `kedra_desktop` управляет наборами из нативного окна, камеры и корневого
узла и направляет команды оформления конкретному окну. При этом `kedra_ui` не создаёт окна.
Нативный запрос Close сам по себе не означает, что прикладной код разрешил закрытие,
и не выполняет Save.
Владение docking и нативной поверхностью не даёт полномочий над исходниками проекта.
Пользовательские элементы описаны в [рабочем пространстве редактора](../editor/index.md).

Производительность CSS, точность нативного текста, первые видимые кадры и поведение платформ
требуют отдельной нативной проверки; изучения исходников для этого недостаточно.
Автоматическая перезагрузка файлов и транзакционная замена таблиц стилей во время работы
не поддерживаются.
